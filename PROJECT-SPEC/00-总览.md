## 2. 项目全貌（标准结构）

FIST 下发的项目级任务，其 `project_dir` 建议遵循以下标准结构（可裁剪，但核心目录职责不变）：

```
<project_dir>/
├── PROJECT-SPEC/        ← 项目规范（FIST 下发时注入，或引用本目录）
├── src/                 ← 源码（语言无关，按项目实际技术栈）
├── tests/               ← 测试（测试对 + 回归）
├── docs/                ← 设计文档（架构/规范，只增不删不改）
├── reports/             ← 进度报告（按日期子文件夹，见 04）
├── corpus/              ← Ω-spec JSON 测试对（见 05）
├── README.md            ← 项目说明
└── CHANGELOG.md         ← 变更记录
```

## 3. 开发总流程（每个项目级任务）

```
1. 读 PROJECT-SPEC/00-总览 + 01-入门（第一次或复习）
2. 定位相关文档：docs/（设计）、corpus/（Ω-spec）
3. 制定方案 → 动手（编辑/生成代码）
4. 测试：跑测试对 + Ω-gate（涉及语义时）
5. 验证：fist.py omega-verify <project_dir> 必须通过
6. 汇报：reports/YYYY-MM-DD/ 下写进度报告（只增不删不改）
7. 提交：git commit（如项目为 git 仓库）
```

## 4. 铁律（不可违反）

1. **验证不可跳过**：项目级任务验收前必须过 Omega 验证；无法验证时必须明说；
2. **测试不改弱**：禁止删除/注释/跳过测试来"通过"——那是在藏 bug；
3. **进度报告只增不删不改**：历史报告是唯一真值，禁止事后修改；
4. **不自研可复用内核**：能调库/复用现成方案就不重复造轮子（拿来主义借力）；
5. **版本锁定**：依赖用精确版本，锁文件入库；
6. **人类主权**：项目级任务的完成/归档仅人类或人类管家可标记（FIST 第 12.1 节）。
