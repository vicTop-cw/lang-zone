# PROJECT-SPEC/03 — 测试规范化

> 本文件规定 FIST 下发的项目级任务的测试结构、测试对、回归与覆盖率。**每次写测试/验证时必读。**

---

## 1. 测试结构

```
tests/
├── test_<模块>.py        ← 按模块组织
├── fixtures/             ← 测试数据
└── regression/           ← 回归测试（历史 bug 修复后固化）
```

## 2. 测试对（Test Pair）

- 每个核心操作/函数必须有 **input → expected** 测试对；
- 必须包含**错误路径**（非法输入 → 期望错误）；
- 测试对同时沉淀为 Ω-spec JSON（`corpus/`，见 05），供 Omega 验证系统跑批。

## 3. 回归

- 修复 bug 后，必须把该 bug 的复现用例固化为回归测试；
- 回归测试禁止删除/注释/跳过（铁律 2）。

## 4. 覆盖率

- 核心逻辑覆盖率优先保证；无法覆盖的分支必须注释说明原因；
- 覆盖率不足时，在进度报告中明说"未覆盖项"。

## 5. 四大原则（参考 tnr README/07）

1. **必须过 Omega 验证**：涉及语义的改动必须过测试对 / Ω-gate；
2. **怀疑主义**：出错时按"输入 → 处理 → 输出"逐层排查，不猜；
3. **否定主义**：通过 ≠ 全对，红灯要能定位到具体用例；
4. **拿来主义**：处处是资源，先复用再自建。
