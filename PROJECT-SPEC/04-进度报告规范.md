# PROJECT-SPEC/04 — 进度报告规范

> 本文件规定 FIST 下发的项目级任务的进度报告规范。**每轮工作后必读。**

---

## 1. 只增不删不改原则

- 历史进度报告是**唯一真值**，禁止事后修改、删除、覆盖；
- 新进展写新报告，不回头改旧报告；
- 发现旧报告有误 → 在新报告中注明更正，不改旧报告。

## 2. 按日期子文件夹

```
reports/
└── YYYY-MM-DD/           ← 按日期归档
    ├── 01-进度报告.md
    └── 02-进度报告.md
```

## 3. 必填字段

每份进度报告必须包含：

| 字段 | 说明 |
|------|------|
| 做了什么 | 本轮实际完成的工作 |
| 做成什么 | 可验证的产出（文件/功能/数据） |
| 修复什么 | 修复的 bug / 问题 |
| 改了什么 | 变更点（含 CHANGELOG 对应条目） |
| 验证情况 | Omega 验证结果 / 测试通过情况 |
| 遗留风险 | 未完成项、已知风险、后续建议 |

## 4. 与 FIST 汇报的关系

- 项目级任务的进度报告落盘在 `project_dir/reports/`；
- FIST 自身的汇报落盘在 `reports/`（FIST-SKILL 第 5 章）；
- 两者独立，不互相覆盖。
