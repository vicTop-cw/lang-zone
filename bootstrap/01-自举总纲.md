# 自举总纲

## 一、什么是自举

自举是指项目自身的工具链/基础设施能够用于构建和迭代自身，不再依赖外部预构建的版本。具体表现为：用本项目产出的编译器编译本项目源码，用本项目产出的构建工具构建本项目。

## 二、自举的动机

- **验证正确性**：自举是编译器/工具链正确性的终极检验——只有行为正确的工具才能成功构建自身。
- **消除外部依赖**：减少对预构建二进制或第三方工具链的依赖，实现真正的自主可控。
- **加速迭代**：用自身工具开发自身，新特性的开发体验与用户使用体验一致，形成正向飞轮。
- **质量标杆**：自举成功意味着项目已达到生产可用级别。

## 三、自举的分级标准

| 级别 | 名称 | 描述 |
|------|------|------|
| L0 | 外部依赖构建 | 完全依赖外部工具链编译本项目 |
| L1 | 部分自举 | 项目产出的部分组件可替换外部工具链中的对应组件 |
| L2 | 完整自举 | 项目产出的完整工具链可独立编译本项目全部源码 |
| L3 | 自举优化 | L2 基础上，自举产出的二进制性能不低于外部工具链构建的版本 |
| L4 | 自举迭代 | 连续 N 代自举（用自举产物再次自举），产物逐代收敛，二进制一致 |

> **本项目语境（Lang-Zone）**：因后端即 Rust 且编译器由 Rust 编写，严格的 L2/L4（"完整工具链可独立编译本项目全部源码"）在本项目中需区分两个对象——
> 1. **`.lz` 生态源码**（标准库、示例、测试样例）：可由 `lzc` 编译，近期即可冲击 L2；
> 2. **编译器 `src/*.rs` 自身**：当前为 Rust，需先自托管（路线 B）方能纳入 L2/L4。
> 详见 `04-当前项目自举具体方案.md`。

## 四、自举的核心原则

1. **渐进式推进**：不追求一步到位，按 L0 → L1 → L2 → L3 → L4 逐级攀登。
2. **可验证性**：每一级自举都有明确、可量化、可自动化的验证标准。
3. **可回退**：任何阶段出现问题都能回退到上一级的稳定状态。
4. **CI 集成**：自举流程必须集成到 CI 流水线中，每次提交自动验证自举状态。
