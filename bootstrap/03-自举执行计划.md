# 自举执行计划

## 一、阶段划分

### 阶段 0：准备工作（预计 2-4 周）

- [ ] 完成前置条件清单中全部项目的核查与补齐
- [ ] 搭建自举专用 CI 流水线（与日常开发流水线并行）
- [ ] 编写自举验证脚本：自动对比外部构建产物与自举构建产物的行为差异
- [ ] 确定第一个自举目标（通常是编译器核心模块）
- [ ] 冻结外部工具链版本，作为基准参照

> **本项目语境（Lang-Zone）**：第 4 项目标在本项目应调整为"确定第一个自举的 `.lz` 生态模块"（如 `test_hello.lz`），
> 因编译器核心模块 `src/*.rs` 为 Rust 编写、短期不可被 `lzc` 自举；冻结的基准即当前 Rust toolchain 版本。

### 阶段 1：L1 部分自举（预计 4-8 周）

- [ ] 选取一个独立模块（如词法分析器），用项目自身编译器编译，替换外部构建的对应模块
- [ ] 运行全量测试，确保替换后行为一致
- [ ] 逐模块推进，每次替换一个模块并验证
- [ ] 达到 L1 标准：至少一个核心模块由自身编译器构建

> **本项目语境**：将"词法分析器"替换为"一个独立的 `.lz` 模块（如 `test_hello.lz` 或 `ready/` 中的工具脚本）"，
> 用 `lzc` 编译并经 rustc 构建，与现有手写 `.rs`/`.exe` 做行为比对，达成"至少一个 `.lz` 模块由自身编译器构建"。

### 阶段 2：L2 完整自举（预计 4-8 周）

- [ ] 用项目自身编译器完整编译整个项目
- [ ] 运行全量测试套件，确保全部通过
- [ ] 用自举产出的二进制再次编译自身（第二代自举），结果一致
- [ ] 达到 L2 标准：完整工具链可独立构建项目

> **本项目语境**：用 `lzc` 完整编译**全部 `.lz` 生态源码**，生成 .rs 全部经 rustc 干净构建，整套 `.lz` 不再需要手写 Rust 配套。
> "第二代自举"在路线 A 下指"用新生成的 rustc 构建产物再次 lzc 编译同一 `.lz` 集，产物一致"；
> 严格的"自举产物再次编译自身"（编译器自举）需先走路线 B（编译器自托管），见 `04-当前项目自举具体方案.md`。

### 阶段 3：L3 自举优化（持续进行）

- [ ] 分析自举构建与外部构建的性能差距
- [ ] 针对性优化编译性能
- [ ] 达到 L3 标准：自举构建性能 ≥ 外部构建性能

> **本项目语境**：优化 `lzc` 的词法/语法/codegen 吞吐，使全量 `.lz` 转译耗时可控（建议目标：不低于外部直接开发 Rust 的 50%）。

### 阶段 4：L4 自举迭代（持续进行）

- [ ] 建立 N 代自举自动化流水线
- [ ] 逐代比对二进制哈希，确保确定性构建
- [ ] 达到 L4 标准：连续 3 代自举产物二进制完全一致

> **本项目语境**：路线 A 下以"生态源码连续 3 代被 `lzc` 稳定编译、产出一致"近似 L4；
> 严格 L4（编译器二进制连续 3 代一致）依赖路线 B 达成编译器自托管。

## 二、自举启动时机

满足以下全部条件时，正式启动自举：

1. 前置条件清单全部达标
2. 核心 API 接口已稳定（近 4 周无 Breaking Change）
3. 团队对当前架构达成共识，无重大重构计划
4. 有至少 2 名开发者专职投入自举工作

> **本项目语境**：当前核心语法规范（`hermes/00`）与实现仍存在已知分歧（如 `->` 返回类型支持未验证、`demo.lz` 仍用旧式 `: int`/`case X:`），
> 在条件 2 满足前应先消歧，避免自举样例误用语法。

## 三、自举成功的判定标准

| 判定维度 | 成功标准 |
|----------|---------|
| 功能等价 | 自举产物通过 100% 的测试套件 |
| 行为一致 | 自举产物与外部构建产物在所有测试用例上输出一致 |
| 独立构建 | 不依赖任何外部预构建的二进制即可完成构建 |
| 迭代稳定 | 连续 3 代自举产物二进制 MD5/SHA256 完全一致 |
| 持续集成 | 自举流水线在 CI 中稳定运行，近 2 周无失败 |

> **本项目语境**："独立构建"在现有后端即 Rust 的架构下，**最小可信基座为 Rust toolchain**（无法脱离 rustc）。
> 因此"不依赖外部预构建二进制"在本项目中应解释为"不依赖手写 `.rs` 配套 / 不依赖预编译的 `lzc` 二进制"，
> 而非脱离 Rust 工具链；彻底脱离需路线 B 的自建后端。
