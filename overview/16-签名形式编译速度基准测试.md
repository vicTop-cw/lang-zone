# 签名形式编译速度基准测试

## 问题
用户所有函数都使用 `..,..`（Both 模式可变参数）签名，编译速度会比 typed 签名快多少？

## 测试方法
- **编译器**：`lang-zone.exe` （release 构建）
- **样本量**：每文件 40 个函数，各跑 25 次
- **两组对照**：
  1. **隔离测试**（Isolated）：body 完全相同（`= 42`），仅签名不同
     - `typed_iso.lz`：`def f00(a: int, b: int) -> int = 42`（×40）
     - `var_iso.lz`：`def f00(..,..) = 42`（×40）
  2. **真实 body**（Realistic）：使用参数的运算
     - `typed_real.lz`：`def f00(a: int, b: int) -> int = (a + b) * 2`（×40）
     - `var_real.lz`：`def f00(..,..) = args.len() * 2`（×40）

## 结果

| 场景 | Typed (median) | ..,.. (median) | 差异 |
|------|:---:|:---:|:---:|
| 隔离测试 (body=42) | 108.10 ms | 104.29 ms | -3.5%（快 3.5%） |
| 真实 body (运算) | 107.98 ms | 106.50 ms | -1.4%（快 1.4%） |

## 结论
1. **没有统计学显著差异** — 4ms 的差距被运行间噪声（±35-76ms）完全覆盖
2. typed 签名的类型推断开销极小（~3ms/40函数），不是编译瓶颈
3. `..,..` 生成 `Vec<Box<dyn Any>>` + `HashMap` 的额外 codegen 开销也被前端减少的类型解析抵消了
4. **选择签名风格的依据应是正确性/可维护性/清晰度，而非编译速度**

## 文件
- `_bench/typed_iso.lz` / `_bench/var_iso.lz` — 隔离测试源文件
- `_bench/typed_real.lz` / `_bench/var_real.lz` — 真实 body 源文件
