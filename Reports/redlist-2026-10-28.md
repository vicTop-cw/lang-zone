（327 = `DEMO/**.lz` 348 件减去 `99_errors/` 负例目录 21 件，与 `find_demo_files()` 的排除逻辑一致。）

### 2.1 根因（已最小化，非环境、非陈旧 rlib）

`DEMO/lz_std/result.lz` 自己声明了 `enum Result<T, E>: Ok(T) Err(E)`（第 9–13 行），于是**本 crate 内 `Result` 指向用户枚举**。
出问题的发射点是第 315 行：

```lz
let c: Result<int, str> = a.or_else(|e: str| -> Result<int, str> = Ok(len(e)))
```

生成的 Rust：

```rust
// 错误形态：裸 Ok(...) → 解析到 std::result::Result::Ok
let c: Result<i64, String> = a.or_else(|e: String| -> Result<i64, String> { Ok((e.len() as i64)) });
//   expected `Result<i64, String>`(本 crate 的枚举), found `Result<i64, _>`(std)
```

而同一文件里其它位置（`Result::Ok(1i64)` / `Result::Err(...)`）都**带限定**，所以是「限定逻辑有分支没覆盖到」，不是「从来没实现」。

**判别实验**（全部在 `temp/redlist/cases/`，native 均 OK）：

| 形态 | 生成结果 | 结论 |
| --- | --- | --- |
| `Ok(5)` 字面量 | `Result::Ok(5i64)` | ✅ 限定 |
| `Ok(x)` 变量 | `Result::Ok(x)` | ✅ 限定 |
| `Ok(x + 1)` 二元运算 | `Result::Ok(e + 1i64)` | ✅ 限定 |
| **`Ok(len(e))` 函数调用** | **`Ok((e.len() as i64))`** | ❌ **丢限定** |
| **`Ok(inc(e))` 用户函数调用** | **`Ok(inc.clone()(e))`** | ❌ **丢限定** |

⇒ 触发器精确为「**变体构造器的实参是 Call**」；与字面量/变量/二元运算无关，与 builtin 还是用户函数无关。

- **阶段**：生成成功（lzc exit=0），**rustc E0308**。
- **疑似模块**：`src/ir/codegen/expr_gen.rs`。`gen_call` 的枚举变体限定分支在 1804–1820 行（`enum_variants` 命中即发 `Enum::Variant(..)`），但在「实参是调用」的路径上，更早的分支（约 2988–3014 行，`Ok/Err/Some/None` 的实参 clone 分支）先返回了**裸 `callee(args)`**，限定分支根本走不到。
- **最小复现**：`temp/redlist/cases/v5_ok_call_only.lz`（以及 `minC_*`/`minB_*` 一族）。
- **台账**：查 `memory/bugs.md` 全库无「变体构造器未限定」条目；仅有 BUG-30（`CY/TESTS/99_bootstrap/lz_std.lz` 的 E0308，已 FIXED，根因在 `convert_decl.rs` 的尾表达式，与本条无关）与一条历史 `result.lz` 记录（`assert val.err() == None` 的 E0425，也已修）。⇒ **新**。

## 5. 「新发现」单列（按影响面排序）

> 判据：`memory/bugs.md` 全文检索无对应条目，或条目形态明显覆盖不到该现象。

### N1（最高影响，native 主路径 + 阻塞门禁）变体构造器实参为 Call 时丢枚举限定
- **样本**：`DEMO/lz_std/result.lz`（门禁唯一红）+ 最小件 `temp/redlist/cases/v5_ok_call_only.lz`
- **E-code**：E0308（`std::result::Result<i64,_>` vs 本 crate `Result<i64,String>`，rustc 原话 "have similar names, but are actually distinct types"）
- **一行根因**：`gen_call` 在「实参是调用」的分支里先返回裸 `Ok(..)`，`enum_variants` 限定分支（expr_gen.rs 1804–1820）走不到。
- **影响面**：**任何**用户自定义枚举只要变体名与 Rust prelude 重名（`Ok`/`Err`/`Some`/`None`），且用「带调用实参」的构造形式，就必然编不过。`lz_std/*` 整层都定义自己的 `Result`/`Option`，属高危区（本轮只 `result.lz` 命中，其余靠「实参非 Call」侥幸躲过）。
- **复现**：`bash temp/redlist/cases/_try.sh temp/redlist/cases/v5_ok_call_only.lz`

### N2（长尾最大，17 条）字符串切片起点未 cast：`s[idx..(idx+1) as usize]`
- **样本**：`p42_min_block.lz` / `p43_nested_block.lz` / `p41_full_tokenize.lz` / `p40_*` / `p37` / `p38` / `base_parser` / `lexer_c/d` / `parser_b/e/step1/step2/v175` / `p_t1a` / `p32` / `p23_lexer_probe`（共 17，其中 10 件为 `.diffwork` 在途产物）
- **E-code**：E0308 + E0277（`str` cannot be indexed by `Range<i64>`）
- **一行根因**：rs-lz 只给**上界**加 `as usize`，起点仍 `i64` → range 两端类型不一致。native 侧同源发射正确。
- **影响面**：几乎所有「字符级扫描器/词法器」写法（`s[i..i+1]`）都会中；这解释了为什么 17 个 tokenizer 探针**成片**红。
- **最小复现**：`temp/redlist/cases/minA_slice_cast.lz`
  ```rust
  // rs-lz 产物
  return s[idx..(idx + 1i64) as usize];   // ← 起点 idx 未 cast
  ```

### N3（6 条）`int(str)` 被发成 `(s as i64)`
- **样本**：`p30_var_cast` / `p31_field_cast` / `p33_enum_cast` / `p34_field_enum_cast` / `p35_listlit_cast` / `p36_list_concat_cast`
- **E-code**：**E0605** non-primitive cast `String as i64`
- **一行根因**：转换发射在 rs-lz 侧退化成 `as` cast；台账 BUG-477（`str(x)`/`int(x)` 原发成函数调用）已 FIXED，但**修的是函数调用形态，没覆盖 `as`-cast 形态**。
- **影响面**：所有「读数字」路径；与 N2 叠加即「扫描器整层不可用」。

### N4（5 条）字符串拼接 `String + &String` 尾值失配
- **样本**：`p18_recursive` / `p20_norec` / `p22_option_pattern` / `p23_nested_pattern` / `p44_nested_fixed`
- **E-code**：E0308（`expected &str, found String`）
- **一行根因**：rs-lz 的 `+` 拼接只在一侧补 `.to_string()`/`&`，另一侧裸 `String` 直接进 `&str` 位置。BUG-450 只修了 native 侧。

### N5（2 条）三元/`if` 表达式缺 then 块 → `if x > 3i64  else {`
- **样本**：`p11_macro_indent` / `p11b_macro_nested`；**E-code**：E0423（rustc 附加 `help: add a block here`）
- **一行根因**：rs-lz 把 `a if c else b` 的 then 分支丢了，只发 `if c` + else 块。

### N6（2 条）tuple / typepack 索引与 `.0` 字段
- **样本**：`p12_typepack`（E0608 `cannot index into (String,i64)`）、`p12c_pack`（E0609 `no field 0 on type Ts`）
- **一行根因**：单元素 tuple 被发成 `(Ts)`（无尾逗号 → 不是 tuple），后续 `args[0]` / `.0` 全崩。

### N7（2 条）模块 import / 外部符号未展开
- **样本**：`p5_alias`（E0432 `unresolved import moda` + E0425 `m`）、`p16_lzi`（E0425 `external_add`）
- **一行根因**：rs-lz 把 LZ 的 `import` 原样发成 Rust `use moda;`，既没内联模块也没生成 crate。

### N8（4 条，杂项，优先级最低）
- `lit_probe`：E0425 `name` —— 字符串插值把占位符变量丢了
- `p8_yield`：E0425 `__gen_vec` —— 生成器底座未声明（native 会发）
- `p24_slice_method`：E0599 `no method slice on String` —— LZ `slice()` 未映射到 `[a..b]`
- `neg_error_uncaught_panic_ok`：E0425 类语法错 —— `panic!("boom".to_string())` 形态（注意：这是 `neg_*` 前缀里的**正向** panic 探针，不是负例）

### 附：最小化过程中额外暴露的一条 rs-lz 缺陷（未计入 40）
**函数尾表达式被发成语句，尾值丢失**。`def main() -> int = ... \n 0` 生成 `{ ...; 0i64; }` → E0308 `expected i64, found ()`。
- 复现：`temp/redlist/cases/minB_str_int_cast.lz`（该件同时叠加了 N3 的干扰，故只作旁证）
- 该形态会把「任何以字面量结尾的函数」打成红，**建议下一轮优先复核**——它可能污染上面若干 E0308 的归因。
