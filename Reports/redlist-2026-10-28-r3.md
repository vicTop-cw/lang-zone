10 条分歧**全部是 rs-lz 侧 `RC=124`（10s 超时被杀）**，native 侧 `RC=0` 且输出正常 ⇒ **rs-lz 产物死循环**：

| 样本 | native | rs-lz | 生成物里的遮蔽点 |
| --- | --- | --- | --- |
| `div-tools/probes/p40_indent_tokenize.lz` | RC=0 | **RC=124** | 1 处 |
| `div-tools/probes/p41_full_tokenize.lz` | RC=0 | **RC=124** | 2 处 |

| `div-tools/probes/.diffwork/parser_v175.lz` | RC=0 | **RC=124** | 9 处 |

**根因（已最小复现）**：rs-lz 把「嵌套块内、对已在作用域内的变量赋值」发成 `let mut x = …`（= Rust 遮蔽），而 native 发 `x = …`。
`p42_min_block.lz` 的 `tokenize` 里 `i = r.1` + `line_start = false` 被遮蔽 ⇒ 外层 `i` 恒为 0 ⇒ `while i < str_len(src)` 永不退出：

```rust
// rs-lz 产物（错）：块内重新声明，外层 i/line_start 被冻住
while i < str_len(src.clone()) {
    let c: String = char_at(src.clone(), i);
    if line_start && c == " ".to_string() { {
        let mut r: (i64, i64) = scan_indent(src.clone(), i);
        tokens = { … };
        let mut i = r.1;              // ← 遮蔽
        let mut line_start: bool = false;   // ← 遮蔽
    } }
```
```rust
// native 产物（对）
        let r: (i64, i64) = scan_indent(src.clone(), i);
        tokens.push(Token::Indent { v: r.0 });
        i = r.1;                      // ← 赋值
        line_start = false;
```

最小复现件（均在 `temp/redlist/cases/`，native 全绿）：

| 最小件 | 形态 | rs-lz 生成 |
| --- | --- | --- |
| `mS1.lz` | `while` 体内 `if` 里 `i = r.1` | `let mut i = r.1;` ❌ |
| `mS2.lz` | `while` 体内 `if` 里 `i = 7`（纯字面量） | `let mut i: i64 = 7i64;` ❌ |
| `mS3.lz` | **直接**在 `while` 体里 `i = 7`（不套 `if`） | `let mut i: i64 = 7i64;` ❌ |
| `mS4.lz` | 双层嵌套 + 另一个循环变量 `n = n + 1` | `i` 遮蔽 ❌ / `n += 1` ✅ |

**关键定性：这不是本轮五个修复引入的回归。** 证据：
1. 触发点在赋值发射路径，本轮两处 rs-lz 提交（`e22c897` / `b78803c`）的 diff **没有碰**该路径（只改切片 cast、`int(str)`、拼接、空 then、实参 clone）。
2. HEAD 上的缓解判据只有一条：`gen_let` 里 `if expr_has_var(v, n)`（BUG-454），**只覆盖「右值引用自身名字」**（`i = i + 1` → 正确发 `+=`）；右值不自引用（`i = r.1` / `i = 7` / `line_start = false`）就落到 `let mut`。HEAD 全文件 `grep decl_has` = **0 次**（无作用域表）。
3. 这 10 件在 r1 里**根本编不过**（E0308/E0605），所以该缺陷此前被编译错误**遮住**、无从观测。也就是说：「新红」的说法只在**行为维度**成立，编译维度仍是净改善。

**并且它已在被处理**：量测结束后（10:28）工作树出现一条**未提交**改动（`src/ir/lz_codegen_lib.lz` +95/−39，注释标 `T0r20`），内容正是「维护作用域表 + `m && decl_has` 判据」，注释里点名 `p43/p44 死循环` —— 与本轮实测的 10 条完全同一批。⇒ 建议 parent 直接与该车道对齐，**不要再另开一份重复修复**。
