# 包与导入

## 1. 可见性规则

**无 `pub` 关键字**（`pub` 是保留字）。可见性通过命名约定控制：

| 标识符开头 | 可见性 |
|-----------|--------|
| 非下划线 | 公开 |
| `_` 前缀 | 私有（模块内可见） |
| `__xxx__` 双下划线包围 | 魔法方法，始终公开 |

```
// 公开
def factorial(n: int)-> int =
    ...

// 私有
def _internal(n: int)-> int =
    ...

// 公开（魔法方法）
def __add__(Self, other: Point)-> Point =
    ...
```

### 1.1 公开 API 签名约束

> ⚠️ 未实现（规划中）：`[_Sortable]` 形式的 trait 约束列表不是当前编译器语法（trait 约束用 `where T <: Bound`）；公开函数暴露私有 trait 的编译期检查亦为规划行为，示例暂无法通过 lzc 编译。

公开函数的签名中**不能出现私有 trait**，否则编译报错：

```
trait _Sortable<T> =
    def cmp(Self, other: T)-> int

// ❌ 编译错误 — 公开函数暴露了私有 trait
def sort(xs: [_Sortable]) = ...

// ✅ 私有函数无此限制
def _sort(xs: [_Sortable]) = ...
```

## 2. 包结构

与 Python 一致：包含 `__init__.lz` 的目录即为一个包。

```
myapp/
  __init__.lz              // 标记 myapp 为包（可为空）
  main.lz
  utils/
    __init__.lz
    math.lz
    strings.lz
  models/
    __init__.lz
    user.lz
```

## 3. 导入语法

```
// 导入整个模块
import utils.math

// 导入指定符号
import utils.math::{add, sub}

// 导入并别名
import utils.strings as strutil

// 从模块导入单个符号
from utils.math import add

// 从模块导入多个符号
from utils.math import add, sub, mul

// 惰性导入
lazy import std::heavy_module
```

> ⚠️ 未实现（规划中）：`lazy import` 当前编译器不解析，示例暂无法通过 lzc 编译；其余 `import` / `from ... import` / `as` / `::{}` 语法已对齐基线。

> **路径分隔符**：`import` 同时接受 `.` 与 `::` 作为路径分隔符，转译到 Rust 时统一用 `::`：
> - `import std::collections::HashMap` → `use std::collections::HashMap;`
> - `import utils.math::{add, sub}` → `use utils::math::{add, sub};`
>
> **`Some`/`None`/`Ok`/`Err` 限定**：当源码自行定义了名为 `Option`/`Result` 的枚举时，
> 这些构造子会被限定为 `Option::None`、`Result::Ok` 等，避免与标准库冲突。

## 4. 命名空间访问

使用 `::` 分隔路径：

```
result = utils.math::add(1, 2)
s = strutil::trim("  hello  ")
```

## 5. 标准库

标准库以 `std::` 开头：

```
import std::net::{TcpListener, TcpStream}
import std::io::{read_to_string, write}
import std::ml::{Tensor, Model}
```

## 6. 宏模块的导入

> ⚠️ 未实现（规划中）：宏模块（`#!bin macro` 及 `!` 标记、如 `@mymacros.derive!`）当前编译器不解析，示例暂无法通过 lzc 编译，详见 [14-宏与转译期.md](14-宏与转译期.md)。

宏模块通过 `#!bin macro` 声明，导入后可使用其中的 `!` 标记：

```
import mymacros

@mymacros.derive!
struct Point =
    x : f64
    y : f64
```

详见 [14-宏与转译期.md](14-宏与转译期.md)。

## 7. 与目标语言的衔接

Lang-Zong **仅 Rust 单后端**。`.lz` 固定转译为 `.rs`：

| 目标语言 | `__init__.lz` | `import utils::math` | 命名空间访问 |
|---------|---------------|---------------------|-------------|
| Rust | `mod.rs` | `use crate::utils::math;` | `utils::math::add` |

> ⚠️ Cython/Python 目标后端的对照表已在早期版本中移除。

## 8. Std Bridge 桥接系统

除了导入用户模块，编译器内置了 **std bridge** 系统，将 Lang-Zong 符号自动映射到 Rust 标准库。

### 8.1 TOML 驱动的符号映射

`std/bridge.toml` 和 `std/modules/*.toml` 定义了模块/类型/方法/别名的映射规则：

```
# std/bridge.toml — 桥接入口
[modules.fs]
rust_prefix = "std::fs"
items = ["read_to_string", "write", "exists", ...]
```

编译器在编译时读取这些 TOML 文件，将 `import std::fs::read_to_string` 映射到 Rust 的 `std::fs::read_to_string`。

### 8.2 支持的特性

- **模块导入**：`import std::collections::HashMap` → `use std::collections::HashMap;`
- **类型映射**：`str` → `String`、`int` → `i64`、`List<T>` → `Vec<T>`、`Dict<K,V>` → `HashMap<K,V>` 等
- **方法调用**：桥接层自动 resolve 方法的 Rust 路径
- **类型重写**（`rewrite_type`）：`str.toml` 可覆盖默认类型映射
- **Tier-2 门控**：不稳定的 nightly API 标记为 Tier-2，需显式 opt-in

### 8.3 架构

桥接层由 `bridge.rs`（注册表 + 统一路由）、`bridge_source.rs`（编译期源码映射）、`bridge_ffi.rs`（C ABI）、`bridge_cli.rs`（IPC 进程间通信）构成，当前仅 `SourceBridge` 可用。

详见 `workbuddy/plan/std-bridge-plan.md`。

## 9. 已移除的特性

| 特性 | 状态 | 说明 |
|------|------|------|
| `toml` 关键字 | ❌ 移除 | 用 `__toml__.lz` 配置文件替代 |
| `package` 关键字 | ❌ 不支持 | 目录即包 |
| `external` 外部语言互操作 | ❌ 移除 | 用 FFI 或宏模块替代 |

## 语法边界

- ✅ 导入语法：`import a.b.c`（或 `import a::b::c`）、`import a::b::{x, y}`、`from a import x, y`、`import a as b`，转译到 Rust 统一为 `use ...;`。
- ✅ `::` 后的花括号 `{}` 是导入符号列表的定界符，如 `import std::net::{TcpListener, TcpStream}`。
- ✅ `.lz` 模块路径可用 `.` 或 `::` 作为分隔符，二者等价。
- ✅ 函数返回类型用 `->`：`def f() -> T = ...`；函数类型本身也用 `->`，如 `(T) -> U`。
- ❌ `from X import a, b` 的顺序固定：必须先写模块路径 `X`，再写 `import`，最后写符号列表，不可颠倒。
- ❌ `lazy import` 未实现；多后端目标（Cython/Python）未实现，当前仅 Rust。
- ❌ 宏模块（`#!bin macro` 与 `!` 标记）未实现；`[_Trait]` 形式的 trait 约束列表不是当前语法（用 `where T <: Bound`）。
