# Lang-Zong 核心语法文档 v1 — 总览

> *"写如 Python，跑如 Rust。"*

## 1. 语言定位

Lang-Zong 是一门**转译型**语言：

- 源码 `.lz` 文件由编译器转译为 **Rust 源码**
- 不直接生成机器码，只做语法层转译，复用 Rust 的类型系统、所有权与优化器
- **单后端：Rust**

核心原则：

1. **Rust 的 Python 皮** —— 保留所有权、零开销、无 GC，用缩进语法
2. **缩进即语法** —— 4 空格缩进决定作用域
3. **默认可变 + 默认拷贝（copy-by-default）** —— 默认绑定可变更、值语义优先拷贝；`mut` 为兼容 no-op，显式 `^` 后缀转移所有权
4. **表达式体** —— 函数最后一行自动 return

## 2. 快速一览

```lz
# 变量
x = 1
mut y: int = 2

# 函数
def add(a: int, b: int)-> int =
    a + b

# 结构体
struct Point =
    x: f64
    y: f64

# 泛型
def max<T>(a: T, b: T)-> T where T <: Ord =
    if a > b: a
    else: b

# 枚举
enum Option<T> =
    None
    Some(T)

# 模式匹配
match x:
    case 0 => "zero"
    case _ => "other"

# 管道
nums |> filter(|x| x > 2) |> map(|x| x * 2)

# 所有权
a = [1, 2, 3]
b = a              # 默认拷贝（copy-by-default），a 仍可继续使用
```

## 3. 编译器

```
lzc hello.lz → hello.rs → rustc → ./hello
```

## 4. 设计原则

1. **不碰语义，只做语法** —— 所有权、性能由 Rust 编译器负责
2. **缩进体** —— `def`/`struct`/`enum`/`trait`/`impl` 定义体用 `=` 开启
3. **类型标注在右侧** —— `x: int` 而非 `int x`
4. **表达式优先** —— 几乎所有东西都是表达式

## 5. 全局语法边界（硬约束速查）

- ✅ 类型标注写在右侧 `x: int`，不是 `int x`。
- ✅ 函数/类型定义体以 `=` 开启（`def f()-> T =`、`struct S =`、`enum E =`、`trait`、`impl`），回退缩进即闭合，无 `end` 关键字。
- ✅ 复合语句（`if`/`elif`/`else`、`for`/`while`/`loop`、`match`/`case`、`guard ... else:`、`with ... as`、定义体）换行体必须缩进 4 空格；Tab 视作 4 空格但同一文件内勿混用。
- ✅ 返回类型用 `->`，函数类型注解也用 `->`（`(T) -> U` 当前 codegen 有缺陷，见 08）。
- ✅ 类型参数统一用尖括号 `<>`，不用方括号 `[]`；`where T <: Bound` 必须与签名写在同一行、`=` 之前。
- ✅ 默认绑定可变更、值语义拷贝（copy-by-default）；`mut` 为兼容 no-op，`^` 后缀转移所有权。
- ❌ 不存在 `name :` Callable 调用块、`KwArgs:`/`Args:` 包块、`out` 关键字、`pass` 关键字、`class`/`type`/`val`/`var` 关键字（均规划/未实现）。构建块 `=:`/`~:`/`*: ` 已实现，见 [构建块.md](构建块.md)。
- ❌ `#` **不是注释**；单引号字符串、`b"..."`、`{:...}`、`[int]`、`x :=` 等写法均不支持。
- ✅ `try`/`catch`/`finally` 已实现为表达式（见 [10-控制流.md](10-控制流.md) §7）；`panic(msg)` 已实现（见 [18-错误处理.md](18-错误处理.md) §7）；`defer` 已实现（见 [10-控制流.md](10-控制流.md) §6.3）。
