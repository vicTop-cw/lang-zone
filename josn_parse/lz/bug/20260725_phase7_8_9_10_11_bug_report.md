## 阶段 7: List/集合操作与迭代器

### 测试文件: `_test_collections.lz`

| Bug 编号 | 严重程度 | 描述 |
|----------|----------|------|
| Bug-59 | 🔴 | 空列表 `[]` 生成 `Vec<>` 缺少类型参数 |
| Bug-60 | 🔴 | 嵌套列表索引 `outer[0]` 产生 move 而非 borrow |
| Bug-61 | 🟡 | `arr.pop()` 返回 `Option<i64>` 打印为 `Some(3)` |

### Bug-59: 空列表类型推断 (E0107)

**lz 代码**:
```lz
arr = []
```

**生成的 Rust**:
```rust
let mut arr: Vec<> = vec![];
```

**错误**: `struct takes at least 1 generic argument but 0 generic arguments were supplied`

**修复**: 应为 `Vec<i64>` 或根据上下文推断类型参数

### Bug-60: 嵌套列表移动语义 (E0507)

**lz 代码**:
```lz
outer = [[1, 2], [3, 4]]
inner = outer[0]
```

**生成的 Rust**:
```rust
let mut inner = outer[0 as usize];
```

**错误**: `cannot move out of index of Vec<Vec<i64>>`

**修复**: 应为 `&outer[0 as usize]` 或 `outer[0 as usize].clone()`

### Bug-61: pop() 返回 Option

**lz 代码**:
```lz
val = arr.pop()
print(val)
```

**运行输出**: `Some(3)` 而非期望的 `3`

**分析**: lz 的 `pop()` 映射到 Rust 的 `Vec::pop()` 返回 `Option<T>`，lz 层应自动解包或提供不同的 pop 语义

## 阶段 8: 字符串方法深度测试

### 测试文件: `_test_string_methods.lz`

| Bug 编号 | 严重程度 | 描述 |
|----------|----------|------|
| Bug-62 | 🔴 | 字符串拼接 `s1 + " " + s2` 类型不匹配 |
| Bug-63 | 🔴 | `s.len()` 返回 `usize` 与 `i64` 比较失败 |
| Bug-64 | 🔴 | 字符串索引 `s[i]` 不支持 `i64` 类型 |

### Bug-62: 字符串拼接 operand 顺序 (E0308)

**lz 代码**:
```lz
combined = prefix + " " + suffix
```

**生成的 Rust**:
```rust
let mut combined: String = prefix + " " + suffix;
```

**错误**: `expected &str, found String` — 第二个 `+` 操作符右侧是 `String` 而非 `&str`

**修复**: 应为 `prefix + " " + &suffix`

### Bug-63: len() 返回类型 (E0308)

**lz 代码**:
```lz
while i < s.len():
```

**生成的 Rust**:
```rust
while i < s.len() {  // i: i64, s.len(): usize
```

**错误**: `expected i64, found usize`

**修复**: 应为 `i < (s.len() as i64)` 或使用 `usize` 类型

### Bug-64: 字符串索引类型 (E0277)

**lz 代码**:
```lz
print(s[i])  // i: int
```

**生成的 Rust**:
```rust
println!("{:?}", s[i]);  // i: i64
```

**错误**: `the type str cannot be indexed by i64`

**修复**: 应为 `s.chars().nth(i as usize).unwrap()` 或自动转换

## 阶段 11: Enum/Defer 边界

### 测试文件: `_test_enum_defer.lz`

| Bug 编号 | 严重程度 | 描述 |
|----------|----------|------|
| Bug-65 | 🔴 | Enum match 臂缺少 `Status::` 前缀 |
| Bug-66 | 🔴 | Enum 变体构造 `Failed("str")` 类型不匹配 |

### Bug-65: Match 臂枚举变体前缀 (E0170)

**lz 代码**:
```lz
match s:
    case Ok_:
        print("OK")
    case Failed(msg):
        print(msg)
```

**生成的 Rust**:
```rust
match s {
    Ok_ => println!("OK"),           // 被当作新变量绑定
    Status::Failed(msg) => { ... },  // 有数据的变体有前缀
    Pending_ => println!("Pending"), // 无数据的变体缺少前缀
}
```

**错误**: `pattern binding Ok_ is named the same as one of the variants`

**分析**: 带数据的变体 `Failed(msg)` 正确生成了 `Status::Failed`，但无数据的变体 `Ok_` 和 `Pending_` 缺少 `Status::` 前缀

**修复**: 所有 match 臂中的枚举变体都应使用 `Status::Variant` 形式

### Bug-66: 枚举变体字符串字面量 (E0308)

**lz 代码**:
```lz
s = Failed("Something went wrong")
```

**生成的 Rust**:
```rust
let mut s = Status::Failed("Something went wrong");
```

**错误**: `expected String, found &str`

**修复**: 应为 `Status::Failed("Something went wrong".to_string())`
