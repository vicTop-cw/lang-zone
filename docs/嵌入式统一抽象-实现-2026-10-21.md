## 一、抽象与档位

内嵌进 `.lz` 的外语言按**值怎么跨过边界**分两档，不按语言分 N 套：

| 档 | 判据 | 语言 | 跨界方式 | 代码位置 |
|---|---|---|---|---|
| `Source` | 纯转译为 Rust 源码 | `tnr` / `rust` / `rs` | 编译期消解（逐字/转译进 `.rs`） | `src/embed/adapters.rs:9` `SOURCE_LANGS`，行为仍在 `src/ir/codegen/decl_gen.rs:264` |
| `Cli` | 其余一切 | `mojo` / `python`(`py`) / `c` / `scala` / 未知语言 | 摘源码 → 该语言工具链建库 → **CLI 命令行 + 结果序列化** | `src/embed/mod.rs:31` `EmbedTier`、`src/embed/mod.rs:179` `trait EmbedLang`、`src/embed/mod.rs:215` `resolve()` |

`BridgeLevel` 的 `LinkTime(1)` / `Runtime(2)` / `SharedMemory(4)` 三档**明确不做**（「嵌入式只走最容易的路」）。`src/bridge/embed.rs` 是 Level 4 共享内存那套，与本抽象无关，保持未注册。

新增语言 = 只在 `src/embed/adapters.rs` 加一个 adapter；不写第二套 codegen。

## 二、产物身份：有 main 即可执行，无 main 即库

判据来自**摘出的外语言源码本身**，不由作者额外声明：`EmbedLang::has_main()`。

- `Executable`：建出/直接跑，结果取 stdout ⇒ LZ 侧调用面 `<产物名>_run()`。
- `Library`：产物名即模块名。既能被**同语言其它程序** `import`（python 侧已在门禁里真跑证明），也能被**内嵌它的 LZ** 经生成的垫片调用 ⇒ LZ 侧调用面 `<产物名>_<函数名>(...)`。

命名（规划的决策 1，本轮裁决）：
- **Cli 档产物 = `<语言>_<源文件主干>`**，如 `mojo_calc` / `python_calc`（你要的前缀形）。
- **Source 档的 Rust 模块名 = `<base>_<lang>`**（如 `calc_tnr`、`input_tnr`）**一字未动** —— 它被 `tests/bridge_e2e.rs:171` 一类断言钉着。
- 两侧是两个命名空间，互不串台；这条由 `tests/embed_unify_r15.rs::source_tier_text_and_cli_artifact_names_coexist` 守。
- 产物目录：`build/embed/<模块主干>/<产物名>/`（`src/embed/artifact.rs:14`）。

## 三、跨界协议（为什么不是 stdin 的 LineProtocol）

`src/bridge/cli.rs` 原有的 `CliEndpoint` 是 Level 3 的 **stdin 管道版**（`METHOD k=v k=v` 一行 + 超时轮询）。本抽象改用：

```
请求：argv = <method> [key=value ...]
响应：stdout 最后一行  OK:<值>  /  ERR:<原因>
```

理由（写在 `src/embed/shim.rs` 头部，不复述成口号）：
1. 摘出来的外语言程序普遍只有 `sys.argv`，要它对 stdin 做行读取 + 轮询是额外负担；
2. stdin 版的 `k=v` 以空格分隔 ⇒ **含空格的字符串参数会被打散**；argv 逐段传递天然免疫（这条有专门判据 `str_params_and_results_cross_the_boundary_byte_exact`）。

响应里的换行/反斜杠由分发入口转义、垫片反转义；解析失败一律 `panic!` 带原文，**不返回默认值**（把「外语言没跑起来」伪装成合法的 `0`/空串正是本项目历来在清的那类静默错）。

## 五、本轮做的裁决（原规划 §4 的五个决策项）

1. **命名**：Cli 档用 `<语言>_<name>` 前缀；Source 档 `<base>_<lang>` 保留不动（理由见 §二）。
2. **`SYNTAX/` 不开新章**：只落本文档 + 实现；待实现稳定再按 3.4+ 把 `__bridge_tier__="cli"` 从"合法值"升成"有实现"。
3. **「无 main 即库」的作用范围**：只作用于**摘出的外语言产物**。LZ 自身的入口语义（`src/ir/codegen/mod.rs` 里从顶层语句自动补 `pub fn main()` 那条，既往入账 BUG-PR-001）一字未动。
4. **后端范围**：第一版只做 rust 后端。cy 后端对 `#[embed(lang)]` 仍走注释降级（`src/ir/codegen_cython.rs:603` 一带），记入流程债 —— 接 CLI 等于给 cy 再加一层 Python 子进程，收益不抵风险。
5. **`SerializationFormat::JsonLines` 空桩**：本抽象**不选它**（选的是 argv + 单行 OK:/ERR:）；`JsonLines` 保持原样未被 embed 路径接走，因此不存在"选中空桩然后静默"的那条路。原 stdin 那套 endpoint 面也未被改动，故既有行为不变。

> **复核抓到的一次引用失效（2026-10-21 复核轮）**：正文里手写的 `file:line` 会在别车道并发编辑下变成假引用——`expr_gen.rs:1731` 落笔时确实指着 `print_arg_is_display` 的调用点，40 分钟后同一行已是 `} else {`（别车道改动把行号顶掉了），而「行号 ≤ 总行数」这种门照样放行。规矩：**本文档内的叙述性引用只写「文件 + 符号名」，精确行号只留给台账第三栏那批由 needle-grep 现场生成的锚点**。
