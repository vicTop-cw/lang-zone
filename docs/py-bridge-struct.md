# PyO3 绑定结构说明（py-bridge-struct）

> 版本：v163 配套（2026-08-19）
> 定位：**PyO3 绑定结构对齐基准**。本文档定义 `@export(Python)` 生成产物的依赖注入、导出入口签名与绑定结构，作为 Cy(Cython) 后端实现的对齐基准——Cy 后端必须与本文档描述的结构保持一致。
> 边界：本文档与 Cargo.toml 依赖注入由 file-agent 负责；**Cy 后端代码/结构不属于本文档职责范围**，禁止以本文档为由改动任何 Cython/Cy 代码。

## 1. 依赖注入（Cargo.toml）

### 1.1 精确版本锁定

```toml
[dependencies]
pyo3 = { version = "0.22.6", optional = true, features = ["extension-module"] }
```

- 版本 `0.22.6` 为锁定基准，不得使用 `"0.22"` 等宽泛版本表达。
- `features = ["extension-module"]`：生成 `.pyd`/`.so` 扩展模块所需（禁止链接 Python 解释器时启用）。

### 1.2 Feature 隔离

```toml
[features]
default = ["infer"]          # 不含 py-bridge
py-bridge = ["dep:pyo3"]     # 启用后才编译 pyo3
```

- 未启用 `py-bridge` 时：`@export(Python)` 只生成绑定源码字符串（`bridge/python.rs::generate_module`），不编译 pyo3，零外部依赖保持。
- 启用 `py-bridge` 时：生成产物可与本项目一同编译为 Python 扩展模块。

### 1.3 导出产物 Cargo.toml 提示

`@export(Python)` 产物源码文件头包含依赖提示注释，消费者需在自身 Cargo.toml 中注入：

```toml
[dependencies]
pyo3 = { version = "0.22.6", features = ["extension-module"] }
```

## 2. 导出入口签名

`@export(Python)` 的完整绑定由 `src/bridge/python.rs` 的 `PyO3Bridge::generate_module()` 生成，结构固定为四段：

```
// Generated by Lang-Zong PyO3Bridge
// Python module: <module_name>
use pyo3::prelude::*;

// ① #[pyclass] 类型（按 [types] 清单顺序）
// ② #[pyfunction] 函数（按 [functions] 清单顺序）
// ③ #[pymodule] 模块入口
```

### 2.1 模块入口签名（唯一导出点）

```rust
#[pymodule]
fn <module_name>_py(_py: Python, m: &PyModule) -> PyResult<()> {
    m.add_function(wrap_pyfunction!(<fn_name>, m)?)?;
    m.add_class::<<type_name>>()?;
    Ok(())
}
```

- 模块函数名 = `<模块名>_py`（如 `mylib` → `mylib_py`）。
- 所有 `#[pyfunction]` 经 `wrap_pyfunction!` 注册，所有 `#[pyclass]` 经 `add_class` 注册。
- PyO3 通过 `#[pymodule]` 函数名（`<name>_py`）与生成的扩展模块名对应，消费者以 `import <module_name>` 导入。

### 2.2 函数导出签名

```rust
#[pyfunction]
pub fn <fn_name>(<arg>: <rust_type>, ...) -> <rust_type> { ... }
```

- 参数名/类型取自 TOML 清单 `[functions]` 的 `args`（`"a: int, b: int"` 形式）。
- 返回类型取自 `ret`（`None`/`void` → `()`）。
- 函数体当前为占位 `todo!("Implement __py_<fn_name>")`，后续由 lz 函数体 codegen 填充（`resolve_call` 返回的 `rust_path` 为 `__py_<fn_name>`）。

### 2.3 类型导出签名

```rust
#[pyclass]
pub struct <TypeName> {
    #[pyo3(get, set)]
    pub <field>: <rust_type>,
}

#[pymethods]
impl <TypeName> {
    #[new]
    pub fn new(<field>: <rust_type>, ...) -> Self { ... }
}
```

- 字段按 lz 类型映射为具体 Rust 类型（**不得降级为 `PyObject`**，见 §3 映射表）。

## 3. 类型映射表（lz → Rust/PyO3）

| lz 类型 | Rust 类型 | 说明 |
|---|---|---|
| `int` / `i32` / `i64` | `i64` | PyO3 自动转换 `int` |
| `f64` / `float` | `f64` | PyO3 自动转换 `float` |
| `str` / `String` | `String` | PyO3 自动转换 `str` |
| `bool` | `bool` | PyO3 自动转换 `bool` |
| `None` / `void` | `()` | 无返回值 |
| `List` / `Vec` | `Vec<PyObject>` | 泛型容器 |
| `Dict` / `HashMap` | `PyObject` | 映射容器 |
| `Any` / `object` | `PyObject` | 任意对象 |
| 自定义类型 | 原名 | 由同文件 `#[pyclass]` 定义 |

映射函数：`PyO3Bridge::lz_to_rust` / `map_to_pyo3_type`（src/bridge/python.rs）。

## 4. 与 Cy 后端对齐基准（供 Cy Agent 参考）

Cy(Cython) 后端实现时必须保持以下结构与 PyO3 设计一致：

| 结构维度 | PyO3 设计（本文档） | Cy 对齐要求 |
|---|---|---|
| 模块入口 | `#[pymodule] fn <mod>_py` 唯一导出点 | 等价单一模块入口，命名 `<mod>_py` 一致 |
| 函数导出 | `#[pyfunction] pub fn <name>(...)` | 等价 `def <name>(...)` 导出 |
| 类型导出 | `#[pyclass] + #[pymethods] #[new]` | 等价 cdef class 构造器 |
| 类型映射 | §3 映射表（int→i64 等） | 同一 lz 类型映射为等价 Python/Cython 类型 |
| 参数来源 | TOML 清单 `[functions].args` | 同一清单驱动 |
| 注册顺序 | 函数/类型按清单顺序注册 | 保持顺序一致 |

- E2E（D4 后续）：`@export(Python)` 产物 → `cargo build --features py-bridge` → Python `import` 运行验证。
