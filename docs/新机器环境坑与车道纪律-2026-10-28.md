## 六、多车道并发规则（血的教训）

1. **每个车道独立 target**：`CARGO_TARGET_DIR=target/lane-<名字>`。
   共用一个 `target/debug` 会撞 `failed to remove target/debug/lang-zone.exe`（Windows 文件锁），
   那不是编译错误，会误导排查。
2. **不要用 `target/debug/lang-zone.exe` 跑长任务**，它会被下一次 build 替换。
3. **`--emit=rs-lz` 的 stdout 是生成的目标程序 Rust 源码**；重定向时**不要**用 CLI 自己会写的同名 `.rs`
   路径（`foo.lz` → `foo.rs`），否则会撞出垃圾文件并误判"产物编不过"。
4. **rs-lz 产物里的 `List<T>` 是合法的**：`lz_builtins/src/flat.rs` 有 `pub type List<T> = Vec<T>`，
   产物都 `use lz_builtins::*;`。不要因为看到 `List<i64>` 就判"没映射到 Vec"。
5. **台账 sha 不可信**：迁移后大量短号在本仓库不存在，复核前先 `git cat-file -t <sha>`。

> 生成物的归属与处置细则见**第九节**（2026-10-29 事故复盘）：脏了的生成物只上报，不还原。

### 9.1 生成物清单：谁生成、git 怎么看待它

先明确「哪些东西不是人写的」。下表为本仓库实测（`git check-ignore -v` + `git ls-files --error-unmatch`）：

| 生成物 | 生成者 | git 状态（实测） | 归属 |
|---|---|---|---|
| `tests/syntax-matrix-report.md` | `div-tools/syntax_matrix.ps1` | **已跟踪、未被忽略** → 一改就在 `git status` 里显示 ` M` | 跑 matrix 的车道 |
| `Reports/*.md` | 各车道自己写的轮次报告 | **被忽略**：`.gitignore:99 reports/`（Windows 大小写不敏感，小写规则命中大写 `Reports/`）；另有 5 个历史文件仍被 git 跟踪 | 写它的车道 |
| `temp/**` | 各车道草稿、证据、一次性脚本 | **被忽略**：`.gitignore:98 temp/`（另有 `TEMP/` 兜大写） | 创建者 |
| `build/**` | embed 编译产物（`src/embed/artifact.rs`：`EMBED_ROOT = "build/embed"`） | **未被忽略**，且当前工作树里没有该目录 → 一旦生成就以 `??` 出现在 `git status` | 跑 embed 的车道 |
| `build/embed/**` | 同上，形如 `build/embed/<主干>/<产物名>` | 同上（未被忽略） | 同上 |
| `foo.lz` → `foo.rs` 同名产物 | `--emit=rs-lz` / 探针脚本（实例：`div-tools/probe_release.lz` + `probe_release.rs`） | **被掩盖**：`.gitignore:6 *.rs`，只对 `src/`、`tests/`、`lz_builtins/`、`lz-infer/`、`std/`、`DEMO/99_spec/moddec/golden/` 放行 → `git status` 根本看不见它 | 生成它的车道 |
| `.fist-mbt/**` | fist-mbt 任务库 | **被忽略**：`.gitignore:214 .fist-mbt/` | 谁跑 fistctl 谁负责，一般不要手删 |

两条最容易误判的：

1. **`git check-ignore` 要对文件问，不要对目录问。** `git check-ignore -v Reports` 返回「未忽略」，
   但 `git check-ignore -v Reports/20260918.14.30.00.md` 返回 `.gitignore:99:reports/` —— 目录那条路不匹配，
   文件那条路因大小写不敏感命中了。**问错对象会得出相反结论。**
2. **看不见 ≠ 没生成。** `*.rs` 产物和 `temp/`、`Reports/`、`.fist-mbt/` 都不出现在 `git status` 里，
   它们照样在磁盘上被别人写。判断「这文件刚被谁写过」看 mtime，不要看 `git status`。

复跑核对命令：

```bash
# 某个路径到底谁管（对文件问，不对目录问）
git check-ignore -v tests/syntax-matrix-report.md
git check-ignore -v div-tools/probe_release.rs
# 是否已入库（已跟踪文件的变更一定可见，且没有任何副本可捞）
git ls-files --error-unmatch tests/syntax-matrix-report.md && echo TRACKED
# 工作树里现在是脏的生成物
git status --porcelain
git status --porcelain -uall | grep -E 'syntax-matrix-report|\.rs$'
```

### 9.2 归属规则（核心，五条）

1. **生成物只由生成它的那个车道提交 / 还原 / 删除。** 别的车道一律只读。
   「生成它的车道」= 本轮任务描述里被指派去跑那个脚本的车道；没指派过，就没人有权动它。
2. **别的车道发现生成物是脏的 → 上报，不动手。** 合法动作只有两个：
   ①在本轮汇报里点名（路径 + mtime + `git status` 原样那一行）；
   ②说明自己的文件白名单，证明不是自己写的。**不许**执行下面任何一条
   （除非该路径就在本轮白名单里）：

   ```bash
   # 车道 B 一律不许（除白名单内）
   git checkout -- tests/syntax-matrix-report.md
   git restore tests/syntax-matrix-report.md
   git clean -fd
   rm -f build/embed/**        # 或 del / rd
   ```

3. **派单时必须写文件白名单，生成物要显式归属。** 白名单之外的文件，本车道既不许改，
   也不许「顺手还原成干净」。白名单模板：

   ```text
   ## 文件白名单（车道 B / T0r42）
   可写：
     - docs/新机器环境坑与车道纪律-2026-10-28.md
   只读（可看可跑，不许 checkout / restore / 删除）：
     - tests/syntax-matrix-report.md   ← 生成物，归属「matrix 车道」
     - Reports/*.md                    ← 各车道自己的轮次报告
     - build/**、build/embed/**        ← embed 产物，归属「embed 车道」
   不碰：
     - temp/**（除自己的 temp/<前缀>_*）
   ```

4. **要「恢复干净」只有一条合法路径：让归属车道重跑生成脚本，而不是还原文件。**
   还原是回到旧值，重生成才是刷新到当前真值 —— 这两件事在生成物上不等价。
5. **生成物被误删 / 误还原后，先补生成再谈其它。** 不要为了「让 status 干净」把半成品
   `git add` 进去，也不要替别人的生成物 commit。

### 9.3 判定「这个文件是不是生成物」：四个办法

按顺序问，任一命中即可判为生成物：

| # | 办法 | 具体动作 | 本次实例的答案 |
|---|---|---|---|
| 1 | 看文件头 | `head -8 <file>`，找 `generated by` / `本报告由脚本生成` / `勿手改` | 命中：报告第 6 行「测试脚本：div-tools\syntax_matrix.ps1（判据 v2，本报告由脚本生成，勿手改）」 |
| 2 | 找生成者 | `grep -rn "<文件名>" scripts/ div-tools/ tests/ src/` | 命中：`div-tools/syntax_matrix.ps1` 里写着 `tests\syntax-matrix-report.md` |
| 3 | 查 `.gitignore` | `git check-ignore -v <file>`（**对文件问**） | 报告本身未命中；`*.rs`、`temp/`、`Reports/`、`.fist-mbt/` 命中 |
| 4 | 对 mtime | `ls -l --time-style=full-iso <file>`，与「某个脚本最近一次运行时间」比对 | 命中：报告 19:46:58，脚本 19:43，同一轮运行 |

四招**全都不命中**时，默认把它当手写源文件 —— 默认不动，这比误删便宜得多。
第 3 招的两个坑要记住：`*.rs` 会把 `foo.lz` 的产物整类掩盖；`reports/` 会因大小写不敏感连带掩盖
`Reports/`。**若文件压根不出现在 `git status` 里，第 4 招（mtime）是唯一还管用的。**

复跑命令块：

```bash
head -8 tests/syntax-matrix-report.md
grep -rn "syntax-matrix-report" scripts/ div-tools/ tests/ src/ 2>/dev/null | head
git check-ignore -v tests/syntax-matrix-report.md div-tools/probe_release.rs
ls -l --time-style=full-iso tests/syntax-matrix-report.md div-tools/syntax_matrix.ps1
```

### 9.5 与既有纪律的交叉引用

本节不是新体系，是第六节那套隔离纪律在「生成物」上的补齐：

| 既有纪律 | 位置 | 与生成物的关系 |
|---|---|---|
| 每车道独立 `CARGO_TARGET_DIR=target/lane-<名字>` | 第六节第 1 条 | `target/**` 已被 `.gitignore:180 **/target/` 覆盖 → 构建产物天然不进 `git status`，**不需要**归属规则；反过来，正因为看不见，**更不许 `git clean -fd`**（会把别人的 target 一起清掉） |
| `tests/common/mod.rs` 的 `unique_dir`（`{prefix}-{pid}-{nanos}-{seq}`） | `tests/common/mod.rs:114` | 测试临时目录按 pid + 纳秒 + 原子计数唯一 → 两条车道并发跑同一用例也不撞 → **测试产物不需要归属**；会撞的是仓库级生成物（报告、`build/embed/`） |
| 串行跑重测试 | 第六节 | 重测试（cargo test 全量、matrix）会重写仓库级生成物 → 必须串行，且**同一条重测试归属同一个车道**，否则又回到 9.2 第 1 条 |
| `reserve_scope` 对非 Fist-Mbt 项目 fail-closed（BUG-488） | 第五节 | 隔离只能靠**显式文件白名单**，不靠锁；白名单是本节全部规则的载体 |
| 「不要动别人的改动」 | 第五节末 | **本节给它补了边界**：别人的**改动**不动，别人的**生成物**更不动 —— 连「还原成干净」也算动 |

```text
看到 git status 里有你不认识的文件
  ├─ git check-ignore -v <file>            # 是生成物吗（对文件问，别对目录问）
  ├─ head -8 <file>                        # 文件头有没有「本报告由脚本生成」
  ├─ grep -rn "<文件名>" div-tools/ scripts/ tests/
  └─ ls -l --time-style=full-iso <file>    # mtime 像不像某次脚本运行
命中任一 → 生成物 → 不 checkout / 不 restore / 不 rm / 不 clean
         → 汇报里点名 + 说明自己的白名单 → 让归属车道重跑脚本
全不命中 → 当手写源文件 → 默认不动，问指挥官
```
