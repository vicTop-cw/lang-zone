## 1. 定位方法（四种手段，按可靠性排序，全部可复算）

所有命令都在 `F:/AI/lang-zone` 下只读执行。

### 手段 G —— `git log --grep='BUG-<号>'`（最强）

本仓库 commit subject 习惯带缺陷号：642 笔里有 **71 笔** subject 直接写 `BUG-4xx`，且常写成
`BUG-442/443/444/445` 这种**斜杠列表**。

```bash
git log --oneline --grep='BUG-469'
git log -1 --format='%H %h %ad %s' --date=iso-strict --grep='BUG-469'
```

- **必须把斜杠列表展开**，否则「一笔四修」会被误判成「只修了第一个号」。
- 判定力：subject 显式含该号 **且** 是 `fix(...)` 类提交 → 置信度 **高**；
  只有 `docs(bugs)` / `test:` 类提交提到该号 → 真实 fix 在它前面，需手段 D 补 → **中**。

### 手段 T —— `git log -S'<代码特征串>'`（次强，用于 subject 不带号的提交）

```bash
git log --oneline -S'gen_recv_place'               -- src/ir/lz_codegen_lib.lz
git log --oneline -S'default: None'                -- tests/cython_backend.rs
git log --oneline -S'variants_with_field.sort_by'  -- src/ir/codegen/expr_gen.rs
git log --oneline -S'force_ref'                    -- src/ir/lz_codegen_lib.lz
```

特征串的选法：**从台账「修复」段抄那个新引入的标识符**（函数名 / 字段名 / 魔法方法名 / 测试名）。
台账写得越细，这一手段越准。例：BUG-458 台账写「target 由 `gen_expr` 改为 `gen_recv_place`」
→ `-S'gen_recv_place'` 一步落到 `1185260`。

### 1.5 展开脚本（本次实际使用）

```python
import subprocess, re, collections
log = subprocess.run(['git','log','--format=%H\t%h\t%ad\t%s','--date=iso-strict'],
                     capture_output=True, text=True, encoding='utf-8').stdout
commits = [dict(zip(('full','h','date','subj'), ln.split('\t',3)))
           for ln in log.splitlines() if ln.strip()]
bybug = collections.defaultdict(list)
for c in commits:
    # 关键：把 BUG-451/452/453 这类斜杠列表展开成三个号
    for m in re.finditer(r'BUG-(\d+(?:\s*[/、,]\s*\d+)*)', c['subj']):
        for n in re.findall(r'\d+', m.group(1)):
            bybug[int(n)].append(c['h'])
```
