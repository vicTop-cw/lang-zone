# 主编译器融入子编译器计划（lzc → lzcyc）

> 日期：2026-09-17
> 目标：以 lzcyc（CY/ 子编译器）为主干吸收主编译器能力，最终形成单一编译器；
> Cython 后端为主线产出，Rust 后端保留为自举与原生验证通道。
> 约束前提：融入期间 `lzc` 行为零破坏——任何阶段完成后，主编译器现有验证
> （cargo test 全绿、DEMO 261/261、自举三代收敛、closed 闭环 13/13）必须保持。

### 1.2 已知债（融入时统一回收）

1. 后处理兜底的 7 项形态缺口——根因在 lib codegen 生成形态，兜底逻辑在 lzcyc
2. semantic_check 作用域语义——`let` 块级 vs 无 let 函数级的双轨制（test_control 笔误暴露）
3. import 解析——主编译器单文件模式不支持跨目录（lzcyc 已实现 merge_imports）
4. infer feature 保护不全——lib 3 处无条件 serde_json 引用，lzcyc 被迫带依赖
5. 并发降级——`go/spawn` 生成同步求值，lz_concurrency 运行时未接线

## 二、融入原则

1. **主干反转，而非搬家**：最终态是"lzcyc 为主干（吸收 lzc 能力）"，不是把 CY/ 搬进 src/
2. **零破坏推进**：每阶段出口都有可执行验收；主编译器验证套件全程红灯数不增
3. **先下沉后融合**：lzcyc 侧验证过的修复先下沉到 lib，再考虑入口合并——避免两套实现漂移
4. **回归即锚**：`CY/testsrc/cli.rs`（54/54）与主编译器测试套件是每阶段的安全网，任何一步变红即停

### M1 — 兜底下沉（后处理 → lib codegen）✅ 主体完成（2026-09-18）

**目标**：7 项后处理修复改为 lib 生成正确形态，lzcyc 后处理退位为空转兼容层。

| 序 | 项 | 下沉动作 | 状态 |
|---|---|---|---|
| 1 | `_variant` 注入 | `gen_enum` 类体首行直出 `_variant = N`（带数据/无数据变体均覆盖） | ✅ M1.1（b5eec92） |
| 2 | Box/Rc/Arc 下标 | prelude 三包装类直出 `__getitem__`/`__setitem__` | ✅ M1.2（2116beb） |
| 3 | Option/None 垫片 | 方法族特判生成：is_none→`(x is None)`、is_some→`(x is not None)`、unwrap 透传、expect→`__lz_expect_fail` 守卫；对齐裸 None 哨兵模型，垫片退位 | ✅ M1.3（2b472ba） |
| 4 | 构建块下标 | `UnpackBuildCall` 生成 `(packed)[N]` 下标（对齐 Rust 端语义），索引裸整数提取 | ✅ M1.4（0eff34d） |
| 5 | filter 谓词 | comp! 宏族 filter 为 lambda 时直出 `(__cv)` 调用 | ✅ M1.5（2910a27 + 9679488 退位） |
| 6 | checker 派发 | Call 识别 `fn[checker]` → `__lz_checked_*` 包装器；`fn_params` 形参表 + `checker_wrappers`（RefCell）generate 收尾统一追加 `__Params` 垫片 | ✅ M1.6（082820b） |
| 7 | import 前缀 | 与 M2.2 import 解析下沉合并处理 | ⏳ 待 M2.2 |

**执行方式**：逐项小步提交；每项下沉后 lzcyc 后处理对应分支保持（双保险），连续两轮全绿后移除该分支。
**验收**：`CY` cargo test 全绿（54/54）+ 主编译器 cython_backend 34/34 全绿。
**回滚**：单项 revert 即可（各修复互相独立）。
**⚠ 遗留整合项**：M1 在本地扩展线（codegen_cython 3288 行版）上完成；origin/master 为精简线
（1594 行，含部分同类修复雏形），两线需按 M2/M3 整合时统一裁决——ir_pass_fixes 2 个失败
（E0308/E0277）为本地旧线 Rust 端既有问题，与 M1 下沉无关。

### M2 — 前端能力下沉与修复

| 序 | 项 | 动作 |
|---|---|---|
| 2.1 | 作用域语义裁定 | 明确 LZ 双轨规则并文档化：`let` = 块级不可变绑定（Rust 式）；无 let 赋值 = 函数级局部（Python 式）。semantic_check 若有与规则不符处修复（test_control 已按此修正样例） |
| 2.2 | import 解析下沉 | lzcyc `merge_imports`（源目录 + std-dir 候选、递归防环、items 扁平合并）下沉为 lib 公开函数，主编译器单文件模式接入——解决 `import lz_std` 类跨目录解析 |

**验收**：主编译器 + lzcyc 双侧测试全绿；`SYNTAX/02-变量与绑定.md` 补作用域章节。

### M3 — 入口融合（CLI 合并）

**目标**：`lang-zone.exe` 与 `lzcyc.exe` 统一。

**策略（推荐）**：lzcyc 为主干仓库目标形态——
1. `lang-zone` crate 继续承载 lib（lexer/parser/ir/codegen 双后端）
2. `CY/` 升级为 bin crate：`lzcyc` 子命令吸收 `lzc` 的 create/build/peek/check/push 全部子命令；`--backend` 默认 cython，rust 为可选
3. 自举/发布脚本（`bootstrap/build.ps1` 等）切换指向新入口，旧 `lzc.exe` 保留一个版本的兼容 shim（转发调用），下版移除

**验收**：`div-tools/cli_regression.ps1` 全通过；两个入口行为等价性抽查（同输入同产物）。

### M4 — 依赖收敛

1. 修复 lib 3 处无条件 `serde_json` 引用（补 `#[cfg(feature = "infer")]`）
2. lzcyc 依赖改 `default-features = false`，回归"零外部依赖"
3. 验收：CY `cargo tree` 无 serde 系；双侧测试全绿

### M5 — LZ 自举组件接入 lzcyc

1. `lz_lexer.lz`/`lz_parser.lz` 编译为 .pyd 接入 lzcyc 前端（对齐 BOOTSTRAP_PLAN P1–P3 产物）
2. 前端双轨并行期：Rust 前端为默认，LZ 前端 flag 切换；一致性对比（同输入 token/AST diff 为空）
3. `lz_codegen_lib.lz`（Rust codegen 的 LZ 版）为 Rust 后端自举通道保留

**验收**：LZ 前端 + Rust 前端对 DEMO 全量产物一致；三代自举收敛在新入口下复现。

### M6 — 环境解锁后的验收闭环（依赖外部条件）

前置：可用 Python（cython 可装）+ C 编译器（GCC/MSVC）。

1. cythonize → .pyd 端到端（`lzcyc compile/run` 全链路）
2. 运行层铁律：.pyd 运行输出 vs Rust 后端运行输出自动对比（BENCH/fib 起步）
3. 性能基准：标量提升（I10）前后对比；cy 后端 vs 纯 Python vs Rust
4. 并发真实现：lz_concurrency 接线（I4），`go/spawn` 不再降级
5. e2e 用例扩到 100+（I12，`TESTS/999_e2e/`）
