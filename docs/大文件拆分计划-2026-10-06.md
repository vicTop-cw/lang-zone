# 全仓大文件拆分计划（v1 · 2026-10-06）

> **原则**：纯结构移动（move-only refactor），不改任何逻辑、不改行为；每个文件拆分独立成段、独立可验证（`cargo build` + 全量测试），可分多个小阶段执行。
> **前置纪律**：每个文件拆分开始前，先 `git commit + push` 同步当前工作区（当前有 184 个未提交改动，必须先落盘）；拆分完成后再次提交同步。
> **验证铁律**（项目 memory）：生成的 `.rs` 必须过 `rustc` 且运行正确；拆分后跑全量 DEMO 回归（`DEMO/` golden + `tests/`）确认零回归。
> **范围**：只拆 Rust 源码大文件。Cython 后端（`lzcyc`、`src/ir/codegen_cython.rs`、`src/codegen/`、`CY/`）按项目铁律**不管不碰**——本文档列出它仅作完整性记录，**不排期**。

## 九、风险与对策

| 风险 | 对策 |
|------|------|
| 可见性错误（private fn 跨模块不可见） | 拆分时统一 `pub(crate)`，`cargo build` 立刻暴露；不放宽到 `pub` |
| `use` 语句遗漏/循环依赖 | 子模块间只允许 `use super::*` 或显式路径，禁止子模块互相 use 形成环；codegen 子模块之间通过 mod.rs 转发 |
