# M6 风险预案：`.pyd` / Cython 段（2026-11-18）

## 1. 现状与阻塞

| 项 | 状态 | 说明 |
|---|---|---|
| LZ → `.pyx` 产物生成 | 可用 | `lzcyc transpile <f.lz>`（默认 cython 后端）本机可跑 |
| `.pyx` → `.c` → `.pyd` | **阻塞** | 依赖 `cython` 包；本机 Loomy 内置 Python 的 pip 已损坏且不可修复（见环境记录），无法安装 |
| Rust 后端闭环 | 可用 | `lzcyc compile <f.lz> --backend=rust`；M5 三代自举收敛已证 |

结论：**产物生成与行为语义可在本机验证；二进制落地（`.pyd`）需在具备 cython 的环境执行**。

## 2. 缓解策略（按优先级）

### S1 递归管线等价验证（本机默认路径）
- 用 `--backend=rust` 的递归管线验证语义：LZ 源 → Rust → 运行输出。
- 判据：M5 双轨门禁（328/328）+ 三代自举收敛（12 源 × 3 代 manifest 一致）。
- 覆盖：语言语义、IR/代码生成、运行行为。
- 缺口：不覆盖 cython 特有的运行时桥（`.pyx` 的 import/类型标注形态）。

### S2 `.pyx` 产物字节级比对（本机可跑）
- 冻结 `CY/TESTS/**/*.pyx` 作为 golden（已入库）。
- 门禁：`lzcyc transpile` 产物与 golden 逐字节一致（`Get-FileHash` 比对）。
- 价值：cython 前端改动（模板/类型导出/注解剥离）一旦漂移立刻红。

### S3 外部环境落地（CI / 具备 cython 的机器）
- 目标环境最低要求：Python 3.10+、`pip install cython setuptools`、本机 C 编译器（MSVC 或 gcc）。
- 步骤：`python -m cythonize -i CY/TESTS/01_basics/comments.pyx` → 生成 `.pyd` → 运行 smoke。
- 建议：作为 CI 的 `workflow_dispatch` 手动任务，避免每次 push 拉起重依赖。

## 3. 验收口径（M6 建议）

1. **语义层**：`--backend=rust` 递归管线全绿（M5 门禁复用）。
2. **产物层**：`.pyx` 与 golden 逐字节一致（S2 门禁纳入 CI 快线）。
3. **落地层**：在 S3 环境跑通 3 个代表样本的 `.pyd` 构建与运行（输出与递归管线一致）。
4. **文档层**：`CY/BACKLOG.md` 与本文更新为最终状态。

## 4. 风险表

| 风险 | 影响 | 缓解 |
|---|---|---|
| 无 cython 导致 `.pyd` 不可验 | 交付缺口 | 三层验收：语义（本机）+ 产物（本机）+ 落地（外部） |
| cython 版本差异致 `.c` 形态漂移 | golden 误红 | golden 只冻结 `.pyx`，不冻结 `.c` |
| 外部环境不可用 | 落地层长期挂起 | 明确标记为 M6 外部依赖项，不阻塞 M5/M7 主线 |
| `--backend=cython` 与 rust 行为分叉 | 双后端不一致 | 共用同一前置管线（词法/语法/IR），仅后端发射不同 |
