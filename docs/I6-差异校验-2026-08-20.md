# I6 差异校验报告（Rust codegen 产物 vs 绑定输出）

> 版本：v164（e08e9ef）｜ 日期：2026-08-20 ｜ 依据：docs/补缺计划-2026-08-19.md I6 项

## 一、校验方法

同一 .lz 源分别走两条输出路径，比对**生成代码结构**与**行为输出**是否一致：

- **路径A · Rust codegen 产物**：`lang-zone <src.lz>` 单文件模式 → `<src>.rs`（IR codegen）→ `rustc --edition 2021 --extern lz_builtins` → 运行 exe，记录 stdout。
- **路径B · 绑定输出路径**：
  1. `lang-zone build <proj>`（lz.toml 项目模式）→ `build/<name>.rs` + `Bridge registry: N symbol(s)` + `build/bridge-ledger.tsv`（append-only 台账，G5）；
  2. `@export(Python)` 绑定结构基准：docs/py-bridge-struct.md（PyO3Bridge::generate_module 四段式 pyclass/pyfunction/pymodule，函数体占位 `todo!("Implement __py_<fn>")`，rust_path=`__py_<fn>`）。

比对维度：① 结构一致性（.rs 中 pub fn 与 registry/ledger 登记符号一一对应）；② 行为一致性（运行输出与源码语义一致）；③ 绑定映射（export 签名按 py-bridge-struct.md 类型映射表可对齐）。

## 三、发现的差异项

1. **无 codegen 结构差异**：`register_symbol` 不注入 .rs 产物文本，registry 由 `generate_with_bridge` 返回值 → ledger TSV 落盘（cli.rs:435-437）。两路径生成代码结构一致（同源同构）。
2. **`@export` 产物差异（预期行为，非缺陷）**：`export_demo.rs` 中无 pyo3 绑定代码；`@export(Python)` 的绑定源由 `src/bridge/python.rs::PyO3Bridge::generate_module` 在启用 `py-bridge` feature 时独立生成（四段式，见 py-bridge-struct.md），与 IR codegen 产物解耦。这与文档基准一致。
3. **单文件模式对多模块项目不支持（非本次回归）**：DEMO/08_modules/services.lz 单文件编译失败（模块依赖），属既有限制；使用项目模式（lz.toml + entry）可编译。IR→rustc 通过率重测中已按单文件口径归类。
