## 一、目标与背景

### 1.1 目标

在 LZ 源码里用 `#[embed(tnr)]` / `@tnr!` 嵌入 **Tnr 原样源码**，编译期由 `tnr` crate �4转译为 Rust 模块，LZ 直接 `use` 该模块 API。LZ 复用 Tnr 的：

- 张量算子：`×`（矩阵乘）、`*`（哈达玛积）、`⊗`（克罗内克积）、`⊕`（直和）、`∑`（归约）、`∂`（偏导）、`∫`（积分）、`lim`（极限）
- 惰性 DAG 求值（段 = 建图单元，行动点 = materialize）
- 多后端：BLAS / Burn(GPU) / ndarray(CPU) / TVM(NPU)
- 符号公式系统（`symbol` / `simplify` / `@` 代入）
- comptime 编译期特化

### 1.2 背景：现有 embed 实现

LZ 已有 `#[embed(rust)]` / `#[embed(py)]`（G7，2026-08-19 落地），但语义是**提取函数体首个字符串字面量**（`extract_embed_code`，`src/ir/builder.rs:10031`），即"返回字符串"形式，**非原样嵌入**。

| 现有实现 | 位置 | 语义 |
|---|---|---|
| `extract_embed_code` | `builder.rs:10031` | 从 `Stmt::Return`/`Stmt::ExprStmt` 提取 `Lit(Str)`，穿透 `ImplicitConvert` |
| builder `embed` 分支 | `builder.rs:9852` | `lang=args[0]`, `code=extract_embed_code(body)` → `IntrinsicKind::Embed{lang,code}` |
| codegen `Embed` | `codegen/mod.rs:3946` | `code.lines()` 逐行 `emit_line` 原样插入 + `register_symbol` |
| Cython 后端 | `codegen_cython.rs:548` | 同步处理 |
| 测试 | `tests/bridge_embed.rs:96` | `#[embed(rust)] def hello_embed() -> int: return "println!(...); 42"` |
| 用例 | `DEMO/embed_demo.lz` | 唯一 demo，生产代码零用例 |

**本计划重定义 embed 语义为原样静态嵌入**，现有字符串形式保留兼容（后续迁移 `@rust!`/`@py!`）。

### 1.3 Tnr 现状（被嵌入方）

| 维度 | 现状 |
|---|---|
| `Tensor` | `pub struct Tensor { dtype, shape, data, device, str_view }`（`tnr/src/tensor/mod.rs:72`，`#[derive(Debug, Clone)]`，字段全 pub） |
| lib API | `tnr::frontend::parser::parse` / `tnr::ir::lower_program_to_lir_ast` / `tnr::codegen::lirgen::transpile_lir` / `tnr::interp::run_program` / `tnr::tensor::ops::*` |
| 编译流水线 | HIR → MIR → LIR → Rust（`lower.rs` + `pass.rs` + `lirgen.rs`） |
| 缩进块 | 支持（`SYNTAX/05` §1.4：块头不含 `{` 时缩进定界），与 LZ 缩进风格一致 |
| 语法 | `fn`/`let`/`mut`/`if`/`while`/`for`/`repeat`/`match`/`spawn`/`sync`/`symbol`/`comptime`；数学符号 `× ∑ ∂ ∫ ⊗ ⊕ ∞ ε δ π 𝕖 𝕚`；注解 `with float64 on gpu(0)`；管道 `\|>`；唯一类型 Tensor（免类型注解） |

## 二、语义定义

### 2.1 两种嵌入机制

| 机制 | 语义 | 插值 | 形式 |
|---|---|---|---|
| `#[embed(lang)]` + **缩进块** | **原样静态嵌入**（编译期文本块原封不动，不解析、不插值） | **禁止** `${var}` / `$(var)` | 缩进式语言（tnr/py/scala 缩进式） |
| `@lang!` + **缩进块** | 原样静态嵌入 | 禁止 | 同上，宏形式 |
| `@lang!` + `r```···``` ` | 原样静态嵌入 | 禁止（原始模式） | 花括号式语言（rust/c/tnr 花括号式） |
| `@lang!` + `f```···``` ` | **动态生成式嵌入** | **支持** `$(var)` / `{var}` | 需动态拼接时 |
| 现有 `#[embed(rust)]`/`#[embed(py)]` 字符串形式 | 保留兼容，后续迁移 `@rust!`/`@py!` | — | 不 breaking |

### 2.2 核心规则

1. **签名随被嵌入语言**：`#[embed(tnr)]` 后是 Tnr 的 `fn`（非 LZ 的 `def`）；`#[embed(scala)]` 后是 Scala 的 `object`/`def`；`#[embed(py)]` 后是 Python 的 `class`/`def`。整个签名行 + 缩进块体一体，作为目标语言原样源码，LZ 不解析。
2. **缩进式原样禁止插值**：`#[embed(lang)]` + 缩进块内不得出现 `${var}` / `$(var)`，必须全部展开原样。
3. **`f``` ` 形式支持动态**：`@lang! f```...$(var)...``` ` 允许插值，插值变量求值后拼入目标语言源码。
4. **comptime 结合宏是生成式出口**：`comptime:` 块内可计算文本，再经 `@lang! f``` ` 插值实现生成式嵌入。
5. **块内注释遵循目标语言**：py 的 `#`、tnr/rust 的 `//`；块外 `//` 是 LZ 注释。

### 2.3 禁止形式

```lz
// ❌ 禁止：embed 缩进块内插值
let py_add = "return a + b"
#[embed(py)]
def add(a, b):
    ${py_add}
```

```lz
// ✅ 合法：f``` 插值在语言宏里（动态生成式）
let extra = "let D = C × W"
@tnr!
f```
fn kernel(A, B)
    let C = A × B
    $(extra)
    relu(D)
```
```

## 三、语法设计

### 3.1 形式 A — 缩进式原样静态嵌入（tnr/py/scala 等缩进式语言）

```lz
// Tnr：签名用 tnr 的 fn，免类型注解（tnr 只有张量），整块一体
#[embed(tnr)]
fn add(a, b)
    a + b                      // tnr 尾表达式即返回值

#[embed(tnr)]
fn matmul_relu(A, B)
    let C = A × B              // tnr 矩阵乘（× 是 U+00D7）
    let D = relu(C)            // tnr 内置算子
    D

// Python：签名用 py 的 class/def
#[embed(py)]
class Demo:
    def func(self, a, b):
        return a + b

// Scala：签名用 scala 的 object/def
#[embed(scala)]
object Demo:
    def func(a: Int, b: Int): Int = a + b
```

### 3.2 形式 B — 反引号块原样静态嵌入（rust/c/tnr 花括号式）

```lz
// Rust 花括号式，用 r``` 原始模式
@rust!
r```
fn fast_add(a: i64, b: i64) -> i64 { a + b }
```

// Tnr 花括号式
@tnr!
r```
fn add(a, b) { a + b }
```
```

### 3.3 形式 C — 动态生成式嵌入（`f``` ` 插值）

```lz
// f``` 支持 $(var) 插值，动态生成 tnr 源码
let bias = "0.1"
let activation = "relu"
@tnr!
f```
fn dense(A, W)
    let C = A × W + $(bias)
    $(activation)(C)
```
```

### 3.4 形式 D — `@lang!` 语言宏套缩进块（等价 `#[embed(lang)]`）

```lz
// @tnr! + 缩进块 = 原样静态，等价 #[embed(tnr)]
@tnr!
fn softmax(x)
    let e_x = exp(x)
    e_x / ∑ e_x
```

## 四、产物机制

### 4.1 同名文件聚合

LZ 文件 `foo.lz` 内**同一种语言**的多个 embed 块 → 收集到**同名** `foo.<lang>` 文件 → 编译为 Rust 模块 → LZ `use` 该模块 API。

```
foo.lz
  #[embed(tnr)] fn add(...) ...      ─┐
  #[embed(tnr)] fn matmul(...) ...    ├─→ foo.tnr（合并所有 tnr 块，按出现顺序）
  @tnr! f```fn relu(...) ...```      ─┘
                                       ↓ tnr 编译器（tnr::parse → lower → transpile_lir）
                                   foo_tnr.rs（Rust 模块）
                                       ↓ LZ codegen
                                   #[path = "foo_tnr.rs"] mod foo_tnr;
                                   use foo_tnr::{add, matmul, relu};
```

其它语言同理：

| lang | 产物文件 | 处理 |
|---|---|---|
| `tnr` | `foo.tnr` → `foo_tnr.rs` | tnr lib 转译为 Rust 模块 |
| `rust` | `foo_embed.rs` | 直接合并到 codegen 产物（`include!` 或 `mod`） |
| `py` | `foo.py` | 桥接模块（PyO3 / subprocess） |
| `scala` | `foo.scala` | 桥接模块（JVM） |
| `c` | `foo.c` → `foo_c.rs` (FFI) | cdylib + `extern "C"` |

### 4.2 多目录冲突处理

`--project` 模式按源文件相对路径生成：`a/foo.lz` → `a/foo_tnr.rs`，`b/foo.lz` → `b/foo_tnr.rs`，路径前缀区分。

###%### 4.3 模块命名

- `foo.lz` 的 tnr embed → 模块名 `foo_tnr`
- LZ codegen 生成 `#[path = "foo_tnr.rs"] mod foo_tnr;` + `use foo_tnr::*;`
- 函数名冲突：LZ 侧同名函数 → 编译错误!错误（embed 函数名占用 LZ 命名空间）

## 五、Tensor 类型复用

### 5.1 Tnr Tensor 定义

```rust
// tnr/src/tensor/mod.rs:72
#[derive(Debug, Clone)]
pub struct Tensor {
    pub dtype: Dtype,
    pub shape: Shape,
    pub data: Data,
    pub device: u8,
    pub str_view: bool,
}
```

### 5.2 LZ ,侧复用

- **直接 `use tnr::tensor::Tensor;`**（struct 对 struct，零 marshal）
- LZ `IrType` 用 `Named { path: "Tensor".into(), args: vec![] }` 表达（`src/ir/types.rs:31`，**不加新枚举变体**）
- codegen 类型映射表加 `Named("Tensor", [])` → `tnr::tensor::Tensor`
- `#[embed(tnr)]` 函数签名里的 `Tensor` 即 `tnr::tensor::Tensor`，L6传参/返回零拷贝

### 5.3 边界

| 场景 | 处理 |
|---|---|
| LZ 调 `#[embed(tnr)]` 函数 | LZ 侧 `Tensor` = `tnr::tensor::Tensor`，直接传引用，零 marshal |
| Tnr 内部计算 | 惰性 DAG，`sync`/`print` 触发 concretize |
| 返回 LZ | Tnr 尾表达式 → `tnr::Tensor` → LZ 直接持有 |

## 六、实现路径（5 阶段）

### P1：lexer 原样块捕获

**目标**：`#[embed(lang)]` 后切换原样捕获模式，产出 `Token::EmbedBlock`。

**改动**：
- `src/lexer/lexer.rs`：
  - 识别 `#[embed(lang)]`（现有 `#[...]` 归约 `@` 装饰器路径，`lexer.rs:1134`）后，切换原样捕获模式
  - 下一 token 判断形式：
    - 遇 `` ` `` → 反引号块（复用 `collect_backtick_block`，`macros/expand.rs:1821`）：`r``` `→`Raw`、`f``` `→`Interp`
    - 否则 → 缩进块：捕获签名行 + 缩进加深的所有行（直到缩进回退），**不产生 LZ token**
  - 产出 `Token::EmbedBlock { lang, src, form: Indent | Raw | Interp }`
- `src/ir/node.rs:291`：`IntrinsicKind::Embed { lang, code }` 注释更新（语义从字符串→原样块，结构不变）

**量级**：~80 行

### P2：builder 双路径 + 同名文件聚合

**目标**：`embed` 分支支持新原样块路径 + 旧字符串兼容；按语言分组写同名文件。

**改动**：
- `src/ir/builder.rs:9852`：`embed` 分支双路径：
  - 新路径：从 `Token::EmbedBlock` 取 `src`（原样块文本）
  - 兼容路径：旧 `def foo(): return "..."` → `extract_embed_code`（**保留，不删除**）
- 新增 `src/ir/embed_collector.rs`：`EmbedCollector` 按 `lang` 分组收集 `EmbedBlock`，同 LZ 源文件 `foo.lz` 的所有 `lang=tnr` 块 → 合并写入 `foo.tnr`（按出现顺序拼接）
- `src/ir/builder.rs:10002` 诊断同步

**量级**：~130 行（builder ~30 + embed_collector ~100）

### P3：tnr lib 转译 → Rust 模块

**目标**：`foo.tnr` 经 tnr lib 转译为 `foo_tnr.rs`，LZ codegen 生成 `use foo_tnr::*;`。

- `lang == "rust"` → 原样合并（已有路径，`code.lines()` + `emit_line`）
- `lang == "py"/"scala"/"c"` → 原样插入 + `bridge_registry` 登记（已有 `register_symbol`）
- `src/ir/codegen_cython.rs:548`：Cython 后端同步（tnr embed 在 Cython 后端禁用或降级为 Rust FFI）

**量级**：~60 行

### P4：`@lang!` 语言宏 + 兼容

**目标**：`@rust!`/`@py!`/`@tnr!`/`@scala!` 内置宏落地；`f``` `动态/`r``` `原样分流。

**改动**：

## 十、风险与依赖

| 风险 | 等级 | 缓解 |
|---|---|---|
| Tnr lib 编译依赖重（tnr-symbolica 等） | 中 | LZ 侧 feature gate `tnr-embed`，默认关 |
| Tnr 转译产物编译失败 | 中 | tnr 错误映射到 LZ span（行号偏移计算） |
| `@lang!` 内置宏与用户宏命名冲突 | 低 | 内置优先 + 保留名编译错误 |
| 同名文件聚合破坏 tnr 语法完整性 | 中 | 按 tnr 顶层项边界拼接（fn/symbol/import 各自完整） |
| LZ 自举试点期 | 低 | 计划一仅扩展 embed，不动核心管线 |

## 十一、与计划二的协同

```
LZ ──#[embed(tnr)]/@tnr!──> foo.tnr → Rust 模块 foo_tnr → use foo_tnr::*（数值计算）
Tnr ──import lz::/#[extern(lz)]──> lz_builtins crate → use lz_builtins::...（系统生态）
```

- 计划一让 LZ 写系统骨架 + 调 Tnr 算数值核
- 计划二让 Tnr 写数值算法 + 调 LZ 管 IO/数据结构/并发
- 与 Tnr `arch-plan/09` P4 互译闭环方向一致，本计划是互操作（非互译），是 P4 前置
