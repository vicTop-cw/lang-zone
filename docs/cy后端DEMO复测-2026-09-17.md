### 2.2 真实待修问题（1 个）— P2

**`DEMO/99_spec/combo-syntax/combo_while_guard_try.lz`**（正向规范测试，注释标明"✅ 已纳入 compile_demos 覆盖"）

- **现象**：`IR build error: Result 值未经解包（unwrap/?）直接参与运算`
- **触发代码**：
  ```lz
  def step() -> int raises E = ...
  def main() =
      try:
          while (n := step()) <= 3 if n % 2 == 1:   // 海象调用 raises 函数参与比较
  ```
- **根因**：`step()` 声明 `raises E`，调用点类型推断为 `Result<int, E>`；`src/ir/builder.rs:12650` 的二元运算检查（`AstExpr::Binary` 分支）发现任一侧为 `Result` 即报错，缺少两种豁免：
  1. **try 块内**的 raises 函数调用（当前就在 try 上下文中，Result 应自动解包或直接以异常语义放行）
  2. **海象 `:=` 绑定点**的自动 unwrap
- **影响面**：默认 Rust 后端下**同样失败** → 共享 IR 层问题，**与 cy 后端无关**
- **修复建议**：在 `builder.rs:12646` 的 Binary 检查处，对左侧海象表达式的 RHS 为 raises 调用且处于 try 块上下文时跳过 Result 检查；或统一约定 raises 调用在 try 内自动降级为解包值
- **优先级**：P2（影响 1 个正向规范测试转绿；不阻塞任何后端工作）
