# ΣLang / LZ 小型库复现 & Bug 修复计划

> **日期**：2026-08-24  
> **版本基线**：v178 (IR→rustc 94.93%, 329 tests/0 fail)  
> **目标**：通过复现 12 个小型库，系统性地发现 LZ 编译器（parse/IR/codegen/semantic）中的缺陷，修复后将 IR→rustc 通过率推至 ≥98%

---

## 1. 策略总览

### 1.1 为什么用"复现库"而不是"加测试用例"

| 维度 | 单测 | 复现库 |
|------|------|--------|
| 覆盖深度 | 一个语法点一个用例 | 多特性交叉，暴露组合 bug |
| 真实度 | 人为构造 | 模拟真实编码模式 |
| 回归价值 | 低（仅验证不回归回归） | 高（库代码本身即回归套） |
| 修复反馈 | 间接 | 直接——库能跑通则 bug 修好 |

### 1.2 选库原则

1. **纯 LZ 原语**：不依赖 `rust.std.*` 显式导入（`lz_builtins` 链接仍为题，但库本身应能独立编译）
2. **渐进复杂度**：从 20 行到 200+ 行，逐步加压
3. **特性正交**：每个库侧重 1-2 个特性交叉，避免一坏全坏无法定位
4. **可独立验证**：每个库有 `main()` + `assert` / 已知输出，编译运行即可判定

### 1.3 特性矩阵与库映射

特性代号：
- **S** struct / enum / 泛型 struct
- **T** trait / impl / duck
- **G** 泛型函数 / 约束 / where
- **C** 闭包 / 高阶函数 / lambda
- **M** match / 模式解构
- **E** 错误处理（raise/try/?）
- **D** 数据结构（List/Dict/Set/自定义容器）
- **A** 算法（递归/迭代/排序/搜索）
- **P** pipe / 链式调用
- **V** 变参 `..` / `/` `*`
- **B** build block / macro
- **X** 字符串处理 / 解析

| 库 | 行数 | 主特性 | 次要特性 | 预期 bug 类别 |
|------|------|--------|----------|---------------|
| L1 排序算法库 | ~80 | A, D, G | M, C | 泛型推断、闭包比较 |

## 2. 阶段划分

### 阶段 α：基础数据结构（L1-L4）— 预计 4 个小阶段

#### L1 排序算法库 (`lib_sort.lz`)

**目标文件**：`libs/lib_sort.lz` + `libs/probes/sort_probe.lz`

**功能**：
- `bubble_sort<T: Ordered>(list: List<T>) -> List<T>`
- `quick_sort<T: Ordered>(list: List<T>) -> List<T>`
- `merge_sort<T: Ordered>(list: List<T>) -> List<T>`
- `binary_search<T: Ordered>(list: List<T>, target: T) -> int`（返回 index 或 -1）
- 带比较器版本：`sort_by<T>(list: List<T>, cmp: fn(T, T) -> Ordering)`

**覆盖特性**：泛型 + trait 约束 + 闭包参数 + List 操作 + 递归 + 模式匹配

**预期暴露的 bug**：
1. [HIGH] 泛型 `<T: Ordered>` 在递归调用中约束是否正确传播
2. [HIGH] 闭包作为参数传递时 codegen 是否正确生成函数指针类型
3. [MED] `List<T>` 的 `pop()` / `push()` 在泛型场景下类型推断
4. [MED] 返回 `List<T>` 的所有权转移 vs clone 语义
5. [LOW] `Ordering` 枚举的三变体 match 是否覆盖完整

**验证**：
```lz
def main() =
    let data = [3, 1, 4, 1, 5, 9, 2, 6]
    assert bubble_sort(data) == [1, 1, 2, 3, 4, 5, 6, 9]
    assert quick_sort(data) == [1, 1, 2, 3, 4, 5, 6, 9]
    assert merge_sort(data) == [1, 1, 2, 3, 4, 5, 6, 9]
    assert binary_search([1, 2, 3], 2) == 1
    assert binary_search([1, 2, 3], 99) == -1
```

#### L2 链表 (`lib_linked_list.lz`)

**目标文件**：`libs/lib_linked_list.lz`

**功能**：
- `LinkedList<T>` = 枚举 `Cons(T, Box<LinkedList<T>>)` / `Nil`
- 或使用 `struct Node<T> { value: T, next: Option<Box<Node<T>>> }`
- `new() / push_front / push_back / pop_front / len / to_list / from_list`

**覆盖特性**：递归类型、Option<Box<Self>>、泛型 struct、impl 块、trait 方法

**预期暴露的 bug**：
1. [HIGH] `Option<Box<Node<T>>>` 这种嵌套类型在 codegen 中的渲染
2. [HIGH] 递归类型的内存布局——Rust codegen 是否需要 `Box` 消除无限大小
3. [MED] `impl<T> LinkedList<T>` 中 `&mut self` 方法的 borrow checker
4. [MED] 模式匹配 `Cons(head, tail)` 的枚举递归解构
5. [LOW] `Drop` trait / 是否需要手动 drop 避免栈溢出

## 3. Bug 分类与修复策略

### 3.1 按严重度分级

| 级别 | 定义 | 示例 | 修复时限 |
|------|------|------|----------|
| **P0 阻塞** | 编译器 panic / 语义拒绝正确代码 | 解析正确表达式报 Parse error | 立即修 |
| **P1 功能** | codegen 产出不通过 rustc | E0308/E0432/E0609 | 当前小阶段内修 |
| **P2 体验** | 误报（false positive 拒绝） | 正确代码报"未绑定变量" | 当阶段内修 |
| **P3 卫生** | warning / 代码质量 | dead_code / unreachable | 可延后 |

### 3.2 按根因分类

| 根因类别 | 典型症状 | 修复位置 | 优先级 |
|----------|----------|----------|--------|
| **类型推断失败** | E0308 类型不匹配 | `codegen.rs` / `builder.rs` | P1 |
| **trait 未生成** | E0599 方法不存在 | `codegen.rs` (collect_duck_impls) | P1 |
| **作用域注入缺失** | E0432 unresolved import | `builder.rs` (inject_builtins) | P0 |
| **递归类型无限大小** | E0072 / 编译失败 | `codegen.rs` (Box 插入) | P1 |
| **关联类型投影错误** | E0220 / 关联类型未找到 | `codegen.rs` (assoc_type) | P1 |
| **模式解构缺失** | E0609 非穷尽匹配 | `codegen.rs` (match arms) | P2 |
| **变参语义错误** | Parse error / 参数数量不匹配 | `parser.rs` / `builder.rs` | P0 |
| **嵌套函数捕获** | E0425 未绑定外层变量 | `builder.rs` (闭包提升) | P1 |
| **字符串切片不安全** | panic / 非 ASCII 越界 | `codegen.rs` (str index) | P1 |
| **pipe codegen 错误** | 调用链断裂 | `codegen.rs` (pipe desugar) | P2 |
| **build block 展开失败** | 代码位置错乱 | `codegen.rs` (build block) | P2 |
| **变参注入位置错误** | args/kwargs 未注入 | `builder.rs` (dotdot injection) | P0 |

### 3.3 修复流程

```
发现 bug → 写最小复现 probe → 定位根因 → 分类定级 → 修复 → 全量回归 → 记录
    ↑__________________________________________|
```

每个 bug 的最小复现 probe 放入 `div-tools/probes/bug_YYYYMMDD_NNN.lz`，命名规范：
- `bug_20260824_001_generic_constraint.lz`

每个修复配套一个回归测试放入 `tests/bugfix_*.rs`，格式参考现有 `tests/ir_pass_fixes.rs`。

## 4. 执行流程（每库标准 SOP）

```
Step 1: 阅读 SYNTAX 相关章节（如写 L6 前重读 09-错误处理.md）
Step 2: 编写 .lz 库文件（含 main + assert）
Step 3: 尝试编译：lang-zone.exe lib_xxx.lz
    ├─ LZ 报错 → 记录 → 最小复现 probe → 诊断 → 修复 → 重试
    ├─ .rs 生成但 rustc 报错 → 读取 .rs 产物 → 分析 codegen → 修复 → 重试
    └─ 编译通过但运行失败 → 分析运行时语义 → 修复 → 重试
Step 4: 运行通过 → 全量 cargo test 回归（确保未破坏）
Step 5: 更新 _ir_test_result.json（重测）
Step 6: 写 CHANGELOG 条目 + 记录到 docs/
Step 7: 提交（按每 10 小阶段同步一次仓库的节奏）
```

## 6. 风险与应对

| 风险 | 概率 | 影响 | 应对 |
|------|------|------|------|
| 递归类型 codegen 无法自动 Box | 高 | L2/L5/L6 阻塞 | 手动要求用户写 `Box<>` 或在 builder 中自动插入 |
| trait 对象 `dyn Trait` 未实现 | 中 | L8 降级 | 先用 `impl Trait` 静态分发替代 |
| `str` 生命周期问题 | 高 | L3/L6/L9 阻塞 | 规定 `str` 为 owned 值类型，codegen 映射到 `String` |

## 7. 已识别的优先修复项（前置解决）

在开始库复现之前，以下已知问题应先修复，否则多个库会被同一 bug 阻塞：

### 7.1 [P0] `lz_builtins` 链接（E0432 霸榜）

- **现象**：50 个 rustc 失败全部是 `use lz_builtins::*` 无法解析
- **根因**：codegen 顶部自动注入 `use lz_builtins::*`，但测试/运行环境下无该 crate
- **修复方向**：提供 `lz_builtins` 桩 crate 或测试用 `#[path]` 注入；或将 `use lz_builtins` 改为条件编译

### 7.2 [P0] LZSTD 模块批量编译失败

- **现象**：`dict.lz / iter.lz / list.lz / option.lz / ordering.lz / prelude.lz / traits.lz` 全部报"未绑定变量"
- **根因**：这些文件使用编译器自动注入的类型名（`Vec<i64>`, `Option<i64>`, `Ordering`）但未 import
- **修复方向**：在 builder 的 prelude 注入阶段自动注入这些名称到作用域

### 7.3 [P1] 嵌套函数捕获限制

- **现象**：`p10_nested.lz` — 嵌套函数不能引用外层局部变量
- **根因**：嵌套函数提升为模块级后无法访问外层局部变量
- **修复方向**：支持闭包式捕获（将外层变量打包进环境 struct），或文档明确限制并给出闭包替代方案

### 7.4 [P1] 字符串返回类型生命周期

- **现象**：函数返回 `str` 时 codegen 可能产生悬垂引用
- **根因**：LZ 的 `str` 语义为 owned，但 codegen 可能直接映射到 `&str`
- **修复方向**：统一将 `str` codegen 为 `String`（或 `Cow<str>`），禁止直接返回 `&str`
