# LZ 编译器规划建议（语法冻结约束版）

> 日期：2026-08-19 ｜ 基线：v0.1.161 ｜ 约束：**语法已冻结，不可新增/修改任何词法或语法规则**
> 定位：在「语法冻结」前提下，重新校准 LZ 编译器下一阶段的全部工作优先级，明确「做什么 / 不做什么 / 先后顺序」。

---

## 一、先划清边界：冻结什么、不冻结什么

「语法冻结」容易被误读成「什么都不能做了」。必须先精确划分，否则团队会在该动手的地方缩手、在该停手的地方越界。

### 1.1 冻结区（红线，一律不动）

| 层级 | 冻结内容 | 依据 |
|---|---|---|
| 词法 L1 | token 集合、关键字集、缩进规则、`.` 分隔 import（`::` 已废弃为 LexError）、`#`=属性宏（非注释） | 红线决策 |
| 语法 L2 | 语法结构、运算符集与优先级（0..17）、泛型约束 `<T: Bound>`/`where`、函数体 `=`+缩进、enum 块 `:`、`impl Type =`、闭包 `\|x\|` 写法 | 语法铁律 |
| 已拍板决策 | 子类型运算符 `<:`/`>:` 已移除；`str`/`()`/`f64`/`None` 等命名；`True`/`False` 字面量关键字 | 决策文档 |

**判据**：任何涉及 lexer token、parser 产生式、关键字/运算符增删改的提案，一律否决，不进入排期。

### 1.2 非冻结区（主战场，可放手做）

| 层级 | 内容 | 说明 |
|---|---|---|
| 语义 L3 | typer / hints 推断完备性、约束求解覆盖 | 实现层，不碰语法 |
| **codegen L4** | IR→Rust / IR→Cython 的生成质量 | **冻结下最大的合法战场** |
| 标准库 | LZSTD、builtins、bridge 桥接 | 库，非语法 |
| 工具链 | CLI 子命令、增量编译、LSP、CI、覆盖率 | 完全无关语法 |
| 测试/文档 | 测试对、Omega 验证、规范定型 | 完全无关语法 |

**核心洞察**：LZ 的语法能力已经足够表达（40+ 特性、261 个 demo、自举 100%）。**当前瓶颈不在「能不能写出来」，而在「生成的 Rust 能不能编译通过」**——这是 codegen 后端的问题，与语法冻结零冲突。

## 二、现状诊断（数据说话）

### 2.1 已经扎实的部分（不可回退）

- 自举 100%（v160/v161）：`--emit=rs-lz` 与 Rust codegen 逐字符一致，bootstrap closed 13/13 RC=0
- cargo test 320/0 全绿，DEMO 261/261 LZ 编译通过
- 单源 IR（LZIR-H）已成型：node/builder/codegen/display/types 五模块
- 语法规范 36 份文档，已定型为权威

### 2.2 核心短板（按严重度排序）

| # | 短板 | 数据 | 性质 |
|---|---|---|---|
| S1 | **IR→rustc 通过率低** | 73/129 ≈ **56.6%**（DEMO 编译目标中生成的 `.rs` 能过 rustc 的比例） | codegen 后端成熟度，冻结下唯一主攻方向 |
| S2 | **双路线并存** | 老 `src/codegen/`（AST→Rust）仍是 `lzc` 默认路径，IR 路线未切换 | 技术债，违反 IR-only 决策 |
| S3 | **错误检测缺口** | 17 条反例静默通过（重复枚举变体/未知类型/参数个数不匹配），反例 8/25 | 解析器「宽容」过度，允许错误代码编译 |
| S4 | **测试覆盖率无行级报告** | 只有覆盖映射表（15/15），无 `llvm-cov` 行级 | 验证强度不足 |
| S5 | **标准库骨架** | LZSTD 仅架构+builtins 部分；bridge 6 文件只接线 4 个 | 库能力不全 |

### 2.3 关键结论

**S1（56.6%→接近 100%）是语法冻结约束下唯一能大幅推进的核心 KPI**。它只依赖 codegen 后端补全，不触碰任何语法。围绕它组织工作，能同时消化 S2（切换 IR 路线）、S3（错误检测）、S4（验证）。

## 三、规划主线（6 个方向，按优先级）

### 方向 1（P0）：IR 路线迁移收尾 —— 冻结下最大的合法战场

**目标**：IR→rustc 通过率从 56.6% 提升到 90%+，并切换默认路径。

**子任务**（对齐 README 差距清单 10 项 + 自举 D2 缺口，二者高度重叠，合并推进）：

| 子项 | 内容 | 优先级 |
|---|---|---|
| 1a | `__call__` 直调接线（`Callable::call`），修复 E0618 | P0 |
| 1b | 魔法 trait 自动派生（`impl Callable/Display/... for T`） | P0 |
| 1c | 顶层构建块 `x =:` 收集与生成 | P0 |
| 1d | `defer` 用 RAII guard 实现（替换 `// defer` 注释） | P1 |
| 1e | std 桥接注册表迁移到 IR 后端 | P1 |
| 1f | 可变参数 `..` 参数包建模 | P1 |
| 1g | 嵌套函数提升 | P1 |
| 1h | impl 块 / 列表推导 / 生成器 / match 模式 codegen 补齐 | P1 |

> ⚠️ 注意：1h 四项**语法均已存在**（`impl Type =` 合法、comprehension 有 `for x in ...`、`*:` 生成器、`match`），当前缺的是 **codegen 生成**，属实现缺口，**补齐不违反语法冻结**。必须在文档/issue 中把「语法缺口」与「实现缺口」严格区分，避免被误判为冻结区。

**验收**：`main.rs` 默认路径切换为 `build_ir` + `IrCodeGen`（保留 `--ast-codegen` 回退对照）；`tests/compile_demos` + `reject_errors` 全量跑 IR 路线绿；DEMO 生成 `.rs` 过 rustc 通过率 ≥ 90%。

### 方向 2（P0）：错误检测缺口补齐（S3）

**目标**：反例通过率 8/25 → 25/25。

**内容**：补齐 `div-tools/syntax_probes/` 17 个反例对应的检测——重复枚举变体、未知类型、参数个数不匹配、未定义变量等。解析器「宽容」过度的地方要收严，让错误代码在编译期被拒绝。

**验收**：语法矩阵反例 25/25 全部拒绝；新增 `tests/reject_errors` 用例不减少。

### 方向 3（P1）：标准库补全（S5）

**目标**：LZSTD 从骨架到可用。

**内容**：
- `lz.std.*` 默认导入项补全（只放 Rust 没有的 / 后端集成项，**不抄** `std/modules/*.toml`）
- bridge 接线补全（python.rs / rust.rs / wasm.rs / shared.rs 接线 + E2E）
- 桥接调用台账（`bridge-ledger.tsv` 追加式）
- 错误码统一（E_SYM / E_TYPE / E_DUP / E_LANG）

**验收**：bridge 六文件全接线；export 三目标（Rust/Python/C）产物可编译；台账可审计。

### 方向 4（P1）：测试与验证强化（S4）

**目标**：验证强度从「全绿」到「可量化」。

**内容**：
- Omega（Ω）机制落地：每个语法特性配 spec JSON + 测试对（正例/反例）
- 行级覆盖率报告（`cargo llvm-cov`），目标行覆盖 90%+、分支 80%+
- 模糊测试：随机 `.lz` 不崩溃、不产生错误代码
- IR→rustc 通过率纳入 CI 指标看板

**验收**：覆盖率达标；每个特性有 spec + 测试对 + golden 三重保障。

### 方向 5（P2）：工具链

**目标**：从「能用」到「好用」。

**内容**：
- 增量编译：模块级缓存 + 依赖图 + 并行编译（依赖方向 1 的 IR 模块边界 + 序列化）
- LSP：诊断/补全/跳转/重命名，复用 typer 类型信息；source map 把 rustc 错误回映射到 `.lz` 行号
- CI：`cargo build` + `check_doc_versions.py` + IR 通过率看板

**验收**：单文件变更编译时间随变更量线性下降；编辑器保存即编译、错误定位到 `.lz`。

### 方向 6（P2）：文档定型

**目标**：语法冻结 = 规范从「演进中」转「权威版」。

**内容**：
- SYNTAX/ 36 份文档冻结为权威版，版本头统一，冻结后不再随实现漂移
- 补齐「语法缺口 vs 实现缺口」分类表，明确哪些是冻结区、哪些是可补区
- 归档 `方案.md`、`LZ_UPGRADE_PLAN.md` 中与冻结约束不符的「新增语法」描述（如 `extern "rust" {}` 块 → 已改 `#[extern(lang)]` 装饰器）

**验收**：规范文档与编译器行为零漂移；无任何文档暗示「未来新增语法」。

## 四、明确不做的事（红线）

1. **不新增任何关键字、运算符、语法结构**——所有「想要新特性」的冲动，一律先问「能否用现有语法 + 标准库/装饰器/魔法方法表达」。
2. **不新增 extern 块语法**——`#[extern(lang)]` 装饰器已用现有 `#`→`@` 机制实现，无需 `extern "rust" {}`。
3. **不引入字节码 VM**——半宿主 VM 违背「转译正确性」核心定位，仅当热重载成为硬需求再评估。
4. **不复用老 `src/codegen/`**——不在 AST→Rust 路线上新增任何功能，只把它当作迁移对照，逐步退役。
5. **不抄 `std/modules/*.toml` 进 `lz.std`**——`lz.std.*` 只放 Rust 没有的/后端集成项。

## 六、风险与注意事项

1. **「语法缺口」与「实现缺口」混淆**——必须建立分类表，否则会误判为冻结区而不敢补，或误判为可补区而越界改语法。
2. **双路线并存期回归风险**——切换默认路径期间保留 `--ast-codegen` 回退 + golden diff 对照，防止切换引入隐性回退。
3. **IR 序列化/增量缓存失效逻辑**——必须严格测试「改了 A 却用 B 的旧缓存」这类传播失效 bug。
4. **自举 D2 与 IR 差距清单重复排期**——两份清单高度重叠（impl/推导/生成器/match），必须合并推进，避免重复劳动。
5. **AI 实现边界**——架构决策（IR 格式、缓存策略、切换时机）人工把关；AI 只做 codegen 补全、测试补全这类机械但有验证锚点的工作。

---

## 七、一句话总结

**语法已冻结，意味着 LZ 的「语言设计」阶段结束，「编译器工程化」阶段开始。** 全部力量聚焦一件事：把「生成的 Rust 能编译、能跑、语义正确」这条 codegen 主线打穿（56.6% → 90%+），同时收严错误检测、量化测试、补全标准库——这些都不碰语法，却决定 LZ 能否从「自举玩具」变成「生产可用」。
