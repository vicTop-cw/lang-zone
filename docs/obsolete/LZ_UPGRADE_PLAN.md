# Lang-Zone (LZ) 升级优化建议书

> 版本：v1.0 ｜ 日期：2026-08-17
> 定位：基于 2026-08-17 架构讨论（宿主式/半宿主、宿主链、增量编译、热重载、IR 分层、Omega 验证、AI 生产级路径），为 LZ 编译器下一阶段升级优化提供详细、可执行建议。

---

## 1. 现状盘点

### 1.1 版本与状态

| 指标 | 数值 | 说明 |
|---|---|---|
| 自举 | 100%（v160） | bootstrap closed 13/13 RC=0 |
| cargo test | 320/0 | 全绿 |
| DEMO | 261/261 | 全绿 |
| 转译一致性 | `--emit=rs-lz` 与 Rust codegen 逐字符一致 | golden 级保证 |
| 已知缺口 | impl 块 / 列表推导 / 生成器 / match 模式 | D2 缺口 |

### 1.2 架构现状

```
 .lz → L1 Lexer → L2 Parser → L3 语义/类型 → L3.5 LZIR → L4 IR codegen（Rust / Cython 双后端）
```

- **路线决策（2026-07-31）**：全力走 IR 中间表示路线（AST → LZIR → 目标语言），旧 AST 直接 codegen 路线退役。
- **LZIR**：定义于 `src/ir/node.rs`，携带 `IrType` 与源码 `Span`，由 `build_ir()` 从 AST 构建。
- **双后端**：`codegen.rs`（Rust）、`codegen_cython.rs`（Cython，基础框架）。
- **差距清单 10 项**：顶层构建块、构建块调用、魔法 trait 派生、`__call__` 直调、可变参数、std 桥接、`@export`、嵌套函数提升、`defer`、装饰器。

### 1.3 架构定位

- **全宿主式语言**：转译到 Rust/Cython，优化外包给 rustc/LLVM。
- **宿主链**：LZ → Rust → 机器码（2 层，短链健康）。
- **生产级路径**：宿主式门槛低，靠"转译正确性 + 测试对 + golden 验证"闭环即可达生产级。

## 3. 方向 A：IR 增强（P0）

### 3.1 现状问题

LZIR 已携带 `IrType` 与 `Span`，但存在三个短板：
1. **Span 覆盖不完整**：部分节点（尤其宏展开后、魔法调用）丢失源码位置。
2. **无模块边界**：IR 是扁平结构，无法按文件/模块独立处理。
3. **无序列化**：IR 只存在于内存，无法缓存。

### 3.2 建议

1. **Span 完备化（强制）**
   - 所有 IR 节点强制携带完整 Span：`(file, line, col, len)`。
   - 宏展开后的节点保留"展开前位置 + 展开来源"双记录。
   - 作用：错误定位、source map、代码感知、热重载回映射。

2. **模块边界**
   - IR 按文件/模块组织，每个模块有稳定接口：导出符号表、依赖图、公共类型。
   - 定义模块级 `ModuleIR` 容器，内部为 `Item` 列表。

3. **序列化缓存**
   - IR 支持序列化（建议 `bincode`，体积小速度快；调试用 JSON）。
   - 按"源码哈希 + 依赖版本"缓存，命中直接加载，跳过重编译。
   - 定义 IR 格式版本号，格式变更时缓存自动失效。

4. **IR 稳定性契约**
   - 发布 IR 格式版本，保证缓存跨版本兼容或安全失效。

### 3.3 验收标准

- 每个 IR 节点可回溯到源码精确位置。
- 模块级 IR 可独立序列化/反序列化，往返一致。
- 缓存命中时跳过重编译，输出与全量编译逐字符一致。

## 4. 方向 B：增量编译（P0）

### 4.1 现状问题

`lzc` 每次全量编译，无缓存、无依赖跟踪。大型程序编译时间随规模线性增长。

### 4.2 建议

1. **模块级缓存**
   - 按文件哈希缓存：`源码哈希 → IR 缓存 → 生成代码缓存`。
   - 未变更模块直接读缓存。

2. **依赖图**
   - 构建模块依赖图（import/use 关系）。
   - 变更模块 + 依赖它的模块才重编译，其余读缓存。

3. **缓存失效策略**
   - 直接失效：源码哈希变化。
   - 传播失效：被变更模块依赖的下游模块级联失效。

4. **并行编译**
   - 独立模块并行编译（rayon），无依赖的模块同时处理。

5. **增量诊断**
   - 只报告变更模块的错误，避免全量报错淹没。

### 4.3 验收标准

- 单文件变更，未变更模块直接读缓存，编译时间随变更量线性下降。
- 缓存命中与全量编译输出逐字符一致（golden 校验）。
- 依赖传播失效正确，无"改了 A 却用了 B 的旧缓存"。

## 5. 方向 C：热重载（P1）

### 5.1 现状问题

无热重载能力，改代码必须重启。

### 5.2 建议

**方案一（推荐）：动态库热重载**
- LZ → Rust 转译输出 `cdylib` 动态库。
- 定义模块加载/卸载/替换接口（`load_module` / `unload_module` / `replace_module`）。
- 运行时监听 `.lz` 文件变更 → 重编译 → 替换动态库 → 状态迁移。

**方案二（备选）：字节码 VM**
- LZ 引入字节码 VM（半宿主），天然支持热重载。
- **注意**：LZ 核心是转译正确性，VM 优先级低，仅当热重载成为硬需求时再评估。

### 5.3 验收标准

- 程序运行中修改 `.lz` 文件，自动重编译并替换，不重启进程。
- 状态（全局变量、已加载数据）在热重载后正确保留或明确重置。

## 6. 方向 D：代码感知自动转译（P1）

### 6.1 建议

1. **LSP 服务器**
   - 实现 language server：诊断、补全、跳转定义、重命名、悬停。
   - 复用现有 typer/hints 类型信息。

2. **保存即编译**
   - 文件保存时自动转译 + 编译，错误实时反馈到编辑器。

3. **source map**
   - 生成 `.lz → .rs` 映射，rustc 错误定位回 `.lz` 源码行号。

### 6.2 验收标准

- 编辑器保存 `.lz` 自动编译，错误定位到 `.lz` 行号。
- 补全/跳转基于真实类型信息，非文本匹配。

## 7. 方向 E：IR 路线迁移收尾（P0）

### 7.1 差距清单 10 项补齐

按优先级推进：

| 优先级 | 项 | 说明 |
|---|---|---|
| P0 | `__call__` 直调 | 生成 `Callable::call` 或方法调用，否则 rustc E0618 |
| P0 | 魔法 trait 自动派生 | 生成 `impl Callable/Display/... for T` |
| P0 | 顶层构建块 `x =:` | builder 消费 `module.top_level_builds` |
| P1 | `defer` 生成 | 用 RAII guard 实现，替换 `// defer` 注释 |
| P1 | std 桥接 / 外部类型 | 迁移桥接注册表到 IR 后端 |
| P1 | 可变参数 `..` | IR 增加 variadic 参数表示 |
| P1 | `@export(Rust/Python)` | 迁移 cdylib / PyO3 导出 |
| P1 | 嵌套函数提升 | 迁移 `collect_nested_fns` |
| P1 | 构建块 `~:` 调用/解包 | 补齐调用构建块与 kwargs 拆包 |
| P1 | 装饰器（`@simd`/`@parallel`/`@tail_call`） | 迁移 |

### 7.2 迁移步骤

1. `main.rs` 默认路径切换为 `build_ir` + `IrCodeGen`（保留 `--ast-codegen` 回退开关对照）。
2. `tests/compile_demos` 与 `tests/reject_errors` 全量切换 IR 路线跑绿。
3. 差距清单清零后，删除 `src/codegen/` 遗留代码。

### 7.3 验收标准

- 默认编译路径 100% 走 IR 路线。
- 双路线输出逐字符一致（golden 对照）。
- 差距清单 10 项全部关闭。

## 8. 方向 F：已知缺口补齐（P1）

### 8.1 缺口清单

- **impl 块**：方法定义与 trait 实现。
- **列表推导**：`[expr for x in iterable if cond]`。
- **生成器**：`*:` 生成器表达式。
- **match 模式**：模式匹配完整语义。

### 8.2 建议

- 按 D2 缺口清单逐项补齐。
- 每个缺口配：spec 文档 + 测试对（正例/反例）+ golden 测试。
- 补齐后更新自举验证（bootstrap closed 用例扩展）。

### 8.3 验收标准

- 每个缺口有独立 spec 与测试对。
- 自举用例覆盖新特性，RC=0。

## 9. 方向 G：测试与验证强化（P0）

### 9.1 建议

1. **Ω 机制引入**
   - 借鉴 sigma-lang 的 Ω/共识门禁方法论：spec JSON + corpus 语料 + 三端验证。
   - 每个语法特性配 spec 规则，机器可验证。

2. **测试对体系**
   - 每个特性配正例/反例测试对，覆盖边界与错误路径。

3. **golden 测试扩展**
   - `--emit=rs-lz` 与 Rust codegen 逐字符一致（已有），扩展到所有 DEMO 与新增特性。

4. **覆盖率行级报告**
   - 目标：行覆盖率 90%+，分支覆盖率 80%+。

5. **模糊测试**
   - 随机生成 `.lz` 源码，验证：不崩溃、不产生错误代码、错误信息可读。

### 9.2 验收标准

- 覆盖率达标，模糊测试无崩溃。
- 每个语法特性有 spec + 测试对 + golden 三重保障。

## 11. 风险与注意事项

1. **IR 序列化格式变更**：需版本管理，格式变更时缓存安全失效。
2. **增量编译缓存失效逻辑**：必须严格测试，防止"改了 A 用了 B 的旧缓存"。
3. **热重载与内存安全**：静态类型语言热重载需谨慎设计状态迁移，避免悬垂引用。
4. **不要过早引入 VM**：LZ 核心是转译正确性，半宿主 VM 仅当热重载成为硬需求时再评估。
5. **双后端一致性**：Rust 与 Cython 后端需同一测试对跑双后端，防止语义漂移。
6. **AI 实现边界**：AI 加速实现，但架构决策（IR 格式、缓存策略、热重载协议）需人工把关。

## 12. 一句话总结

**LZ 的升级主线 = 把"一层 IR 做扎实"（span + 模块边界 + 序列化）→ 解锁增量编译 → 解锁热重载与代码感知。** 不需要更多层 IR，不需要过早引入 VM，优化外包给 rustc 是宿主式的红利，保持短链即可。
