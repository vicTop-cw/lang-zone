## 一、这一轮量到的东西：两侧闸门，一边各瞎一半

cy 的方法改写表靠两个静态判据：**是不是用户类**（`ty_is_user_class`）和**本类有没有实现那个魔法名**
（`user_class_has_method`）。接收者的静态类型是 `IrType::Any`（无注解闭包形参，
`src/ir/builder/capture.rs:528` 恒落 Any）或 `IrType::Generic(_)`（泛型形参，
`src/ir/builder/convert_decl.rs:665`）时，cy 侧的形参就是 `object`，两个判据同时取到极端值：
`!ty_is_user_class` 的改写臂**恒真**（用户类自带的方法名被强改成 Python 名），
正向直派臂**恒假**（`__shl__` 不派发、迭代适配器不套）。
外加三支**无条件**臂（`clone`/`unwrap`/`try_into`，当初为 with 脱糖而设）连静态用户类都不放过。

## 三、两支闸门形状的坑（不是「多加个 if」那么轻）

1. 那三支无条件臂的反向闸门**不能**写成「是不是用户类」。with 脱糖在**共享 IR** 里就对
   **没有** `clone` 的用户类发 `alias.clone()`（`DEMO/06_control_flow/with_defer.lz` 是这条的实测来源），
   按「是不是用户类」落回方法调用就是 `AttributeError`。所以判据换成「本类有没有定义这个名字」，
   锁在 `cy_clone_unwrap_only_passthrough_when_no_such_method`（同一支程序里两种用户类：
   有 clone 的 ⇒ 产物含 `a.clone()`；没 clone 的 ⇒ 产物**不含** `b.clone()`）。
2. 助手内部分派有两种形状，选错一种就把好的一面换成坏的一面：
   - **按属性存在性**（`getattr(o, name, None)`）：`_lz_orv`／`_lz_self`／`_lz_contains`。
     理由是 `Option[MyClass]` 在本后端就是**裸值**，按名单判会对它发 `o.unwrap_or(d)` 而 AttributeError——
     修一个分叉造一个新的。
   - **按名单**（`_lz_dyn`）：`_lz_meth`／`_lz_len`／`_lz_isempty`。
     反例是 `remove`：Python 的 `list` **自带** `.remove`（按**值**删），
     而 LZ 的 `.remove(i)` 是按**位置**删，按属性存在性分会把语义静默换掉（这一条是既有
     `.pop(i)` 改写的原意，见 `DEMO/01_basics/lists.lz`）。
