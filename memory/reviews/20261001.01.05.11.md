## 二、BUG-5 收口（台账抬头仍写 OPEN，原因见 §六）

复现件 `FIND_BUG/hunt-20260926/bug-E-list3-empty-nested-pushdown-e0308/rv_list3.lz`
（`let a: List<List<List<int>>> = [[], [[]]]` + `println(a)`）。改前产物：

```
static a: LazyLock<Vec<Vec<Vec<i64>>>> = LazyLock::new(|| vec![Vec::<Vec<i64>>::new(), vec![Vec::<i64>::new()]]);
    return println!("{:?}", vec![(), vec![()]]);        // ← 引用位内联体
```

定义位对、引用位错，说明 D6 轮的 `ListLit` 元素位下推只覆盖了 AST 字面量路径，没覆盖
`comptime_consts` 内联路径：`comptime_value_to_lit` 给每个子表达式一律 `IrType::Any`，
codegen 的 `ListLit` 臂 `is_nil` 判据（`IrType::Unit | Any` → `"()"`）把空列表发成 `()`。
改后两行逐字相同（`vec![Vec::<Vec<i64>>::new(), vec![Vec::<i64>::new()]]`）。

穷尽同类点（不是「顺手也改一下」，是逐臂判定）：

- `ComptimeValue::Tuple` 臂：同一函数、同一 `IrType::Any` 写法 → **一并修**，实测
  `let t: (List<List<int>>, List<int>) = ([], [1, 2])` 的内联体从 `(()，vec![1i64, 2i64])`
  变为 `(Vec::<Vec<i64>>::new(), vec![1i64, 2i64])`；
- `Map/Type/Inspect` 臂：`_ => None`，本就不产出内联体 → **不适用**；
- 三个调用点：只有 :4316 有声明类型可传；:4347（`comptime <expr>`）与 :7638（comptime 块）
  在语法上没有注解类型可依据 → 显式 `None`，走「退回 Any，与改前逐字相同」那条路。

## 三、BUG-9：载体必须带 `+ Send + Sync`，且卡片归因是错的

卡片写「2026-09-30 T0r3 载体改造引入」。**实测推翻**：把同一份生成码的载体逐一手改，
跑闸门同款 rustc 参数（`--edition 2021 --extern lz_builtins=… -L dependency=target/debug/deps -A warnings`）：

| 载体 | 结果 |
|---|---|
| `Box<dyn Fn(i64) -> i64>`（HEAD 旧载体，`git show HEAD:src/ir/codegen/mod.rs` 里 `Rc<dyn Fn`=0、`Box<dyn Fn`=22） | `error[E0277]: dyn Fn(i64) -> i64 cannot be sent between threads safely` |
| `Rc<dyn Fn(i64) -> i64>`（T0r3 载体） | 同错 |
| `Arc<dyn Fn(i64) -> i64>`（只换指针） | E0277 两条（sent + shared） |
| `Arc<dyn Fn(i64) -> i64 + Send + Sync>` | 编译通过，运行输出 `"rc-send-marker ok"` / `2`，exit 0 |

即：这条缺口 Box 时代就在，换 Arc 单独也不够。真正的产品改动必须包含 `+ Send + Sync` 上界。
证据件：`TEMP/bug5/carrier/{box_head,arc_plain,arc_send}.rs`（同一底稿只差载体字样，
可重跑：`rustc --edition 2021 TEMP/bug5/carrier/arc_send.rs --extern lz_builtins=target/debug/liblz_builtins.rlib -L dependency=target/debug/deps -A warnings -o TEMP/bug5/arc_send.exe`）。

**收紧的代价，实测划出边界**：`Arc + Send + Sync` 会顺着捕获链往上咬。第一轮 run1 因此红
7 处（`find_bug_libs::lib_closure` + DEMO 6 个非基线新增），两处根因，都不是「语义不该收紧」而是我漏改：

1. 转发闭包模板硬编码 `std::rc::Rc::clone(&plus3)` → 载体成 Arc 后 `E0308 expected &Rc<_>, found &Arc<…>`；
2. HOF 形参 `impl Fn(b) -> c + 'static` 不含 Send/Sync，而 compose 一类函数把形参捕获进
   Send 载体 ⇒ rustc 直接给出「consider restricting opaque type … with trait Send」。
   修法只在**本函数返回类型是 fn 值**时给形参加 `+ Send + Sync`（`map/filter/for_each`
   这些返回非 fn 值的 HOF 形参一字未动），不是全局放宽也不是全局收紧。
