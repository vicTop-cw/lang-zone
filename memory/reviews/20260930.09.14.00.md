## 六、入账的回归：BUG-9（本轮唯一「闸门全绿但产品回归」）

- **形态**：fn 值被 `go expr` 的捕获闭包带走时，产物编译报 `E0277: Rc<dyn Fn(i64) -> i64> cannot be sent between threads safely`。旧 `Box<dyn Fn>` 是 `Send` 的（std 只为 `Box<dyn Fn>` 与 `&dyn Fn` 实现 `Fn*` + 自动 Send 判定），换 `Rc` 后失去该性质；发射位在 codegen:10520（`std::thread::spawn(move || …)`）。
- **为什么三门禁看不见**：326 文件 DEMO 闸门与 742 项 workspace **无一用例**在 `spawn` 内捕获 fn 值 ⇒ 全绿也不证这条路没坏。这条是读 `go` 发射位反推出的探针，不是测试跑红撞出来的。
- **已排除的简易解法（实测，不是猜）**：只把 `Rc` 换 `Arc` 仍红——`Arc<dyn Fn>` 需要 trait 对象自带 `+ Send + Sync` 才 `Send`，裸 `dyn Fn` 两条都缺（`TEMP/rc_probe/go_capture_fn_arc.rs`）。⇒ 正解是**按调用点选择载体**（spawn 位发 `Arc<dyn Fn(..) -> .. + Send + Sync>`）或在 `go` 发射位对捕获的 fn 值做一次性 Box 化转发。
- **挂起锁（按 `tests/find_bug_bugs.rs:4-5` 声明的约定）**：语料 `FIND_BUG/codegen/bug-rc-fn-not-send-in-spawn.lz` + `#[ignore = "RUSTC_FAIL: …"] fn cg_rc_fn_value_not_send_in_spawn`（`tests/find_bug_bugs.rs:509-515`）。修复后**移除 `#[ignore]` 转正**，不是删锁。
