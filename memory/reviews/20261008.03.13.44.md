## 二、BUG-34：三处发射形态与 Python 运算符协议不同名（本轮修，cy 侧）

| 面 | 修前（逐字，取自 `magic-probes-100301.log`） | 根因 |
|---|---|---|
| `x.contains(y)`（用户类实现 `__contains__`） | AttributeError: '_lzcyg_m_contains.Word' object has no attribute 'contains' | Python 的协议面是 `y in x`；LZ 的魔法名与调用糖都不是它 |
| `a << b`（实现 `__shl__`） | TypeError: unsupported operand type(s) for <<: '_lzcyg_m_bits.Money' and '_lzcyg_m_bits.Money' | 移位两族不在共享 IR 的分派表里，cy 发裸 `<<`，而 Python 要 `__lshift__` |
| `~x`（实现 `__invert__`／整数） | `'bool' object has no attribute 'v'`（取自 `magic-probes-103016.log`：移位先响，`~` 是它后面那一支） | `map_unop` 把 BitNot 降级成 Not（见 §四），旧 cy 一律发 `not ` ⇒ 对象塌成 bool |

修法是一条**闸门 + 一张不被消费的登记表**：三处都按「接收者的静态类型是用户类，且它确实实现了那个魔法名」改写
（BinOp Shl/Shr 直派、`.contains` 变 `in`、UnOp Not 按操作数类型还原成 `not `/`~`）。
**本轮踩到的量具坑**：闸门第一版直查 `impl_methods`，而那张表在类生成时被 `remove` 走（防重复注入）⇒
两个新臂恒假、探针读数一字未变。于是加了 `class_method_names`（struct 自写 + impl 注入都登记、只读不消费）。
这与 BUG-22/23 同族（登记表键与查询键不同源），只是方向换成「键被吃掉」。

## 三、BUG-35：迭代协议的「取完了」与 `.unwrap_or` 根本没接线（本轮修，cy 侧）

- `__next__` 返回 `Option.None` 表示结束，cy 旧发射发成 `return None`，Python 的 for 把 `None` 当成**一个元素**：
  修前逐字 `TypeError: unsupported operand type(s) for +: 'int' and 'NoneType'`。
- `.unwrap_or(d)` 在 cy 的方法表里**整条缺席**，落到通用兜底变成对裸值调方法：
  中途逐字 `AttributeError: 'int' object has no attribute 'unwrap_or'`。
- **这一支的价值在过程**：第一版把用户的 `__next__` 改名 `__lz_next__` 再包一层 StopIteration，
  `for` 侧当场修好，但同一支探针的 `m_next` 从「返回 None」变成「把 StopIteration 抛进用户程序」——
  **修复自己引入新分叉**，是探针把它当场抓住的。终版改成只在 **for 的取数面**套 `_lz_iter(o)`，
  用户的 `__next__` 一字不动 ⇒ `next(it)`、`it.__next__()` 仍是 Option 形态；
  内建 list/str/dict 一律不套（它们的 `None` 是元素不是结束，套上去会把序列截断）。
- `.unwrap_or` 走分档助手 `_lz_or(v, d)`（cy 的 None 有两种真实形态：Python `None` 与垫片单例 `_LzNoneCls`），
  臂上带 `!ty_is_user_class` 反向闸门。

## 四、BUG-36：`~x` 的位非在共享 IR 里被降级（入账未修，本车道不改 `src/ir/builder/`）

`src/ir/builder/ops_map.rs` 里 `UnaryOp::BitNot => UnOpKind::Not, // 位非降级为逻辑非` ⇒ AST 层的信息在 IR 里没了。
rust 面恰好不受影响（`!` 一符两用：bool 逻辑非 / 整数位非 / 用户类走生成的 `impl Not`），
cy 面必须按操作数类型猜回来。**这是补救不是修复**：第三个后端读同一份 IR 会把 `~6` 当逻辑非。
同族在册：`__shl__`/`__shr__` 也不在 `magic_method_for_binop` 里。转正前置写进卡里（改动落在共享 IR ⇒ 需要另一条车道）。
