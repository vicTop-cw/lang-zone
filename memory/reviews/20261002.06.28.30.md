## 一、本轮做了什么（T0r7）

起点是目标里那句「所有特性稳定，**无回归**」。本轮的三条动作都不是加特性，而是把上一轮
自己埋的两处口径错和一处垫片缺口**打到能红**：

1. **回退「f-string 插值一律 Debug」**（BUG-15 → REVERTED）。本轮开工后我按规范复核，发现上一轮那次
   裁决建立在一条假证据上：当时 grep 的是不存在的 `docs/SYNTAX/`，零命中被我读成「规范对引号无条文」。
   规范其实在仓库根 `SYNTAX/00-词法基础.md:188`，明写 `f"x={x}"` -> `format!("x={}", x)`（Display，不带引号）；
   而真正**会被执行**的判据 `tests/str_boundary.rs` 的 c7_fstring 断言 `name=LZ, age=30`。
   证据优先级据此定为：规范条文 > 会执行且有绿/红成对日志的判据 > 没人执行的断言文案。
   Rust 侧 `gen_fstring` 逐字节回到基线（脚本比对代码行相等，注释除外），cy 侧改用**运行时**判定
   `_lz_fs`（str 不带引号，其余按 Debug）——比 Rust 的静态表更贴规范，且 bool/None/容器仍带引号形态一致。
2. **修自己上一轮 BUG-21 的半边修复**（BUG-26）。切片作值时 `.to_vec()` 不分基底类型，
   文本基底被一起发进去 ⇒ rustc E0599，把 workspace 打红两个 target；补 `base_is_str_like()` 按类型分叉。
3. **补自己本轮改写表造成的回归**（BUG-25）。`contains` 改写成了 `k in ps.kwargs`，
   而后端**自己发的垫片类** `_LzKwargsMap` 没有 `__contains__` ⇒ Python 退化成迭代协议，`KeyError: 0`；
   垫片补齐四个协议方法，并把**两份逐字副本**收成一份 `const PARAMS_SHIM`（两处插入点共用）。

BUG-13 也按它卡里那句「转正前置：先造能红判据，再动产品码」做完了：L1 现在逐件扫生成的 `.pyx`，
把 `def` 行里 `-> Py_ssize_t|double|bint|float` 这种「Cython 只给 warning」的假注解当缺陷红。

## 三、口径类裁决只认「会被执行的判据」

本轮唯一一次改语言语义（f-string）走的是**回退**而不是继续推进，理由要写清楚以免下一轮又被当证据读：

  `tests/demo_codegen_compile.rs` 的 Stage 只有 Transpile/Rustc —— 断言反了也不会响。
  本轮把这两件直接喂跨后端差分器，让它们的 assert **第一次真的被执行**：两端**同形失败**
  （`一致 2 | 分叉 2`，两侧都是 `name=LZ, age=30` 那一侧赢）⇒ 两个后端早已一致，错的只是那两句文案。
  改文案后 `一致 4 | 分叉 0`。这条实证比任何注释都硬，所以 BUG-22 的卡里连「再生命令」都写了。
- 「`void` 是缺口」「`ref`/`with` 是 cy 独有缺陷」两类初判同样在上一轮已撤回，本轮不再重复入账；

## 八、追加增量：cy 面的 `--test` 执行面（销 BUG-18）

主表 §五 落盘之后又补了一条**特性**（不是量具）：cy 后端此前没有 `--test` 执行面，
`lzc <件>.lz --backend=cython --test` 要么打一行 `Generated` 后 rc=0（＝装作跑过），
要么在 T0r7 主表那一遍是「带原因拒绝」。这一轮按 BUG-13 验证过的顺序补完：
**先造能红的调用面判据，再动产品码。**

- 判据：`CY/scripts/cy_test_gate.py`（打真入口，不是单测）。三格语料 + 四支罐头对照
  （`--selfcheck`：rc=0 但没有任何 test 行 / 只有拒绝文案 / 报 1 failed 却没有 FAILED 行
  必须全判红，罐头绿证必须判绿——否则「我会判状态」这句是假命题）。
  逐条断言的是**行**而不是 rc：`test <名> ... ok`、`test <名> ... FAILED`、
  汇总行 `test result: <ok|FAILED>. P passed; F failed; …`，再加 rc 的零/非零期望。
  只比 rc 会把「拒绝」（rc=1）读成「测试失败」，把「什么都没跑」（rc=0）读成「全过」。
- 红证（判据先跑在产品码之前）：`TEMP/bug18-judge-before-0802.log` ⇒ 合计 3 格，红 3 格；stdout 逐字是那句拒绝文案。
- 绿证（发射运行器 + 宿主之后同一条判据）：`TEMP/bug18-judge-after-0837.log` ⇒ 合计 3 格，红 0 格，逐格 pass_only rc=0、one_fails rc=1、setup_visible rc=0。
- 落点（行号现 grep 取到，逐条在场）：`src/ir/codegen_cython.rs`
  的 `set_test_runner`/`emit_test_runner`/`test_names` 登记与 `__main__` 入口；
  `src/main.rs` 的 `run_cy_test_mode`/`cy_python_program`/`CY_TEST_HOST`。
  宿主走 pyximport 并把 .pyx 复制成 `_lzcyt_<stem>` 别名——**别名不是洁癖**：
  pyx 的 finder 排在 `sys.meta_path` 末尾，同名 site-packages/stdlib 包会先命中
  （cy L3 实测过 `enum`/`struct`/`test_suite` 被抢出假绿），所以导入回来还要验「加载来源
  就在本次产物目录里」，否则宿主退出码 4 ⇒ CLI 报「未能给出判定」而不是报绿。
  **这条归属判据在同轮里被我自己改过两次**（红绿之间的一次返工，勘误已写进台账小记）：
  ① 第一版读 `mod.__file__`，而 LZ 产物自己在模块级发 `__file__ = "<源件>.lz"` ⇒
  真产物被判成冒名、每次 rc=4 假红；改用导入机写入的 `__spec__.origin`（退路 `__loader__.path`）。
  ② 归属比较原用字符串前缀，而 `.../target/cy-testface/…` 以 `.../target/cy-test` 开头却是隔壁目录
  ⇒ 门禁那一遍其实是被这条**假绿**放过的；改用 `os.path.commonpath`。两支各配一支对照
  （判据 `--selfcheck` 的 C4：真归属放行＋兄弟目录与仓根冒名都拒），且 C4 是**从 `src/main.rs`
  里抠出内嵌宿主源码再 exec** 来测的——判据侧另抄一份同名实现，测不到出货面。
  ③ 宿主跑两遍：第一遍把 pyximport/setuptools/MSVC 的编译日志关进子进程丢弃，否则冷缓存那遍的
  链接器日志混进 stdout ⇒ 跨端 stdout 不可比。逐字绿证另存
  `TEMP/bug18-cli-mixed-after-0837.log`（`test bad ... FAILED` + `❌ Some tests failed`，rc=1）与
  `TEMP/bug18-cli-pass-0837.log`（两条 ok + `✅ All tests passed`，rc=0）。
