## ① 这轮做了什么

1. **补上方法表里缺失的整条臂 `.to_string()`**。普查（`TEMP/census-r14-085959.log`）显示补臂前表里**没有**这一条，
   于是所有内建接收者上的 `.to_string()` 落到通用尾巴，发射成 Python 的 `x.to_string()`
   ⇒ 运行期 AttributeError。规范把它写成内建（`SYNTAX/00-词法基础.md:187`、
   `SYNTAX/01-类型系统.md:735`「对应 Display trait 的 to_string」）。
2. **print 的实参分 Display／Debug 两档**（上一轮落改，本轮钉锁）。cy 原先无条件套 `_lz_dbg`，
   与规范 `SYNTAX/99-内置预导入库.md:50`（`print(...)` → `{}`）和 Rust 面逐实参分档
   （`src/ir/codegen/expr_gen.rs:76`）不一致。
3. **`_lz_dbg` 的浮点指数拼法**：Python 的 `repr` 给 `1e+16`／`1e-05`，Rust 的 `{:?}` 给 `1e16`／`1e-5`；
   两侧都不报错、只是值不一样，这一类比运行期异常更难发现 ⇒ 按指数梯逐值实测后才改。
4. **五支常驻锁 + 承重证明**，形状门的名单补上 `to_string`（现在 20 条臂、prelude 22 支垫片）。
5. **顺带把 L3 的一次红盘追成一条跨轮结论**：现存 golden 里有一批是陈旧的（见 ⑥）。

## ⑥ 附带抓出：**一批陈旧 golden 被两处旧错互相印证盖住了**

对齐 print 口径后 L3 首跑点名 39 件输出不符（`TEMP/snap-r14-l2l3A-r14.log`）。逐件实测

陈旧的含义很具体：`.exp` 里裸字符串**带引号**（`"B"`），而今天 rust 面给 `B`、cy 面也给 `B`
⇒ golden 封在「rust 面对裸字符串也发 `{:?}`」的年代；后来 rust 面改了口径而 `.exp` 没人重封，
恰好 cy 当时「一律 Debug」与那份陈旧逐字相等 ⇒ L3 一直是绿的，两处旧错互相把对方盖住
（这是「全局缓解不得遮掉在册形态」的镜像）。

第一版形状门，只认「旧行 == 新行整体加引号」，于是把 `42 "hello"` → `42 hello` 这类**多实参那一行**
误判成「形状不认识」（4 件）。第二档补的是「两边的 `"` 全摘掉后逐字相等、且旧侧引号更多」，

`32 + 4 == 36` 这句不是散文：干跑点名的 STALE∪SHAPE **件名集合**
必须与 APPLY 点名的重封集合逐件相等（本件按集合对表，不等就 REFUSE），且 APPLY 里 SHAPE 档为 0。
