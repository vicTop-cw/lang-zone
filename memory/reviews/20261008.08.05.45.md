## 一、这一轮量到的东西：三条臂连「接收者是谁」都不看

cy 的 `Option` 表示是「裸值／Python `None`／垫片 `_LzNoneCls`」——那是**值表示**。
`is_none`/`is_some`/`expect` 三条臂当初按这条立论写成**无条件**（`"is_none" => return format!("({} is None)", r)`），
于是它同时也是「不管接收者是谁，都把一次方法调用换成一次 identity 比较」。
上一轮（T0r12）已经给 `clone`/`unwrap`/`try_into` 三支无条件臂补了「本类有没有定义这个名字」的闸门，
并且**明写了没为 `expect` 取数**——本轮先取数，再按同一纪律修。

## 二、BUG-40：三条无条件臂吃掉用户类同名方法（有 oracle 的三支）

| 探针 | 修前（逐字，取自 `TEMP/uncond-x13-before-r13.log`） | 修后 |
|---|---|---|
| `x_expect_static` | rust `'42\n'` / cy 'Cfg { n: 21 }\n' —— **不报错，打印的是对象而不是返回值**；发射形态 ``(Cfg(n = 21) if Cfg(n = 21) is not None else __lz_expect_fail("m"))))`` | cy '42\n' ⇒ 与 rust 逐字一致 |
| `x_isnone_static` | rust `'true\n'` / cy 'false\n'；发射 `print(_lz_dbg((Cfg(n = 1) is None)))` | cy 'true\n' ⇒ 一致 |
| `x_issome_static` | rust `'false\n'` / cy `'true\n'`（同一条臂的镜像） | 一致 |
| `x_expect_duck`／`x_isnone_duck`（动态接收者） | rust `'42\n'`／`'true\n'` 而 cy `'Cfg { n: 21 }\n'`／`'false\n'` | 发 `_lz_exp`／`_lz_isnone` ⇒ 一致 |

修法与上一轮同一条纪律：闸门从「无条件」换成 `!user_class_has_method(cg, &receiver.ty, <名字>)`
（**本类有没有定义这个名字**），动态接收者（`ty_is_dynamic_receiver`）发运行时助手
`_lz_isnone`／`_lz_issome`／`_lz_exp`。助手要**名单与属性都在**才走方法那一支：
`is_none` 的兜底本来就是表达式（`o is None`）而不是透传，只按属性存在判会把任何恰好带
`is_none` 属性的对象当成 LZ Option——这与 BUG-37 里 `remove` 必须按名单是同一条判据的两种朝向。

## 三、BUG-41：`.expect()` 的发射把接收者拼两遍（本轮自己找到的第二条）

旧发射是 `({r} if {r} is not None else __lz_expect_fail({m}))`——同一个表达式**拼两次**。
r 是变量时无害；r 带副作用时就是跑两遍，而**退出码仍是 0**。实测（同一支 `x_expect_twice`，
`def mk()` 的体里有一句 `print("mk")`）：修前 cy stdout '"mk"\n"mk"\n5\n'，修后 '"mk"\n5\n'，
发射形态从 ``(Cfg(n = 21) if Cfg(n = 21) is not None else __lz_expect_fail("m"))))`` 变成 `__lz_expect(mk(), "m")))`。静态那支的旧形态里也能直接看见双拼：``(Cfg(n = 21) if Cfg(n = 21) is not None else __lz_expect_fail("m"))))``。

这条**没有跨后端对照**：同一份源码在 rust 面恒 E0308（下面 §五 的 BUG-42），
所以凭据只能是 cy 自己的 stdout 与发射形态——语料 `expect_receiver_once.lz` 故意不封盘、
登记进 `NO_ORACLE_EXPLAINED`，行为面由发射形态锁 `cy_expect_evaluates_receiver_once` 数
「那一行里 `mk()` 只出现一次」。

## 五、rust 侧在册的两条（本车道不改 `src/ir/codegen/mod.rs`、`src/ir/builder/`）

- **BUG-42**：`Option::expect(self, msg: &str)` 被喂 `.to_string()` ⇒ 整个 `.expect` 族在 rust 面恒
  E0308。生成的那一行是 `println!("{:?}", mk().expect("m".to_string()));`，rustc 指认 ``expected `&str`, found `String```
  （完整诊断在 `TEMP/uncond-x13-rsdetail-r13.log`）。后果：**这一族语料永远取不到 oracle**，`.expect` 的行为凭据只剩
  cy 侧的自证——这不是等价证据，缺口写在卡里。
- **BUG-43**：内建 `remove` 的**实参**被无条件强转 `as usize`，不看接收者 ⇒ 用户类自带的
  `remove(ref self, i: int)` 编不出：方法定义是 `fn remove(&self, i: i64) -> i64 {`，
  调用点却是 `println!("{:?}", Cfg { n: 1i64 }.remove((3i64 as usize)));`，rustc 指认 ``expected `i64`, found `usize```。与 BUG-39 是同一张表的同一个缺闸门，只是机制不同
  （BUG-39 换名字，这条换实参类型）。`x_remove_static`/`x_remove_duck` 两支 cy=OK 而 rust=RUSTC_FAIL，
  所以本轮语料不含 remove 那支（封盘要求两后端逐字一致）。
