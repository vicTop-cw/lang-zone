## 一、告警普查：量到 0 行告警，而这个读数是「看得见对照」的读法

取数面与门禁逐字同构（`python -m cython -3 --module-name cy_gate_gen <绝对 pyx>`，cwd = pyx 目录），
语料整树镜像后逐件转译——第一版按件建隔离目录，`99_bootstrap/import_runtime.lz` 因找不到同目录
兄弟模块而 `TRANSPILE_FAIL`，那是**取数面的缺陷**，不是产品的（L2 的在册失败清单一直是空的）。

- 工具链：TOOLCHAIN: Cython version 3.2.2
- 正向对照一（BUG-13 原样形状）：CONTROL ctrl_warn.pyx  期望 warning        rc=0(要 0) 命中=True 实际前置词集合=['warning']
- 正向对照二（定位错误 + rc!=0）：CONTROL ctrl_err.pyx   期望 (无前置词)         rc=1(要 1) 命中=True 实际前置词集合=['(无前置词)']
- 逐件合计：合计 81 件 | clean 81 | 有告警 0 | rc!=0 0 | 转译失败 0 || 分组行 0（逐行累加 0）| 类别 0
- 自证行：SELFCHK OK: 对照 2/2 命中、两条累加路径一致、四态覆盖满 81 件

**检测面的边界，写在判据的注释里而不是靠人记**（实测 cy-warn-shapes-182731.log）：同一条命令下
`cdef int spam(int x)` **连 `-Wextra` 都不打印 performance hint**（`cdef_nogilless         flags=-        rc=0 行数= 0`），
而标注里的未知类型会打印（`unknown_ret_type       flags=-        rc=0 行数= 1 warning: unknown_ret_type.pyx:1:12: Unknown type declaration 'nosuchtype' in annotation, ignoring`）。⇒ 本判据的检测面只有 `warning:` 与带定位的错误；
「没有告警」不等于「产物没有优化空间」，只等于「这一面没有」。

## 二、L2 新判据：`warning:` 行是拒绝项，基线 0，配 in-test 对照

`tests/cy_codegen_gate.rs`：

- `cython_warning_line()` 只认 `warning: <路径>.pyx:<行>:<列>: <消息>` 一种形状，其余 stderr（`Error compiling`、
  代码回显、续行）**不当告警算**——免得把「长得像」读成「是」。
- `assert_cython_warning_channel()` 在语料循环**之前**跑对照件：解析不出告警行就当场 panic
  ⇒ 「语料没有告警」永远不可能靠取数面失明来成立。
- 语料侧 `warned` 与 `failed` **各自记账**（rc=0 也能带 warning），汇总行打印 `Cython 告警行 N`，
  `assert warned.is_empty()` 逐字带出每一行。
- **没有告警豁免清单**：告警说的是「写上去的东西没生效」，开清单等于把它登记成常态。

对照件让这条判据的「可红性」每次跑都在场，不需要额外变异产品码（上一轮那种同码变异红证被权限
分类器拦下，这里根本不依赖它）。

## 三、L3 汇总行的过度主张，用一张 oracle 登记表堵住

改之前 L3 只报 `执行通过 N`，而 N 里混着两类：**逐字比对过的**和**只证明跑完没抛的**。
本轮实测二者分别 75 与 6（逐字 `分类计数 {'C': 3, 'A': 3} | 件数 6`）。新增 `NO_ORACLE_EXPLAINED` 登记表（6 条，每条带原因）＋
汇总行拆成「逐字比对」与「无 oracle 仅跑通」两栏＋双向对表：

- 件无 `.exp` 又不在表里 ⇒ 红（覆盖悄悄变小）
- 表里登记了但 `.exp` 已存在 ⇒ 红（表陈旧，该件其实已覆盖）
- `逐字比对 + 无 oracle != 语料件数` ⇒ 红（有件两头都不沾）

6 件的成因（逐字，来自 `TEMP/why-unsealed-r9.log`，该件由 `TEMP/why_unsealed_r9.py` 现跑）：
  C_参考面缺(RUSTC_FAIL/OK)      01_basics/literals.lz
  A_空输出                      04_functions/generic_min.lz
  A_空输出                      05_expressions/elif_test.lz
  A_空输出                      07_data_structures/enum_minimal.lz
  C_参考面缺(RUSTC_FAIL/OK)      15_feature_matrix/named_args.lz
  C_参考面缺(RUSTC_FAIL/OK)      99_bootstrap/lz_std.lz

其中 3 件是 **rust 面取不到 oracle**（已分别在册 BUG-29 / BUG-24 / BUG-30，本车道不改 `src/ir/codegen/mod.rs`），
3 件是两侧 stdout 恒为空——空 golden 不承重，封了反而把「有文件」当成「有覆盖」。
登记表的转正前置与卡片里写的一致：rust 面能编之后用 `python -u TEMP/seal_missing_exp.py` 补封
（该工具不会覆盖已存在的 `.exp`），补封后必须同轮把该条从表里移出。
