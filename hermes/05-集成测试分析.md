## 失败分类

### 一、与本次架构变动**无关**（95% 的失败）

#### 1. 未实现特性 — 测试超前于编译器

| 测试 | 使用的特性 | 现状 |
|------|-----------|:--:|
| ASY-001~006 | `async`/`await` | codegen 未实现 |
| BLD-GEN-001/002 | `*:` 构建块 | parser 拒绝 BuildGen token |
| DCL-MG-001~006 | `magic` | 魔法方法引擎未完整实现 |

#### 2. 语法规范不兼容 — 测试用了废弃/不同语法

| 测试 | 问题 | 现状 |
|------|------|:--:|
| DCL-EN-001 | `enum Color = Red \| Green \| Blue` | LZ 枚举用缩进列表 `enum Color: Red\n Green` |
| DCL-EN-002~004 | 类似枚举语法错误 | 同上 |
| DCL-FN-010 | `def f() raises str:` 无 `=` | 应为 `def f() raises str = expr` |
| DCL-FN-011 | `def f():` 无体 | 缺少函数体 |
| DCL-FN-013 | `def f[T]()` Rust 风格泛型 | LZ 用 `def f<T>()` |

#### 3. 代码生成正确但 rustc 层面失败 — 无对应 Rust API

| 测试 | 生成的 Rust | 问题 |
|------|-----------|------|
| DCL-IM-002 | `use std::io::print;` | `print` 不在 `std::io` 中 |
| DCL-IM-003 | `V.Vec_new()` | 不存在 `Vec_new` 函数 |
| DCL-ST-002 | struct 带方法 | method codegen 某些模式不完整 |

### 二、与本次架构变动**有关**（5% 的失败）

| 测试 | 原因 | 架构变动 |
|------|------|:--:|
| ASY-002 | S006 unused function | strict 模式默认开启 |
| DCL-IM-001 | `::` 废弃语法 | `::` → `.` 统一 |

**结论：集成测试低通过率主要因为测试超前于编译器实现，与本次架构重构无关。**

## 修正计划

### Phase 1 — 立即修（架构变动导致的）

| 动作 | 文件 |
|------|------|
| DCL-IM-001: `::` → `.` 迁移 | 批量替换集成测试中的 `::` |
| 未使用函数加 `@unsafe` 或 `_` 前缀 | ASY-002 等 |

### Phase 2 — 清理不兼容测试

- 删除用废弃语法的测试（DCL-EN-* 的 pipe 枚举语法）
- 修正 DCL-FN-010: 加 `=`
- 标记 async/magic/build 测试为 "skipped — 未实现"

### Phase 3 — 保留有用测试

保留并修正能通过的测试：
- DCL-FN-001/002 (simple def)
- DCL-IM-001 (after :: → . fix)
- DCL-ST-001 (simple struct)

### 预期修复后通过率

```
当前: 15/60  (25%)
Phase 1+2 后: ~30/60 (50%)
删除不兼容后保留: ~20 有用测试 (100% 通过)
```
