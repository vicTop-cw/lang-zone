# Lang-Zone 编译器包体系架构设计

> **设计参考**: Python 3.13 标准库分层架构 (`token` → `ast` → `symtable` → `compile`)
> **设计原则**: 单向依赖、接口隔离、零循环引用、分层测试
> **版本**: v1.0 | **日期**: 2026-07-23

---

## 一、分层架构总览

参考 Python 标准库"自底向上、逐层抽象"的包设计哲学，Lang-Zone 编译器工具链划分为 **5 个架构层**：

```
┌─────────────────────────────────────────────────────────────────────┐
│                         L5  应用入口层                               │
│  main.rs  ────  CLI 命令行接口（编译流水线编排）                       │
├─────────────────────────────────────────────────────────────────────┤
│                         L4  代码生成层                               │
│  codegen/  ──  AST → Rust 源码转译                                  │
│  ┌──────────┬──────────┬──────────┬──────────┬──────────┐          │
│  │  decl    │  func    │  stmt    │  expr    │ builders │          │
│  │  (声明)  │  (函数)  │  (语句)  │  (表达式)│ (构建块) │          │
│  │  magic   │ helpers  │          │          │          │          │
│  └──────────┴──────────┴──────────┴──────────┴──────────┘          │
├─────────────────────────────────────────────────────────────────────┤
│                         L3  语义与类型层                             │
│  ┌──────────────┬──────────────┬──────────────────────┐            │
│  │  types/      │  magic/      │  bridge/             │            │
│  │  类型系统    │  魔法函数    │  外部交互桥接        │            │
│  ├──────────────┼──────────────┼──────────────────────┤            │
│  │ · 类型定义   │ · 签名获取   │ · core    (统一抽象) │            │
│  │ · 类型映射   │ · 方法解析   │ · source  (源码映射) │            │
│  │ · 类型转换   │ · trait 分发 │ · ffi     (C ABI)    │            │
│  │ · 类型擦除   │              │ · cli     (IPC)      │            │
│  └──────────────┴──────────────┴──────────────────────┘            │
├─────────────────────────────────────────────────────────────────────┤
│                         L2  语法与宏层                               │
│  ┌──────────────┬──────────────┬──────────────┐                    │
│  │  parser/     │  ast/        │  macro/      │                    │
│  │  语法分析器  │  抽象语法树  │  宏系统      │                    │
│  ├──────────────┼──────────────┼──────────────┤                    │
│  │ · Parser     │ · Expr/Stmt  │ · expand     │                    │
│  │ · stmt/expr  │ · Pattern    │ · interp     │                    │
│  │ · helpers    │ · Module     │ · group      │                    │
│  └──────────────┴──────────────┴──────────────┘                    │
├─────────────────────────────────────────────────────────────────────┤
│                         L1  词法层                                   │
│  ┌──────────────┬──────────────┬──────────────┐                    │
│  │  lexer/      │  config/     │  util/       │                    │
│  │  词法分析    │  系统配置    │  基础工具    │                    │
│  ├──────────────┼──────────────┼──────────────┤                    │
│  │ · Token 定义 │ · TOML 解析  │ · 导入机制   │                    │
│  │ · Lexer      │ · 路径管理   │ · 错误类型   │                    │
│  └──────────────┴──────────────┴──────────────┘                    │
└─────────────────────────────────────────────────────────────────────┘
```

**核心法则**：上层依赖下层，下层绝不引用上层；同层模块通过 trait 接口通信。

## 二、各层包职责详设

### L1 词法层 — 编译器的"眼睛"

| 包路径 | 职责 | 对标 Python | 关键导出 |
|--------|------|-------------|---------|
| `lexer/token.rs` | 定义全部 Token 变体（80+），缩进虚拟 Token | `token.py` — `tok_name` 字典 | `pub enum Token` |
| `lexer/lexer.rs` | 源码 → Token 流的完整词法分析 | `tokenize.py` — `generate_tokens()` | `pub struct Lexer`, `tokenize()` |
| `lexer/mod.rs` | 重导出 + 字符分类辅助（`is_build_ws`） | — | `pub use token::*; pub use lexer::*` |
| `lexer/span.rs` | 源码位置信息（文件/行/列），用于错误报告 | `tokenize.py` — `TokenInfo` | `pub struct Span` |
| `config/mod.rs` | 系统配置管理：项目级 `.lzconfig` TOML 解析 | `configparser` / `tomllib` | `pub struct ProjectConfig` |
| `config/paths.rs` | 标准库路径解析、模块搜索路径 | `sys.path` | `pub fn resolve_std_dir()` |
| `util/import.rs` | 模块导入机制：路径解析、循环依赖检测 | `importlib` | `pub struct ImportResolver` |
| `util/mini_toml.rs` | 零依赖 TOML 解析器（自实现） | `tomllib` | `pub fn parse()` |
| `util/error.rs` | 统一错误类型：词法/语法/语义/IO 错误 | `SyntaxError`, `ImportError` | `pub enum CompilerError` |

**层内依赖**：
```
token ← lexer (使用 Token)
token ← span (Token 携带 Span)
config/paths ← config/mod (路径管理)
```

## 三、依赖关系矩阵（单向无环）

```
                    ┌─────────────────────────────────────────┐
                    │              L5  main.rs / lib.rs       │
                    │             (编排所有层)                 │
                    └────┬────┬────┬────┬────┬────┬────┬─────┘
                         │    │    │    │    │    │    │
              ┌──────────┘    │    │    │    │    │    └──────────┐
              ▼               ▼    ▼    ▼    ▼    ▼               ▼
    ┌─────────────┐  ┌─────────────────────────┐    ┌──────────────────┐
    │   codegen/  │  │  L3  types/ magic/ bridge│   │   macro/         │
    │   (L4)      │  │      (语义 + 桥接)        │   │   (L2.3 宏系统)   │
    └──────┬──────┘  └───────────┬─────────────┘    └────────┬─────────┘
           │                     │                           │
           └──────────┬──────────┘          ┌────────────────┘
                      ▼                     ▼
              ┌─────────────────────────────────────┐
              │    L2  parser/ + ast/               │
              │    (语法分析 + 抽象语法树)            │
              └─────────────────┬───────────────────┘
                                │
                                ▼
              ┌─────────────────────────────────────┐
              │   L1  lexer/ + config/ + util/      │
              │   (词法分析 + 配置 + 基础工具)        │
              └─────────────────────────────────────┘
```

**依赖方向**：L5 → L4 → L3 → L2 → L1（严格单向，无反向依赖）

**同层规则**：
- `bridge/core.rs` 不依赖任何 bridge 子模块（被其他子模块依赖）
- `ast/` 只被 `parser/` 和 `codegen/` 依赖，自身仅依赖 `types/`
- `types/` 仅依赖 `lexer/`（通过 `Spanned<T>` 携带位置信息）

## 四、模块间边界定义（接口契约）

### 4.1 L1 ↔ L2 边界：`Token` 接口

```rust
// L1 导出
pub enum Token { /* 80+ variants */ }
impl Token { pub fn to_string(&self) -> String; }

pub struct Lexer;
impl Lexer {
    pub fn new(source: &str) -> Self;
    pub fn tokenize(&mut self) -> Vec<Token>;  // 核心 API
}

// L2 消费
// parser/parser.rs
use crate::lexer::Token;
use crate::lexer::Lexer;
```

### 4.2 L2 ↔ L3 边界：`Type` + `MagicEngine` 接口

```rust
// L2 AST 引用 L3 类型
// ast/decl.rs
use crate::types::Type;  // Function.return_type: Option<Type>

// L3 魔法引擎消费 L2 AST
// magic/engine.rs
use crate::ast::Function;  // 遍历函数列表寻找 __xxx__ 方法
```

### 4.3 L3 ↔ L4 边界：`Bridge` trait + `BridgeRegistry`

```rust
// bridge/core.rs
pub trait Bridge {
    fn name(&self) -> &str;
    fn resolve_import_full(&self, path: &[String], items: &[String]) -> ImportResolveResult;
    fn resolve_call(&self, name: &str, args: &[String]) -> CallResolveResult;
    fn resolve_type(&self, name: &str) -> Option<String>;
}

pub struct BridgeRegistry;
impl BridgeRegistry {
    pub fn register(&mut self, bridge: Box<dyn Bridge>);
    pub fn resolve_import_full(...) -> ImportResolveResult;
}

// codegen/mod.rs
use crate::bridge::core::{BridgeRegistry, Bridge};
```

### 4.4 L4 ↔ L5 边界：`CodeGen::generate()`

```rust
// codegen/mod.rs
pub struct CodeGen;
impl CodeGen {
    pub fn generate(
        module: &Module,
        std_dir: Option<PathBuf>,
        allow_rustc_private: bool,
        rustc_version: String,
    ) -> String;
}

// main.rs
use lang_zong::codegen::CodeGen;
let rust_code = CodeGen::generate(&module, std_dir, allow_rustc_private, rustc_version);
```

## 六、Python 标准库对标参考

| Lang-Zone 模块 | Python 对标 | 设计借鉴 |
|----------------|-------------|---------|
| `lexer/token.rs` | `token.py` (`tok_name`, `ISTERMINAL`) | 所有 Token 定义放在单独模块，不混入解析逻辑 |
| `lexer/lexer.rs` | `tokenize.py` (`generate_tokens`) | 词法分析器作为独立层，输出标准化 Token 流 |
| `ast/expr.rs`, `ast/stmt.rs` | `ast.py` (`ast.Expr`, `ast.stmt`) | AST 节点按语义分类（表达式/语句/声明），每种节点独立类型 |
| `ast/visit.rs` | `ast.NodeVisitor`, `ast.NodeTransformer` | Visitor 模式分离遍历逻辑与节点定义 |
| `parser/` | `parser.py` (CPython PEG parser) | 解析器依赖 AST 和 Token，不反向依赖 |
| `types/def.rs` | `types.py` / `typing.py` | 类型作为独立抽象层，被 AST 和 codegen 同时引用 |
| `magic/engine.rs` | `operator.py` (`__add__` → `+` 映射) | 操作符 → trait 映射表独立管理 |
| `bridge/core.rs` | `ctypes` / `cffi` | 统一 Bridge trait，具体实现（Source/FFI/CLI）按等级分层 |
| `util/mini_toml.rs` | `tomllib` (3.11+) | 零依赖 TOML 解析，仅用于 std bridge 配置 |
| `config/` | `sysconfig` / `sys.path` | 模块搜索路径、标准库位置集中管理 |

## 七、编译流水线与包依赖关系

```
.lz 源文件
    │
    ▼
┌──────────────────────────────────────────────────┐
│ L1: Lexer::new(source).tokenize()                │
│     输出: Vec<Token>                             │
│     依赖: config/paths (文件路径解析)              │
└──────────────────┬───────────────────────────────┘
                   ▼
┌──────────────────────────────────────────────────┐
│ L2: MacroExpander::expand(tokens)   [宏系统]      │
│     TokenGroup::classify() → Expr/Decl/Stmt       │
│     输出: Vec<Token> (宏展开后)                    │
│     依赖: macro/interp (编译期执行宏体)             │
└──────────────────┬───────────────────────────────┘
                   ▼
┌──────────────────────────────────────────────────┐
│ L2: Parser::new(tokens).parse_module()            │
│     输出: ast::Module                             │
│     依赖: ast/* (AST 节点定义), types/def (Type)   │
└──────────────────┬───────────────────────────────┘
                   ▼
┌──────────────────────────────────────────────────┐
│ L3: MagicEngine::resolve(__xxx__)                 │
│     输出: MagicEntry (trait_path, method)         │
│     BridgeRegistry::resolve_import_full(path)     │
│     输出: ImportResolveResult (rust_path, shim)   │
└──────────────────┬───────────────────────────────┘
                   ▼
┌──────────────────────────────────────────────────┐
│ L4: CodeGen::generate(&module, std_dir, ...)      │
│     输出: String (Rust 源码)                       │
│     依赖: ast, types, magic, bridge, codegen/*    │
└──────────────────┬───────────────────────────────┘
                   ▼
              输出 .rs 文件
```
