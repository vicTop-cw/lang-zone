## 一、跨文档矛盾（严重）

### 1. 运算符优先级表两套体系：`12-操作符.md` vs `附录B`

两处「权威」优先级表对同一批运算符给出**不同优先级数字**：

| 运算符 | `12-操作符.md` §二（L374-393） | `附录B` §三（L154-177） |
|--------|:---:|:---:|
| 成员访问 `.` `?.` | 16 | **17** |
| 等于 `==` `!=` | 6（与比较合并） | **5**（比较 6 / 等于 5 拆分） |
| 管道 `\|>` | 1 | **2** |
| 海象 `:=` | 2 | **1** |
| 赋值 `=` | 0 | **1** |
| 三元 `if/else` | **表中无此项** | 1 |
| 范围 `..` `..=` | 表中无此项 | 2 |

同一语言两种优先级数字，直接决定 `a = b |> c == d` 这类表达式如何结合——**哪份是权威？**

### 2. `12-操作符.md` 内部自相矛盾（`:=` 的优先级描述）

- L362（§1.20）：`右结合，优先级最低（仅高于管道 |>），见 §二 优先级表`
- L376-378（§二 表）：`0: = · 1: |> · 2: :=`

`:=` 在表中是 **2 级**（高于 0 级 `=` 和 1 级 `|>`），文本却说「优先级最低」——**文本与自己的表矛盾**。

### 7. `附录B` 关键字表中混入非关键字（自相矛盾）

- L35：关键字表内列出 `| Number | 内置数值 trait | 泛型约束 |`

## 二、文档内部矛盾（中等）

### 8. `06a-struct.md`：字段可见性新规则与全文示例冲突

- 新增 §2.5（L101-125）：「LZ **没有 `pub` 关键字**。字段可见性**完全由字段名前缀**表达」——只定义 `.name`（公开）/ `._name`（私有）两种写法
- 但同文 §2.1（L14-17）`struct Point = x: f64`、§2.3（L82-89）`struct Example<T> = id: int ...` 全部使用**无前缀**字段

**无前缀字段（`x: f64`）在 §2.5 的规则下属于什么可见性？文档未定义。** 要么「无前缀 = 默认公开」补进 2.5，要么全文示例统一改为 `.x`——当前两种写法并存且语义不明。

### 10. `14-生成器.md` 两处歧义

- L404 附近表格：`yield (2,)` 标为非法；同文 §5.2（L291-294）示例 `xs = one *:` 使用裸 `yield` 调用——单元素元组参数包的合法性判定与「应显式用 `yield 2`」的建议自相矛盾
- L68 vs L600：§2.3 说 iterator 的 `return`「与 `raise` 语义等价（见 §8.3）」并注明「以下 return 行为适用于 def 生成器（向后兼容）」，§8.7 对比表又写「允许（等价于 raise）」——def/iterator 两套 return 语义分层不清

---

### 11. `13-指针与引用.md` / `99-内置预导入库.md`：Cell/RefCell 被列为「指针类型」

- `13-指针与引用.md:20-21`：指针类型表含 `Cell<T>` / `RefCell<T>`
- `99-内置预导入库.md:19-21`：同样列出

Cell/RefCell 是**内部可变性容器**，非 Box/Rc/Arc 式堆指针；与智能指针并列为「指针类型」在语义上不准确。

## 三、结构性问题（轻）

### 12. `03-函数.md` 索引页成为孤儿文档

- `15-测试框架.md`：v3.2 · 2026-07-28
- `README.md:3`：「基于编译器源码审计 · 2026-07-27」

版本号/日期无法反映文档实际更新，交叉审计时无法判断哪份是新的。
