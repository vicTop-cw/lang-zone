# 设计决策：闭包胖箭头 `=>`（可选）与无参闭包 `| |`

**日期**: 2026-07-31
**状态**: 已决策（语法设计定稿，工程实现待执行）
**提出**: 用户提案「闭包都加胖箭头，无参函数中间需要空格 `| |`，逻辑或需要紧贴 `||`，加箭头后可换行缩进和普通函数一样」

## 决策

1. **闭包胖箭头 `=>` 可选**：`|x| body`（旧写法，兼容）与 `|x| => body`（新写法）**并存**，不强制迁移。
   - `=>` 后支持换行缩进块体，与 `def` 函数一致：
     ```lz
     let compute = |a, b| =>
         c = a + b
         c * 2
     ```
2. **无参闭包用 `| |`（中间空格）**，与逻辑或 `||`（紧贴）靠空白区分：
   ```lz
   let f = | | => 42          // 无参闭包（中间空格）
   let g = a || b             // 逻辑或（紧贴）
   ```
3. 逻辑或必须紧贴 `||`（已如此，lexer 贪婪匹配），**不允许** `| |` 表示逻辑或。

## 现状核实（实证）

| 项 | 现状 | 证据 |
|----|------|------|
| 文档闭包语法 | `|x| x + 1` / `|x, y| x + y`，多行体 `|a, b|` 换行缩进；**无参闭包无示例** | `SYNTAX/03e-复合综合.md:131-133,155` |
| lexer 对 `\|` | `\|\|` 紧贴 → `PipePipe`（逻辑或）；`\|>` → `Pipe`（管道）；`\|=` → `OrEq`；单 `\|` → `Pipe_` | `src/lexer/lexer.rs:685-700` |
| parser lambda | `Pipe_` 开头进闭包分支，收集参数直到下一个 `Pipe_`，然后 `parse_expr` 解析 body；**无胖箭头分支** | `src/parser/expr.rs:809-821` |

**关键结论**：
- `| |`（空格）在词法上天然成为两个 `Pipe_` token，parser 闭包分支 `while !check(&Token::Pipe_)` 会立即遇到第二个 `|` → 空参数闭包——**当前即可解析**，只是文档未定义。
- 正因 `||` 已被逻辑或占用，**当前语言写不出无参闭包**（`||` 会被当逻辑或）；`| |` 正好补上该空缺。
- 胖箭头 `=>`（`FatArrow` token，`src/lexer/token.rs:79`）已有（match case 用），parser 闭包分支消费 `Pipe_` 后检查/跳过 `FatArrow` 即可。

## 词法/语法规则（定稿）

| 写法 | 含义 | 词法产物 |
|------|------|---------|
| `\|\|`（紧贴） | 逻辑或 | `PipePipe` 单 token |
| `\| \|`（中间空格） | 无参闭包定界符 | 两个 `Pipe_` |
| `\|x\| body` | 单参闭包（无箭头，旧式） | `Pipe_` … `Pipe_` + body |
| `\|x\| => body` | 单参闭包（胖箭头，新式） | `Pipe_` … `Pipe_` + `FatArrow` + body |
| `\|x\| =>\n    body` | 多行块体闭包 | 同上 + 缩进块 |

**歧义排查**：`a | | b`（空格分隔两个 `|`）会被解析为闭包而非位或——位或 `|` 是二元运算，要求两侧都有操作数；若用户在表达式中间写 `| |`，parser 的 `Pipe_` 入口会进入闭包分支并报参数错误。此歧义可接受（`| |` 语义已指定为无参闭包定界符）。

## 验证

- `| | => 42` 可解析为无参闭包，`a || b` 仍为逻辑或，两者不冲突。

- `|x| =>\n    body` 多行缩进块体生成正确 Rust 闭包。
