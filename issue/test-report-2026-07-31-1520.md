## 二、新发现 Bug

### 🔴 P1-1: IR codegen `!` 一元运算符优先级错误

**严重等级**: 🔴 P1 — 生成语义错误的 Rust 代码

**复现步骤**:
```lz
def main() =
    x = 5
    y = 3
    if not (x == y):
        print("not equal")
```
编译: `lang-zone test.lz --ir-codegen`

**实际结果**: 生成 `if !x == y { ... }` — 在 Rust 中 `!` 的优先级高于 `==`，解析为 `(!x) == y`
**预期结果**: `if !(x == y) { ... }` 或 `if x != y { ... }`
**影响**: 所有使用 `not` 否定比较表达式在 IR 路线生成的 Rust 代码语义错误。`check` 表达式也因此受影响（`if !x >= 0` 而非 `if !(x >= 0)`）

**根因**: `src/ir/codegen.rs:665` — `ExprKind::UnOp` 无条件生成 `{op}{operand}`，当 operand 是二元运算符时缺少括号

**修复建议**: 在 `gen_expr` 的 `UnOp` 分支中，当 `op` 为 `Not` 且 `operand` 为 `BinOp` 时包裹括号

### 🔴 P1-2: IR codegen i64::MIN 双重取反

**严重等级**: 🔴 P1 — 生成无法编译的 Rust 代码

**复现步骤**:
```lz
def main() =
    a = -9223372036854775808
    print(a)
```
编译: `lang-zone test.lz --ir-codegen`

**实际结果**: 生成 `let mut a: i64 = --9223372036854775808;` — 双重取反
**预期结果**: `let mut a: i64 = i64::MIN;` (AST 路径已在 commit `b6453fb` 修复)
**影响**: `--9223372036854775808` 即 `-(-9223372036854775808)` = `9223372036854775808` 溢出 i64，rustc 编译报错

**根因**: AST codegen 已在 `src/codegen/expr.rs` 特殊处理 i64::MIN，但 IR codegen (`src/ir/codegen.rs:665`) 未同步此修复

---

### 🔴 P1-3: IR builder elif 链条件逆序

**严重等级**: 🔴 P1 — 生成语义完全错误的代码

**复现步骤**:
```lz
def main() =
    x = 42
    if x > 100:
        print("big")
    elif x > 50:
        print("medium")
    elif x > 10:
        print("small")
```
编译: `lang-zone test.lz --ir-codegen`

**实际结果**: 
```rust
if x > 50 { "medium" } else { if x > 10 { ... } else { if x > 100 { "big" } else { ... } } }
```
条件顺序变为 `50 → 10 → 100`（逆序）

**预期结果**: 条件顺序 `100 → 50 → 10`（源代码顺序）

**根因**: `src/ir/builder.rs:430` — `for (elif_cond, elif_body) in elif_clauses.iter().rev()` 中的 `.rev()` 将 elif 链反转

**影响**: 所有含 `elif` 的 IR 代码生成逻辑完全错误

---

### 🔴 P1-4: IR builder match 语句仅取第一个臂

**严重等级**: 🔴 P1 — match 完全失效

**复现步骤**:
```lz
def describe(n: int) -> str =
    match n:
        0: "zero"
        1: "one"
        _: "other"
```
编译: `lang-zone test.lz --ir-codegen`

**实际结果**: 
```rust
pub fn describe(n: i64) -> String {
    return { return "zero".to_string(); };
}
```
**预期结果**: 
```rust
pub fn describe(n: i64) -> String {
    match n {
        0 => "zero".to_string(),
        1 => "one".to_string(),
        _ => "other".to_string(),
    }
}
```

**根因**: `src/ir/builder.rs:443` — `arms.first().map(|arm| { ... })` 只取第一个 arm，丢弃 scrutinee 表达式和所有其他臂

**影响**: IR 路线的 match 完全不可用

### 🟡 P2-2: IR codegen `check` 自定义消息丢失

**严重等级**: 🟡 P2

```lz

```

**根因**: `src/ir/builder.rs:1007` 硬编码了消息字符串

### 🟡 P2-3: IR codegen print 格式不一致（{:?} vs {}）

**严重等级**: 🟡 P2

IR 路径使用 `println!("{:?}", ...)` 而 AST 路径使用 `println!("{}", ...)`。字符串会以 Debug 格式输出（带引号），行为不一致
