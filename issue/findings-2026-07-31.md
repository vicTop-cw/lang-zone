## 一、P0 — 实锤 bug（有运行证据）

### 1. 顶层构建块被静默丢弃，生成不可编译的 Rust 代码

**证据**:
- `src/parser/parser.rs:339-345` 把顶层 `x =: body` 收集进 `Module.top_level_builds`
- `src/ast/decl.rs:19` 新增字段 `top_level_builds: Vec<(String, Vec<Stmt>)>`
- 全仓库引用该字段的只有 `ast/decl.rs` / `parser/parser.rs` / `project.rs` 三处——**codegen 和 typer 从不消费它**（`grep top_level_builds src/codegen` 无命中）

**实测**: 编译
```lz
x =:
    y = 1
    y + 1
def main() = print(x)
```
生成的 `topbuild.rs` 只有 `fn main() { println!("{}", x) }`，`x` 未定义，rustc 必然报 `cannot find value x`。

**影响**: 静默数据丢失 + 产出不可编译的 Rust 代码，无任何报错。

**修复建议**: 在 `CodeGen::generate` 中真正生成顶层构建块（闭包绑定），或至少显式报「顶层构建块暂不支持」——二选一，不能静默。

### 2. 数字字面量非法/溢出静默变 0（`src/lexer/lexer.rs:92-171`）

```rust
let val = i64::from_str_radix(..., 16).unwrap_or(0);   // L108 / L120 / L132
Token::IntLit(num.parse().unwrap_or(0))                 // L169
Token::FloatLit(num.parse().unwrap_or(0.0))             // L167
```

**触发场景**:
- `0xG`（无有效数字）→ `IntLit(0)`
- 十进制溢出 i64（如 20 位数字）→ `0`
- `123e`（科学计数法无尾数）→ `FloatLit(0.0)`

**影响**: 错误输入静默变成「正确」的值，用户代码拿到 0 却没有任何报错——编译器撒谎，是最危险的一类行为。

**修复建议**: 三处改为返回词法错误（如 `InvalidNumber`），而不是 `unwrap_or(0)`。

---

### 3. 未终止字符串静默接受（`src/lexer/lexer.rs:173-196`）

**证据**: `read_string` 循环读到 EOF 直接返回 `StrLit(...)`，无错误；结尾 `\` 在 EOF 处被静默吞掉。

**触发场景**: `"abc`（无闭合引号）→ 静默返回 `StrLit("abc")`。

**修复建议**: 循环结束且未遇 `"` 时产生 `UnterminatedString` 错误。

## 三、P2 — 死代码 / 逻辑缺陷

### 9. cache.rs 的 output/deps 校验全是死逻辑（`src/main.rs:206-212`）

**证据**:
- 实测 `.lzcache/if_elif_else.lzcache` 内容为 `hash=...\noutput=`——main.rs 的 `--cached` 只存源文件哈希
- main.rs 从不设置 `entry.output`、从不调用 `scan_deps` 记录依赖
- 于是 `CacheEntry::is_fresh`（`src/cache.rs:83-108`）的产物存在检查、依赖哈希检查永远形同虚设

**影响**: **改 import 的依赖文件后缓存不会失效**；CLI 缓存路径与 cache.rs 的设计完全脱节。

---

### 10. 缓存文件名只用 file_stem（`src/cache.rs:122-125`）

`a/foo.lz` 和 `b/foo.lz` 的缓存同为 `foo.lzcache`，互相覆盖；`output_filename`（L128-130）同理。

---

### 11. `prune_stale` 会误删 .rs（`src/cache.rs:141-160`）

L147 把缓存目录里所有「无对应源文件」的 `.lzcache` **和 `.rs`** 一起删。若产物与缓存混放，用户编译好的 `.rs` 会被清理。

---

### 12. main.rs 的 `.lz` 替换与 Windows 残留

- `path.replace(".lz", ".rs")`（`src/main.rs:51,159,182,198`）替换**所有**出现的 `.lz` 子串：`a.lz.lz` → `a.rs.rs`
- `--test` 模式（L215-244）：Windows 上实际产物是 `foo_test.exe`，`remove_file(&test_bin)`（无 `.exe` 后缀）删不掉，每次运行残留一个可执行文件

---

### 13. main.rs 重复代码

- `--emit=ir`（L152-172）与 `--ir-codegen`（L173-192）两段几乎完全相同的生成逻辑
- `rustc_version`（L32-36）无论是否需要 `--allow-rustc-private` 都无条件起 rustc 子进程
