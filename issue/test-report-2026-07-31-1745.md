## 🔴 新发现 Bug

### N1 🔴 P1: `float(str)` 生成 `String as f64` 无效 Rust

- **Issue**: `issue/ir-codegen-float-str-conversion.md`
- **测试文件**: `DEMO/99_spec/ir-edge-type-boundary.lz`
- **现象**: `def test_str_to_float(s: str) -> f64 = float(s)` → `(s as f64)` — rustc E0605
- **对比**: `int(s)` 当 `s: String` 时**能正确**生成 `.parse::<i64>().unwrap()`
- **根因**: `float`/`f64` 转换分支固定用 `as f64`，未检测参数为 `IrType::Str`
- **修复**: 参照 `int` 分支，为 `float` 增加 `IrType::Str` → `.parse::<f64>().unwrap()` 路径

### N2 🔴 P1: Match guard 条件被静默丢弃

- **Issue**: `issue/ir-codegen-match-guard-dropped.md`
- **测试文件**: `DEMO/99_spec/ir-edge-guard-combo.lz`
- **现象**: `case n if n < 0 =>` → 生成 `n =>`（通配模式），guard 完全丢失
- **影响**: 所有 match 带 guard 分支全部变成 catch-all，后续臂不可达
- **关键发现**: for 循环 guard **正常**（`for item in items if item > 0` → `.filter()`），说明并非全面缺失
- **修复**: codegen 处理 `MatchArm` 时需检查 `Pattern::Guarded` 并输出 `if condition`

### N3 🟡 P2: 无返回类型标注的函数推断为 `i64` 导致类型不匹配

- **Issue**: `issue/ir-codegen-void-fn-return-type.md`
- **测试文件**: `DEMO/99_spec/ir-edge-empty-collections.lz`
- **现象**: `def empty_list_test() = ... print(a,b)` → `pub fn empty_list_test() -> i64 { return println!(...) }` — rustc E0308
- **附注**: `let y: Option = None` 类型标注被丢弃
