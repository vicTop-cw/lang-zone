## 五、新发现 Bug

### B1 — 🔴 P0: `.pow()` 整数类型歧义 (E0689)

**影响文件**: `05_expressions/operators.lz`, `13_operators/precedence.lz`

**根本原因**: 未提交改动将 `**` 正确映射为 `.pow()` 方法调用，但生成的代码中整数字面量缺少类型标注：
```rust
let pow: i64 = 2.pow(10);  // E0689: 2 是 ambiguous integer
```
Rust 无法推断 `2` 的具体整数类型，`.pow()` 需要接收者明确为 `i32`/`i64` 等具体类型。

**修复方向**: 在 codegen 中，当 `.pow()` 的接收者是整数字面量时，根据类型标注添加后缀（如 `2_i64.pow(10)`）。

**与上一轮的关系**: 本轮新发现。上一轮 N1 (`**`→`*`) 已修复，但修复引入此回归。

### B2 — 🔴 P1: `in` 运算符 `.contains()` 参数类型不匹配 (E0277)

**影响文件**: `05_expressions/operators.lz`

**根本原因**: 未提交改动将 `in` 正确映射为 `.contains()`，但字符串场景生成：
```rust
let in_str: bool = "hello".to_string().contains("llo".to_string());
// E0277: String doesn't implement Pattern
```
Rust 的 `str::contains` 需要 `Pattern` trait，`String` 不实现。需要 `&str` 参数或自动借用。

**修复方向**: 当 `.contains()` 的参数是 `String` 类型时，添加 `&` 前缀转为 `&str`。

**与上一轮的关系**: 本轮新发现。上一轮 N3 (`in`→`==`) 已修复，但修复引入此边缘情况。

### B3 — 🟡 P2: `.contains()` 对 Dict/HashMap 特殊化需求

**影响文件**: 低优先级，目前 DEMO 中无 Dict `in` 测试

**现状**: `in` 对 Dict/HashMap 应生成 `.contains_key()` 而非 `.contains()`。未提交代码中已有此意图但未完整实现（codegen.rs 有 Dict 分支但实际生成路径未经过）。

## 八、边界测试分析

### 8.1 运算符边界 — Pow 特殊情况

| 场景 | LZ | 生成 Rust | 结果 |
|------|-----|-----------|:--:|
| 整数幂 | `2 ** 10` | `2.pow(10)` | ❌ E0689 |
| 变量幂 | `x ** y` (x: i64) | `x.pow(y)` | ✅ |
| 链式幂 | `2 ** 3 ** 2` | `2.pow(3.pow(2))` | ❌ E0689 ×2 |
| 复合赋值幂 | `mx **= 2` | `mx = mx.pow(2)` | ✅ |

### 8.2 运算符边界 — In 特殊情况

| 场景 | LZ | 生成 Rust | 结果 |
|------|-----|-----------|:--:|
| 列表 in | `3 in [1,2,3]` | `vec![1,2,3].contains(&3)` | ✅ |
| 字符串 in | `"llo" in "hello"` | `"hello".contains("llo")` | ✅ |
| 字符串 in (to_string) | `"llo" in hello_str` | `hello_str.contains("llo".to_string())` | ❌ E0277 |
| Dict in | `"a" in {"a":1}` | `map.contains_key(&"a")` | ✅ (代码路径存在) |

### 8.3 按位取反 ~ — 验证

| 场景 | LZ IR | 生成 Rust | 语义 |
|------|-------|-----------|------|
| `~5` | `UnOp(Not, 5)` | `!5` | ✅ 位非（整数） |
| `~True` | `UnOp(Not, True)` | `!true` | ✅ 逻辑非（布尔） |

> 验证确认：`~` 运算符通过 `UnOpKind::Not` → `!` 生成正确 Rust。N2 误报已撤销。
