## 五、新发现 Bug

### N12 🟡 P1: struct_more 可变借用缺失 — E0596

- **文件**: `DEMO/07_data_structures/struct_more.lz`
- **现象**: `let c = Counter { count: 0 }; c.increment()` 报 E0596 `cannot borrow c as mutable`
- **根因**: LZ 中 `c.increment()` 调用 `&mut self` 方法，但 codegen 生成 `let c = ...` 而非 `let mut c = ...`。LZ 源中不标注 mut，编译器需推断变量是否被可变借用
- **影响**: `struct_more.lz` (1 文件)
- **严重等级**: P1 — 阻止 struct impl 方法中的可变方法调用

### N13 🟡 P2: callable_objects 期望函数找到 struct — E0618

- **文件**: `DEMO/07_data_structures/callable_objects.lz`
- **现象**: `doubler(21)` 报 E0618 `expected function, found Multiplier`
- **根因**: LZ 支持 `__call__` 让 struct 实例可调用，但 codegen 未生成对应的 `Fn` trait impl 或 `call` 方法转换
- **影响**: `callable_objects.lz` (1 文件)
- **严重等级**: P2 — 高级特性未实现

### N14 🟡 P2: 闭包生命周期标注缺失 — E0373

- **文件**: `DEMO/04_functions/closures_more.lz`
- **现象**: 返回闭包 `|x| x + n` 报 E0373 `closure may outlive the current function`
- **根因**: LZ 闭包捕获外部变量时，codegen 未生成 `move` 关键字或生命周期标注
- **影响**: `closures_more.lz` (1 文件)
- **严重等级**: P2 — 返回闭包场景受阻

### N15 🔴 P0: 工作区源码编译错误 — `mutted_consts` typo

- **文件**: `src/ir/codegen.rs:63`
- **现象**: `cargo run` 触发重编译时报 `E0560: struct CodeGen has no field named mutted_consts`
- **根因**: 未提交修改中，构造函数 `mutted_consts` 拼写错误（应为 `mutated_consts`），预编译二进制不受影响
- **影响**: 任何 `cargo run` 调用会先触发重编译 → 失败。需先 `cargo build` 确认状态
- **严重等级**: P0 — 阻塞开发流程
- **注**: 此 bug 可能为 cargo 锁竞争/增量编译缓存导致，`cargo build` 第二次运行通过

### N16 🟡 P1: try-catch 代码块返回类型错误 — E0308 (14 errors)

- **文件**: `DEMO/10_error_handling/panic_raise_try.lz`
- **详细错误**:
  1. try 块 `__result.ok()` 返回 `()` 而非预期 `i64`
  2. catch 臂 `if let Err(e) { -1 }` 类型为 `()` 而非 `i64` (缺 `else` 和 `return`)
  3. `parse_int`, `read_file` 函数未定义 (E0425)
  4. `return panic!(...)` 后跟不可达代码 (warning)
- **影响**: `panic_raise_try.lz` 14 errors, `try_more.lz` 若干 errors
- **严重等级**: P1 — try-catch 核心控制流受阻
