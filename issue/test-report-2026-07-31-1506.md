## 三、新发现 Bug

### 🔴 Bug #N1-UPGRADE: Variadic `..` 生成无效 Rust 代码 — P0（代码生成严重缺陷）

> 原 Bug #N1 仅报告 `..` 分隔符文档化但未实现的问题。本次测试发现该功能已部分实现但**生成完全不可编译的 Rust 代码**，严重等级从 P1（文档）升级为 P0（代码生成缺陷）。

**复现步骤**:
```lz
def sum_all(..nums: int) -> int =
    let total = 0
    for n in nums:
        total = total + n
    total

def main() = print(sum_all(1, 2, 3, 4))
```

**预期结果**: 生成可被 rustc 编译的 Rust 代码，`..nums` 表现为可变参数

**实际结果**: 生成的 Rust 代码有两处致命错误：
```rust
fn sum_all(nums: i64) -> i64 {     // ❌ 应为 &[i64] 或 Vec<i64>
    let total = 0;
    for mut n in nums {             // ❌ 不能对 i64 迭代
        total = total + n;
    }
    total
}
// ❌ 调用方传 4 个参数给 1 参数函数
println!("{}", sum_all(1, 2, 3, 4))
```

**技术根因**: Parser 正确消费了 `..` 标记，但 codegen 未做相应处理：
- 参数类型直接从标注类型转换为 Rust 类型，未包装为切片/迭代器
- `for in` 对参数类型不做 `IntoIterator` 检查
- 调用方不做参数打包

**影响范围**: 所有使用 variadic `..` 参数的代码生成的 Rust 产物均无法编译

**严重等级**: 🔴 P0（生成不可编译目标代码，属于编译器撒谎）

**修复建议**: 
1. Codegen 将 variadic 参数包装为 `&[T]` 或 `Vec<T>`
2. 调用方将多个参数打包为数组/切片字面量

### 🟡 Bug #N5: `check` 新增为关键字，存在标识符遮蔽风险 — P2

**复现步骤**:
`src/lexer/lexer.rs:391` 新增 `"check" => Token::Check`
`src/lexer/token.rs:23` 新增 `Check` 枚举变体

**预期结果**: 如 `check` 为关键字，应文档化且测试覆盖；如非关键字，不应在词法层硬编码

**实际结果**: `check` 作为关键字硬编码，`Stmt::Check` AST 节点在 parser（`stmt.rs:309`）、typer（`mod.rs:640`）、IR builder（`builder.rs:994`）、codegen（`stmt.rs:258`）均有处理。但：

**影响范围**: 使用 `check` 作为变量名的代码将解析失败
