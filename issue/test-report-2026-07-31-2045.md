### E0425 详细分解 (最大类别, 31 文件)

这些几乎都是 codegen 层面的 bug——LZ 编译器成功生成了 IR，但 IR→Rust 的代码生成产生了引用不存在变量的代码：

- **变量作用域丢失** (13): `mutable_let`, `ownership`, `walrus`, `walrus_more`, `build_more`, `var_call_block`, `go_stmt`, `prelude_demo` 等 — 生成的 Rust 引用了不在当前作用域的变量名
- **函数/方法引用** (8): `option_result`, `checker`, `closures_more`, `operators` — 生成的 Rust 调用了不存在的函数
- **try-catch 作用域** (5): `combo_while_guard_else/try/walrus`, `combo_try_raise_guard` 等 — 错误处理块中的变量泄露到外部作用域
- **其他** (5): `pipe_spec`, `parallel_decorator`, `iterator_demo` 等

## 四、新发现 Bug（本轮测试）

### 🔴 N1 (P0): 指数运算符 `**` 错误生成为 `*` 乘法

**文件**: `DEMO/05_expressions/operators.lz` (line 36)
**错误码**: E0425（连锁触发）

**复现步骤**:
```lz
let pow: int = 2 ** 10  // LZ 指数运算
```

**实际生成的 Rust**:
```rust
let pow: i64 = 2 * 10;  // ❌ 生成的是乘法，不是指数
```

**预期生成**:
```rust
let pow: i64 = 2_i64.pow(10);  // ✅ Rust 指数运算
// 或: let pow: i64 = (2i64).pow(10);
```

**影响范围**: `operators.lz`、`compound_assign_more.lz`（复合赋值 `**=` 也可能受影响）
**根因**: IR builder 或 codegen 将 `**` 运算符映射为 `*`（乘法），缺少 `pow()` 方法调用转换。

### 🔴 N3 (P0): `in` 运算符错误生成为 `==` 等值比较

**文件**: `DEMO/05_expressions/operators.lz` (lines 61-64)
**错误码**: E0425（连锁触发）

**复现步骤**:
```lz
let in_str = "llo" in "hello"         // 子串包含
let in_lst = 3 in [1, 2, 3]           // 列表包含
let in_set = 2 in {1, 2, 3}           // 集合包含
```

**实际生成的 Rust**:
```rust
let in_str: bool = "llo".to_string() == "hello".to_string();  // ❌ 等值比较
let in_lst: bool = 3 == vec![1, 2, 3];                         // ❌ 等值比较
let in_set: bool = 2 == HashSet::from([1, 2, 3]);              // ❌ 等值比较
```

**预期生成**:
```rust
let in_str: bool = "hello".contains("llo");                  // ✅
let in_lst: bool = vec![1, 2, 3].contains(&3);               // ✅
let in_set: bool = HashSet::from([1, 2, 3]).contains(&2);    // ✅
```

**影响范围**: `operators.lz`、任何使用 `in` 运算符的代码

### 🔴 N4 (P1): panic! 和枚举变体构造语法错误

**文件**: `DEMO/10_error_handling/panic_raise_try.lz`
**错误码**: E0423

**复现步骤**:
```lz
def find_user(id: int) -> str =
    if id <= 0:
        panic(AppError.InvalidInput("id must be positive"))
    "user_{id}"
```

**实际生成的 Rust**:
```rust
return panic!("{:?}", AppError::InvalidInput("id must be positive".to_string()));
// ❌ panic! 参数应该是 String，这里传了 AppError::InvalidInput 值
```

以及：
```rust
return panic!("{:?}", FileError.ReadError("empty path".to_string()));
// ❌ FileError.ReadError 点号应为双冒号 FileError::ReadError
```

**预期生成**: panic! 宏应该接受格式化字符串，枚举变体构造需用 `::` 语法。

**影响范围**: `panic_raise_try.lz`, `try_more.lz`, `combo_defer_guard_try.lz`

trait Drawable:

**影响范围**: `trait_impl.lz`

### 🟡 N6 (P1): try-catch 表达式生成无效 `return` 控制流

**文件**: `DEMO/10_error_handling/panic_raise_try.lz`
**错误码**: E0425 / E0308

**复现步骤**:
```lz
def safe_divide(a: int, b: int) -> int =
    try:
        checked_divide(a, b)
    else:
        -1
    finally:
        print("division attempted")
```

**实际生成的 Rust**:
```rust
pub fn safe_divide(a: i64, b: i64) -> i64 {
    return {
        checked_divide(a, b);
        ();
        -1;
        return println!("{:?}", "division attempted".to_string());
    };
}
```

问题:
1. 块表达式返回类型混乱：`checked_divide()` 返回 i64，`()` 是 unit，`-1` 是 i64
2. `finally` 块中 `return println!(...)` 是错误的早期返回

**影响范围**: `panic_raise_try.lz`, `combo_defer_guard_try.lz`, `combo_try_raise_guard.lz`
