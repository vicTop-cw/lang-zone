## 复现步骤

1. 编写以下 `.lz` 文件：
```lz
def main() =
    let a = 1
    let b = 2
    let c = 3
    let x: int = (a + b) * c      # 期望 (1+2)*3 = 9
    let y: int = a + b * c        # 期望 1+6 = 7
    print(x, y)                   # 应该输出 9 7，实际输出 7 7
```

2. 用 IR 路线编译：
```
cargo run -- test.lz
rustc test.rs --edition 2021
```

3. 查看生成的 Rust 代码 — **两个表达式完全相同**：
```rust
let x: i64 = a + b * c;   // 应该是 (a + b) * c
let y: i64 = a + b * c;   // 正确
```

4. 编译通过（无错误），但 `x` 的值从 `9` 变成了 `7`，**语义完全错误**。

## 根本原因

IR 构建器或代码生成器在将 AST/IR 树展开为 Rust 文本时，**丢弃了括号分组信息**。运算符优先级完全由 Rust 的默认优先级决定，LZ 源码中通过括号显式指定的分组被忽略。

## 影响范围

- **所有包含括号分组的算术表达式**：`(a + b) * c`、`((a+b)*(c-a))/(b+1)` 等
- 影响文件：DEMO 中目前没有重度使用括号分组的文件，但这是**核心语义正确性问题**
- 潜在影响：任何用户代码中使用括号改变运算顺序的场景

### 已验证的受感染模式

| LZ 源码 | 生成 Rust | 正确 Rust | 结果 |
|---------|-----------|-----------|------|
| `(a + b) * c` | `a + b * c` | `(a + b) * c` | ❌ 错误 |
| `((a+b)*(c-a))/(b+1)` | `a + b * c - a / b + 1` | `(a+b)*(c-a)/(b+1)` | ❌ 严重错误 |
| `-(5 * 3)` | `-5 * 3` | `-(5 * 3)` | 结果碰巧相同 |

### 不受影响的模式

- `not (a == b)` — `not` 关键字级运算符的括号保留
- 函数调用 `f(x)` — 函数调用的括号正常工作
- 索引 `xs[i]` — 索引括号正常工作

## 修复方向

需要确保 IR 表达式树中保留括号分组节点（`Group` / `Paren`），并在 codegen 时输出对应的 Rust 括号：

```rust
// IR 中应保留：
Expr::Paren(inner) 
// codegen: format!("({})", gen_expr(inner))
```

或运算符优先级感知方案：跟踪每个子表达式的"最小所需优先级"，在需要时自动插入括号。
