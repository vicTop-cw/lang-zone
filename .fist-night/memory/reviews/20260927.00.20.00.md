## 三、根因（定位到行）

1. **BUG-N1**：`src/ir/builder.rs:4974-4981` 把 `A::b`（PathAccess）降级为
   `FieldAccess{ field: "\u{1}PATH\u{1}" + segment }`。
   `src/ir/codegen/mod.rs:12704-12822`（FieldAccess **表达式**发射点）已在 BUG-8 修复中剥离哨兵，
   但 `10255-10347`（**Call** 发射点）把含哨兵的 `field` 原样拼进
   `format!("{}::{}({})", base_s, field, ...)`（10347）→ 哨兵泄漏进产物。
2. **BUG-N2**：`src/ir/codegen/mod.rs:9640` 用 `types.contains(&type_name.as_str())` 与白名单
   `["Duration","Instant"]` **精确匹配**；`time::Duration` 是 PathAccess → `type_name == "\u{1}PATH\u{1}Duration"`
   → 匹配失败 → std 模块链拦截不生效 → camelCase→snake_case 与 `std::` 前缀均未施加。
3. **BUG-N3**：生成签名 `compose<a,b,c>(f: impl Fn(b)->c, g: impl Fn(a)->b)` 下，调用点
   `compose(move |x| {...}, move |x| {...})` 的闭包参数无类型标注，Rust 无法反推 `a`。
   **属语义/设计决策**，卡 C 禁区只挂账不修。
