### BUG-11 尝试记录（失败留档，勿重复踩坑）

- 假设：外层闭包的返回体即内层闭包（`nested`）时内层会装箱逃出外层作用域 → 内层必须 `move`。
- 实施：新增 `CodeGen.parent_lambda_nested_box: Cell<bool>`，在外层 Lambda 的
  `gen_expr(body)` 前置位，在两个闭包分支（block / expr）强制 `uses_move = true`，
  并向 `c = CodeGen::new()` 重建的 child 传播该标记。
- **结果：未生效**——`nesting-closure-lambda.lz` 产物仍为
  `Arc::new(move |a: i64| { Arc::new(|b: i64| { .. a .. }) })`，E0373 依旧。
- 插桩发现：该样例中 `nested` **恒为 false**（25 个 Lambda 全部 `nested-FALSE`），
  内层闭包的字符串是在 `else` 分支由**全新 `CodeGen::new()` child** 重生成的
  （expr_gen.rs ≈6570-6620 的 `body_s` 重建路径），该路径只挑选性复制
  `box_lambda / nested_fn_ret / parent_lambda_non_move` 等少量字段，
  其余上下文（含本次新增标记）**不继承**。
- 结论：BUG-11 的修点不在「加标记」，而在 `body_s` 重建路径的**上下文继承契约**——
  需人工重构为显式上下文对象或补齐继承字段。改动面超出最小安全改动范围 → **回退**。
- 处置：本轮已把 `expr_gen.rs`、`mod.rs` **还原为仓库原版**，副本中仅保留 BUG-8 一处补丁。
