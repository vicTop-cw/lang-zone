## 🟡 [P1] D1 — 字面量溢出编译期拦截

- **问题定位**：`src/token.rs::read_number`
  - 整数溢出：`i64::from_str_radix` / `from_str` 失败被 `unwrap_or(0)` 吞掉 → 词法产出 `IntLit(0)`。
  - 浮点溢出：`f64::from_str` 将溢出解析为 `+inf` / 无效解析为 `NaN`，不报错 → 词法产出 `FloatLit(inf)`。
- **优化方向**：
  1. 整数：解析失败时**返回 `Token::LexError`**（携带字面量文本与位置），由 `parse_module` 统一拒绝，给出明确报错（如「字面量超出 i64 范围」）。
  2. 浮点：检测 `f64::from_str` 结果为 `inf` / `NaN`（溢出或无效）时同样报错，而非静默通过。
  3. 可引入 `--strict` / `-W overflow` 开关，便于逐步收紧而不破坏现有合法用例。
- **配套测试**（整改后预期反转）：
  - 新增用例断言「溢出字面量应 `exit 1` 且含 `LexError`」。
  - 当前 `B04`（整数溢出→0）、`E06`（浮点溢出→inf）是「断言实际静默行为」的临时用例，整改后应**反转预期**为报错。

## 💭 [P2] D2 — 未知类型名校验

- **问题定位**：`map_type` 仅对已知别名（`List/Dict/Set/Option/Result`）做递归映射；未知类型名（如误写 Rust 风格 `Vec<int>`）会原样透传，内部泛型不递归映射，生成非法 Rust（如 `Vec<Vec<int>>`）。
- **优化方向**：
  1. 对未知类型名给出**警告或错误**，避免静默生成不可编译代码。
  2. 对所有 `X<...>` 构造（无论 `X` 是否已知）递归 `map_type` 内部参数。
- **配套测试**：新增「未知类型名应被拒绝 / 告警」用例。

## 💭 [P3] D4 — 缩进不匹配 fail-loud

- **问题定位**：`src/token.rs::handle_indent` 对「列号介于两层缩进之间」的情况仅留空注释静默处理。
- **优化方向**：改为发出**警告或错误**（fail-loud），避免语句被错误嵌套导致难以理解的解析结果。

---

## 💭 [P3] D3 — 表达式层 `if` / `match`

- **问题定位**：`parse_expr` 主链无 `if` / `match` 表达式解析分支，其可用性依赖 `parse_stmt` 中 `Token::If` / `Token::Match` 的特判。未来若支持 `let x = if a { 1 } else { 2 }` 这类表达式用法，当前链不会消费而报错。
- **优化方向**：在 `parse_expr` 显式增加 `if` / `match` 表达式解析分支，与语句层解耦。

## 🛠 测试体系增强（工程改进，非编译器缺陷）

1. **端到端编译运行**：当前为文本级子串断言。建议将生成的 `.rs` 经 `rustc --edition 2024` 实际**编译并运行**，验证语义正确性（捕获代码生成产生非法 Rust 的情况）。
2. **Golden File 比对**：对关键用例保存「黄金输出」，支持整文件 diff 而非仅子串，提升回归灵敏度。
3. **CI 集成**：将 `run_tests.py` 接入持续集成，任何源码变更自动回归。
4. **边界补充**：最深缩进 / 嵌套深度限制、超长源码、制表符 / 空格混合缩进、注释中含 `=:` / `~:` 等边界。
