# Lang-Zong 编译器 — 测试计划 (TEST PLAN)

> 本计划与全部测试产物均存放于 `test-suite/` 目录内，不修改或创建该目录以外的任何文件。
> 系统待测对象 (SUT)：预编译二进制 `target/debug/lang-zone.exe`（CLI：`lzc <file.lz> [--tokens] [--ast]`）。

---

## 1. 项目与技术栈概览

**Lang-Zong (`lang-zone`)** 是一个用 **Rust** 编写的源码到源码（transpile）编译器：
将自研语言 **Lang-Zong (`.lz`)** 源文件翻译为 **Rust 源码**，再交由 `rustc` 编译执行。

编译流水线（位于 `src/`）：

| 阶段 | 文件 | 职责 |
|------|------|------|
| 词法分析 | `src/token.rs` | 源码 → Token 流；处理缩进（Indent/Dedent）、构建块符号 `=:`/`~:`/`*:`，以及 0x/0o/0b 进制、f-string、原始串、三引号串 |
| 语法分析 | `src/parser.rs` | Token 流 → AST；含构建块语义校验、模式匹配、guard、泛型 `>>` 拆分 |
| 代码生成 | `src/codegen.rs` | AST → Rust 源码；copy-by-default（`.clone()`）、`owned` 契约检查、构建块闭包与 `__Pack` 不安全解包、f-string 降级 |
| 入口 | `src/main.rs` | CLI：读 `.lz` → 词法 → 语法 → 代码生成 → 写 `.rs`；`--tokens`/`--ast` 仅打印中间产物 |

语言核心特性：函数/泛型、`struct`/`enum`/`trait`/`impl`、控制流（`if/elif/else`、`for/while/loop`、`match`）、
`guard let`/条件守卫、管道 `|>`、安全导航 `?.`、空合并 `??`、构建块（`=:` 变量 / `~:` 调用 / `*:` 生成器）、
`^` 显式 move 与中缀 XOR 消歧、`int?`→`Option<int>` 语法糖。

## 2. 测试范围与目标

### 2.1 范围
- **编译器前端与中端**：词法、语法、代码生成三个阶段的转换正确性。
- **错误处理路径**：非法/边界输入必须**优雅报错**（退出码 1 + 明确信息），**不得 panic（退出码 101）**。
- **构建块专项**：三种构建块的合法形态与语义校验拒绝（yield 约束、返回值约束、顶层禁用）。

### 2.2 不纳入范围
- 生成的 Rust 最终经 `rustc` 链接运行的端到端语义（属下游验证，本计划以 `token/ast/rust` 文本断言为主）。
- 性能/压力基准测试（留待后续迭代）。

### 2.3 测试目标
1. 验证核心语言特性被正确解析与转译（功能正确性）。
2. 验证边界输入（空、极大/溢出数值、超长标识符、深层嵌套、Unicode）被稳健处理。
3. 验证异常输入被拒绝且不崩溃（健壮性）。
4. 暴露词法/语法/代码生成中的潜在缺陷与风险点，给出改进建议。

## 3. 测试类别与优先级

| 优先级 | 含义 | 通过标准 |
|--------|------|----------|
| **P0** | 关键路径，必须通过 | 核心功能用例 100% 通过 |
| **P1** | 重要，应当通过 | 边界与异常用例通过率 ≥ 95% |
| **P2** | 扩展/增强，可选 | 记录结果，不阻塞 |

### 3.1 功能测试 (Functional) — P0/P1
覆盖词法、语法、代码生成对关键语言的转换：关键字/字面量/操作符词法化、函数/结构体/枚举/匹配 AST 构造、
`int?`/f-string/管道/安全导航/空合并/guard let/`owned` 契约等代码生成形态。

### 3.2 边界测试 (Boundary) — P1
空输入、单行标识符、i64 最大值、**整数/浮点溢出静默归零**、深层嵌套泛型（`>>` 拆分）、深层嵌套表达式、
超长标识符、三引号串公共缩进裁剪、Unicode 字符串、浮点字面量边界。

### 3.3 构建块专项 (Build Block) — P1
三种构建块合法形态生成；语义校验拒绝：顶层禁用、生成器缺 yield、变量块含 yield、调用块返回值非 BuildParams。

### 3.4 异常处理测试 (Exception Handling) — P1
构建块符号缺空白（LexError）、未闭合括号、表达式非法 token、函数缺体、const 缺 `=`、浮点溢出。
**关键断言：进程不得 panic（退出码 101）。**

## 4. 测试设计方法

- **黑盒驱动**：每个用例提供一段 `.lz` 源，调用 SUT 的三种模式之一：
  - `--tokens`：断言词法产物包含预期 Token 子串（如 `IntLit(255)`、`LexError`）。
  - `--ast`：断言 AST Debug 输出包含预期结构子串（如 `name: "add"`、`is_enum: true`）。
  - 默认（代码生成）：断言生成的 `.rs` 包含预期 Rust 子串（如 `Option<i64>`、`println!(...)`、`__Pack::Tuple`）。
  - 错误模式：断言退出码为 `1` 且 stderr 含预期错误信息，且**非 101**。
- **不变量断言**：仅对从源码推导出的稳定转换不变量做子串匹配，避免脆弱的整文件比对。
- **执行隔离**：所有输入 `.lz` 与生成产物均落在 `test-suite/_work/`，报告与用例描述落在 `test-suite/reports/` 与 `test-suite/cases/`。

## 6. 执行与报告

1. 运行 `python3 run_tests.py`（或托管 Python 解释器），驱动 `target/debug/lang-zone.exe`。
2. 每次执行后，于 `test-suite/reports/` 生成详细测试报告，包含：
   - 测试范围与目标
   - 测试用例清单及逐条执行结果（通过/失败/崩溃）
   - 发现的缺陷与风险评估
   - 通过率统计（按类别与优先级）
   - 改进建议
3. 退出码约定：SUT 正常成功为 `0`，优雅报错为 `1`，**panic 为 `101`（视为严重缺陷）**。

---

## 7. 通过标准总结

- P0 功能用例：100% 通过。
- P1 边界/构建块/异常用例：通过率 ≥ 95%，且**零 panic**。
- 任何 panic（退出码 101）或 `owned` 契约误判均记为 **Blocker** 级缺陷。
