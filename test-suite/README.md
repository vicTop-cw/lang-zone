# test-suite/ — Lang-Zong 编译器测试集成（根目录）

本目录为 Lang-Zong 编译器的**专属测试集成根目录**。所有测试相关内容（计划、用例、驱动、生成产物、报告、改进建议）**仅存放于本目录内**，不修改或创建项目其他任何文件/目录。

## 目录结构约定

每次测试运行归档为一个**日期子文件夹**，按 `{yyyyMMdd}-NN` 命名：

```
test-suite/
├── README.md                  # 本文件：目录结构约定与索引
└── {yyyyMMdd}-NN/             # 单次测试运行（如 20260722-01）
    ├── README.md              # 本次运行说明（范围 / 如何运行 / 结果摘要）
    ├── TEST_PLAN.md           # 本次运行的测试计划
    ├── run_tests.py           # 测试驱动（黑盒，调用 SUT）
    ├── SUGGESTIONS.md         # 改进建议（针对发现问题的具体优化方向）
    ├── cases/                 # 用例源占位（权威定义见 run_tests.py 的 CATALOG）
    ├── reports/               # 详细测试报告
    │   └── TEST_REPORT_NNN.md
    └── _work/                 # 运行期产物（输入 .lz / 生成 .rs / results.json）
```

## 命名规则

- **格式**：`{yyyyMMdd}-NN`
  - `yyyyMMdd` = 运行日期（本地，如 `20260722`）
  - `NN` = 当日递增序号，从 `01` 起；换一天则重置为 `01`
- **示例**：`20260722-01`、`20260722-02`、`20260723-01`

## 每次测试的流程

1. 在 `test-suite/` 下新建一个 `{yyyyMMdd}-NN/` 文件夹（同日内第二个运行用 `-02`，依此类推）。
2. 将该次测试相关的**全部内容**（脚本、输入、报告、建议）放入该文件夹内，自包含、可独立复现。
3. 报告记录测试内容、结果与发现；`SUGGESTIONS.md` 给出针对问题的具体优化方向。

## 可追溯性

- 按日期文件夹即可检索历史测试记录；每个文件夹自包含，可独立复现。
- 各 `run_tests.py` 以 `../../target/debug/lang-zong.exe` 引用项目预编译二进制（相对运行文件夹上两级 = 项目根）。
- 为遵守"仅在 test-suite/ 内存放测试产物"的约束，套件**使用预编译二进制**作为被测对象，未重新构建项目；如需基于最新源码验证，请在项目根执行 `cargo build` 后重跑。
