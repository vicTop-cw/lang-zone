# LZ 函数 — 检查站 [checker]

> 规范版本: 3.4 · 基于编译器源码 · 最后校订: 2026-08-07

`[checker]` 是参数**运行时检查与转换**机制。可以定义在**任意函数**（含普通函数、`..` 可变参数函数、魔法方法）的签名中。

---

## 一、语法位置

`[ ]` 中括号有三种形态，必须放在函数名**之后**、`<generics>` **之前**：

| 形态 | 语法 | 语义 |
|------|------|------|
| **定义检查站参数** | `def f[ps: __Params](...)` | 函数新增一个 `ps: &mut __Params` 伪参数，调用方必须传入 `__Params` |
| **引用已有检查站** | `def f[cache](...)` | 函数引用一个已定义的 checker 块或 checker 函数，调用时自动打包参数 → 调 checker → 拆包 |
| **显式无检查站** | `def f[None](...)` | 显式声明此函数不使用检查站（即使模块有默认检查站） |

> 省略 `[ ]` 中括号表示**不声明检查站**（默认行为），与 `[None]` 语义等价。

```lz
def function_name[checker_name]<generics>(params) -> Ret = body
                  ↑                ↑
              中括号检查站        尖括号泛型
```

---

## 二、定义

三种 `[ ]` 形态分别对应不同的语义：

### 2.1 引用已有检查站 `[checker_name]`

这是最常用的形态——函数声明时引用一个已定义的检查站（checker 块或 checker 函数）：

```lz
// 定义 checker 块
block counter[ps: __Params]:
    let n = ps.args[0] as int
    print(f"counter called with {n}")

// 普通函数引用 checker 块作检查站
def add[counter](a: int, b: int) -> int =
    a + b                          // body 中参数已通过 counter 检查站处理

// 可变参数函数 + 检查站
def send[validate]<R>(.., ..) -> R =
    for v in args:
        print(v)
    for (k, v) in kwargs:
        print(f"{k}: {v}")
```

### 2.2 定义检查站参数 `[ps: __Params]`

函数**定义自身为检查站**——它接受 `&mut __Params` 并原地修改参数：

```lz
// 定义检查站函数（接收 &mut __Params，原地修改）
def validate_age(ps: __Params) -> __Params raises str =
    if ps.kwargs.contains("age"):
        let age = ps.kwargs["age"] as int
        if age < 0 or age > 150:
            raise "invalid age"
    ps                               // 返回处理后的参数
```

> 注意：`def f[ps: __Params]` 是在**定义检查站本身**（新增 `ps` 伪参数），
> 而 `def f[cache]` 是**引用已有检查站**。两者不可混淆。

### 2.3 显式无检查站 `[None]`

显式声明不使用检查站，覆盖可能存在的默认检查站：

```lz
def fast_path[None](x: int) -> int = x * 2   // 保证不经过任何检查站
```

## 三、调用

### 3.1 定义了 `[checker]` 的函数调用

函数定义时声明了 `[checker]` 默认检查站，调用时检查站**自动执行**：

```lz
// add 定义时用了 [counter] 检查站
add(1, 2)                          // 自动经过 counter 检查站处理参数
```

### 3.2 调用处覆盖检查站

调用时可以用 `[ ]` 覆盖或跳过默认检查站：

```lz
// ✅ 覆盖：用另一个检查站替代默认的
def fib[counter](n: int, a: int, b: int) -> int =
    a if n == 1 else fib(n - 1, b, a + b)

fib[other_check](10, 0, 1)         // 覆盖默认的 counter，改用 other_check

// ✅ 跳过：显式 None 不经过任何检查站
fib[None](10, 0, 1)                // 跳过 counter 检查站

// ✅ 正常调用（使用默认检查站）
fib(10, 0, 1)                      // 自动经过 counter
```

> **调用处覆盖规则**：
> - 调用处 `[chk]` 有值 → 用该值替代默认的检查站
> - 调用处 `[None]` → 跳过检查站（即使函数定义了默认检查站）
> - 调用处无 `[ ]` → 使用函数定义的默认检查站

## 四、检查函数契约

检查函数接受 `__Params` 并返回 `__Params`：

> `__Params` 是编译器为每个含 `[checker]` 的函数自动生成的内部 struct。
> 命名中的 `__` 前缀为编译器内部类型约定，避免与用户自定义类型名冲突；
> 用户代码中不应自行定义名为 `__Params` 的类型。

```lz
// 编译器为每个含 [checker] 的函数自动生成：
// struct __Params:
//     args:    List<dyn>                  // 位置参数（动态类型，需 as 强转）
//     kwargs:  Dict<str, dyn>             // 关键字参数（动态类型，需 as 强转）
```

> `__Params` 的字段类型为 `dyn`（动态类型擦除）。从中取值后须用 `as` 强转为目标类型，而 `as` 可能失败并抛出 `CastError`。
> 因此**所有使用 `__Params` 的 checker 函数都应声明 `raises`**，即使内部已用 `try-catch` 处理（见 §三 异常规则）。

```lz
// 校验 age 参数的检查函数
def validate_age(ps: __Params) -> __Params raises str =
    if ps.kwargs.contains("age"):
        let age = ps.kwargs["age"] as int
        if age < 0 or age > 150:
            raise "invalid age"
    ps                               // 返回处理后的参数
```

注：泛型方法消歧使用 `.` 而非 `::`（与 LZ 统一路径规则一致）。

### 4.1 checker 内的 `as` 与 `raises` 规则

Checker 函数内部通常需要使用 `as` 从 `dyn` 类型强转为具体类型。规则如下：

| 场景 | 是否需要 `raises` | 说明 |
|------|:---:|------|
| 函数体内有 `as` 强转且未被 `catch` | **需要** | `CastError` 可能向外传播 |
| `as` 强转被 `try-catch` 完全捕获 | **需要** | checker 是编译期约束，向外抛出任何异常均应告知调用方 |
| 函数体内无 `as` / 无 `raise` | 不需要 | 不会产生异常 |

> **`try-catch` 捕获后仍需 `raises` 的设计理由**：checker 函数在调用方函数体执行**之前**运行，是编译期插入的约束检查。若 checker 内部用 `catch` 静默吞掉异常，调用方将不可见地接受错误数据。因此 checker 函数应始终向外部声明潜在异常，即使内部已捕获：
>
> ```lz
> def safe_validate(ps: __Params) -> __Params raises CastError =
>     try:
>         let age = ps.kwargs["age"] as int   // as 可能抛出 CastError
>         if age < 0:
>             raise "invalid age"
>         ps
>     catch CastError:
>         raise "age must be int"             // 重新抛出，调用方可感知
> ```

### 4.2 `__Params` 是 struct，不是 trait

`__Params` 作为**编译器生成的内部 struct**（见 §四 开头的注释）承担两件事：`args` 收集位置参数、`kwargs` 收集关键字参数。设计上**刻意不做成 trait**：

- 做成 trait 会让每个 checker 被迫泛型化（`def checker<P: __Params>(ps: P) -> P`），常路径被强制加泛型；
- trait 并不能消除「`~:` 块元组 → `__Params`」的转换，你仍要为每种实参形态写一遍 impl；
- 真正需要「可插拔参数容器」才是 trait 的用武之地，那作为**可选扩展层**（见 §4.4），不在常路径。

### 4.3 参数转换：边界由编译器原生脱糖，无需魔法方法

`~:` 块 / 直接调用产出的实参形态固定为四种，编译器在脱糖时**直接打包成 `__Params`**，chker 返回的元组/字典同样**直接拆回**——全程不触发任何用户魔法方法：

| `~:` / 调用产出 | 脱糖为 `__Params` |
|---|---|
| 元组 `(10, 20)` | `args = (10, 20)`，`kwargs = {}` |
| 字典 `{"a": 1}` | `args = ()`，`kwargs = {"a": 1}` |
| 裸值 `10` | `args = (10,)`，`kwargs = {}` |
| record `{a: 1, b: 2}` | `args = ()`，`kwargs = {a: 1, b: 2}` |

> chker 返回 `(p1, p2)` 元组（或字典）时，编译器按同样规则拆回 `args`/`kwargs`，再分派给目标函数的形参。`__Params` 在此纯为中转结构，chker 内部用 `as` 从 `dyn` 取值（见 §4.1）。

### 4.4 用户空间扩展（可选）：`__implicit_to__` 与 `__from__`

若需让用户代码手动构造 `__Params`、或支持自定义参数容器，提供两类内置转换（不破坏 §4.3 的编译器脱糖）：

- **隐式自动**——在内置源类型（tuple / record / scalar）上挂 `__implicit_to__ -> __Params`（源侧，由 `__implicit_from__` 的 blanket impl 自动派生，约定见 `06g` §8.2）：
  ```lz
  // 内置 tuple 的隐式转换（由编译器提供，示意）
  struct TupleToParams =
      magic __implicit_from__(self: (T, ...)) -> __Params =
          __Params { args: self, kwargs: {} }
  ```
  类型不匹配传参时编译器自动搜索该转换。
- **显式多形态**——在 `__Params` 上提供 `__from__` 重载（目标侧，`From` 风，见 `06d`）：
  ```lz
  def __from__(t: (T, ...)) -> __Params      = __Params { args: t, kwargs: {} }
  def __from__(d: Dict<str, V>) -> __Params  = __Params { args: (), kwargs: d }
  ```
  > 注：隐式转换优先使用 `__implicit_from__`（目标侧）→ 编译器自动插入；若都不存在且用户显式调用，则走 `__from__`（见 `06d` §十四 优先级链）。
- **trait（可选扩展层）**：仅当要支持用户自定义「参数容器」并实现 `__Params` 抽象时才引入，作为高级扩展，不影响上述常路径。

### 4.5 `__Params.args` 的索引约定（与 `01-类型系统` §7.1 一致）

`args` 为 `List<dyn>`（同构、动态长度）。按 [01-类型系统](01-类型系统.md) §7.1 的序列/元组分工：

- **序列用 `[]` 索引**：`ps.args[0]`、`ps.args[-1]`（Python 风末位），**不是 `ps.args.0`**；
- `kwargs` 用 `ps.kwargs["key"]`。

```lz
let p1 = ps.args[0] as int      // ✅ 序列索引（args 是 List<dyn>）
let last = ps.args[-1] as int   // ✅ Python 风末位
// ps.args.0                     // ❌ args 是 List 非异构元组，按 §7.1 该用 [0]
```

### 4.6 block 也能做检查站（作用域级检查站）

「检查站」从函数专属升格为「任何能接收 `__Params` 的可命名执行作用域」。在 [05b-block命名块.md](05b-block命名块.md) 中，`block` 可声明为 checker 作用域或带检查站，复用本文件的边界脱糖与 `__Params` 结构：

- **checker 作用域块** `block NAME[ps: __Params]:`：**惰性登记**（定义时不执行体），触发时 `ps` 作为 `mut __Params` 注入，块体校验/改写 `ps`（**原地修改**，因 block 无返回值，不用 `return __Params`）。省略注解 `block NAME[ps]:` 亦合法（`ps` 推断为 `__Params`）。
- **block 带检查站** `block NAME[chk]:`：与函数 `[chk]` 对称，触发块时先跑 `chk` 改写 `__Params`，再跑体，可通过 `block NAME ^:` 传参（`^:` 后换行缩进写参数；`^:` 对应 block 的 `[...]` 中括号，函数检查站入口用 `~:` 对应 `(...)` 圆括号，见 [11-构建块.md](11-构建块.md)）。

```lz
block norm[ps: __Params] raises ValueError:
    if (ps.args[0] as int) < 0:
        raise ValueError("neg")
    ps.args[0] = (ps.args[0] as int).abs()   // 原地改写

def div[norm](a: int, b: int) -> int = a / b  // 复用 block 作检查站
```

> block checker 相比函数 checker 额外能校验**捕获的外层变量**（闭包），适合「进入逻辑前一并校验环境 + 参数」。两者都可作为 `[chk]` 挂到函数/块上。

> **`^:` 在 block 入口处的语义重载**：`^:` 在 [11-构建块.md](11-构建块.md) §二 本义是「索引构建块 → `__getitem__`（单值 key）」。block 入口复用 `^:` 是因为 block 用中括号 `[...]`（与索引同一括号族），此处作**专用重载**：block 非容器、无 `__getitem__` 冲突，单值块体按 §4.3 脱糖为 `__Params` 注入 `ps`——与函数 `~:`（对应 `()`）入口对称。

## 五、代码生成

函数签名自动注入 `ps` 伪参数，调用时 `Some(chk)` 或 `None`：

```rust
// add[my_check](1, 2) 生成（以下为编译器生成的 Rust 代码，非 LZ）：
pub fn add(
    ps: Option<fn(__Params) -> __Params>,  // 检查站函数指针
    a: i64,
    b: i64,
) -> i64 {
    let __params = match ps {
        Some(chk) => chk(__Params { args: vec![Box::new(a), Box::new(b)], kwargs: HashMap::new() }),
        None => __Params { args: vec![Box::new(a), Box::new(b)], kwargs: HashMap::new() },
    };
    // 从 __params 提取参数...
    // body...
}

// add(1, 2) 生成：
add(None, 1, 2)                      // 不传检查站 → ps = None
```

## 六、编译期验证

| 检查项 | 行为 |
|--------|------|
| `[checker]` 中的标识符是否已定义 | 未定义 → 编译错误 |
| checker 函数的签名是否为 `(__Params) -> __Params` | 不匹配 → 编译错误 |
| `[checker]` 是否只含一个标识符 | 多内容 → 解析错误 |
| checker 是否为自身递归引用 | 自引用 → 编译错误 |

## 七、语法边界

```lz
// ❌ [checker] 位置错误（必须在泛型 <T> 之前，函数名之后）
def bad<T>[check](..) = ...        // 错误：[checker] 不能在 <T> 之后

// ❌ [checker] 内容为空
def bad[](..) = ...                // 错误：检查站名称不能为空

// ✅ 正确位置
def good[check]<T>(..) = ...       // [checker] 在泛型之前，函数名之后

// ✅ 任意函数皆可用
def simple[check](x: int) -> int = x * 2    // 普通函数
magic map<T> =
    def __map__[check](self, f: fn(T) -> T) -> Iterable<T> = ...  // 魔法方法
```
