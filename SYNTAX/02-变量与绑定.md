# LZ 变量与绑定

> 规范版本: 3.3 · 基于编译器源码 · 最后校订: 2026-08-05

本文档定义 Lang-Zone 的变量绑定语义：默认可变、`let` 不可变、`const` 常量、`ref` 引用。

---

## 一、核心语义

Lang-Zone 的变量绑定与 Rust 相反：

> **默认绑定可变更（mutable）**。只有显式使用 `let` 才是不可变绑定。

| 绑定形式 | 可变性 | 说明 |
|----------|:------:|------|
| `let x = 42` | 不可变绑定 | 不可重新赋值 |
| `x = 42` | 默认可变绑定 | 默认可重新赋值 |
| `let mut x = 42` | **显式可变绑定** | 与 `x = 42` 完全等价（语法糖，见 §2.3）；仅用于强调可变性 |
| `ref x = 42` | **可变引用** | 可重新赋值（`x = 100`），通过引用修改原值 |
| `let ref x = 42` | **不可变引用** | 不可重新赋值 |

> **ref 弱化**：`ref x = s` 与 `x = &s` 等价（取引用绑定）；`ref x = &s` 是对引用再取地址（二级引用），合法（见 [13-指针与引用.md](13-指针与引用.md) §2.1）。
> **禁止组合**: `let mut ref x = 42` 为非法绑定形式（`let` 已标示不可变, 与 `ref` 互斥, `mut` 为冗长修饰）。
---

## 二、默认可变绑定

### 2.1 基本语法

```lz
x = 42            // 默认可变
x = 100           // 重新赋值，合法
print(x)          // 100

y = "hello"
y = "world"       // 合法
```

### 2.2 带类型注解

```lz
x: int = 42       // 默认可变 + 类型注解
x = 100           // 合法
```

### 2.3 mut 修饰符（no-op / 显式可变）

```lz
mut x = 42        // 等价于 x = 42
mut y: int = 42   // 等价于 y: int = 42
let mut z = 42    // 等价于 z = 42（显式可变语法糖，与默认可变绑定完全等价）
```

`mut` 关键字仅作为装饰性标记存在，不改变语义；`let mut x = v` 中 `mut` 覆盖 `let` 的不可变语义，整体等价于默认可变绑定 `x = v`（`let` 仅对 `let x = v` 表示不可变）。

> `mut` 在变量绑定中是 no-op（默认已可变），但在 struct 方法参数中 `mut self` 表示 `&mut Self`（可变引用）。详见 [06a-struct.md](06a-struct.md)。

## 三、let 不可变绑定

### 3.1 基本语法

```lz
let x = 42        // 不可变
// x = 100        // ❌ 编译错误
```

### 3.2 带类型注解

```lz
let x: int = 42
let name: str = "world"
let pi: f64 = 3.14159
```

### 3.3 解构绑定

```lz
let (a, b) = (1, 2)     // 元组解构
let Some(v) = opt        // Option 解构（顶层 let 亦支持模式解构，见 00 §1.7）

// `..` rest 模式：忽略其余元素
let (first, ..,) = (1, 2, 3, 4)    // first=1，其余忽略
let (head, .., tail) = xs          // 解构 head 和 tail，中间忽略
```

## 四、const 编译期常量

### 4.1 语法

```lz
const MAX_SIZE: int = 1000
const PI: f64 = 3.14159
const GREETING: str = "hello"
```

- 必须在声明时初始化
- 值必须在编译期可确定
- 不支持运行时表达式

### 4.2 错误示例

```lz
// ❌ 常量值需编译期可求值——以下使用运行时调用，需用 comptime 包裹
const X: int = rand()       // 错误：运行时表达式
const NOW: str = get_time() // 错误：运行时表达式
```

### 4.3 使用 `comptime` 包裹运行时求值

```lz
comptime:
    const LEN: int = some_list.len()    // ✅ comptime 块内，编译期执行
    const NOW: str = get_time()         // ✅ comptime 块内
```

## 五、ref 引用绑定

> **为何有 `ref` 和 `&` 两套符号？** 声明引用用 `ref`（变量绑定语法），取引用用 `&`（表达式操作符）。这是因为 LZ 的变量绑定由关键字（`let`/`ref`/`mut ref`）控制语义，而表达式中 `&x` 产生引用值。生成 Rust 后两者统一为 `&`/`&mut`，但 LZ 语法层需要区分"声明一个新引用绑定"和"获取已有变量的引用值"。

### 5.1 可变引用

> 遵循 LZ "默认可变"原则：`ref r = x` 创建**可变引用**（等价于 Rust `&mut T`），可修改原值。

```lz
x = 42
ref r = x         // r 是 x 的可变引用（无 `let`，默认可变）
r = 100           // 通过引用修改 x
print(x)          // 100

// mut ref 等价于 ref（mut 为 no-op）
mut ref m = x     // 也是可变引用
```

### 5.2 不可变引用

```lz
x = 42
let ref r = x     // r 是 x 的不可变引用（`let` 强制不可变）
// r = 100        // ❌ 编译错误
```

### 5.3 引用绑定字面量

```lz
ref r = 42         // 创建临时变量存 42，r 指向它（可变引用）
let ref s = 42     // 不可变引用指向临时变量
```

直接对字面量/常量取引用时，编译器自动创建临时变量存储该值，引用指向该临时变量。

对应的 Rust 映射：

| LZ | Rust |
|----|------|
| `ref r = x` | `let r = &mut x;` |
| `let ref r = x` | `let r = &x;` |
| `ref r = 42` | `let mut tmp = 42; let r = &mut tmp;` |

```lz
x = 42
let ref r = x     // r 是 x 的不可变引用（`let` 强制不可变）
// r = 100        // ❌ 编译错误
```

## 六、owned 所有权转移

```lz
//owned s: str = "hello"    // 错误，owned 只修饰形参
def greet(owned name: str) = print(f"Hello, {name}!") // owned 只修饰形参
def greet1(name: str) = print(f"Hello, {name}!") // owned 只修饰形参

s: str = "Alice" // 这个就是自带 owned
t = s^                    // 所有权转移给 t（后缀 ^ 标记移动）

//greet(s)                //ERROR, ❌ s 已被移动

greet(t)                // 编译通过,自动转移所有权，等同于 greet(t^)

// print(t)               // ❌ t 已被移动

def foo(..) = print("called foo!")

// 错误，args 属于内部注入 ，没有个形参
//foo(s=(42,"foo"))

name = "Alice"

greet(name~) // 合法，等价于 greet(name = name^) `name~` 是命名参数的简化糖写法
greet1(name~) // 合法，等价于 greet1(name = name) `name~` 是命名参数的简化糖写法
//greet(name^~) // 错误，画蛇添足，编译器不认识，`找不到‘name^’ 这个变量`
//greet1(name^~) // 错误，画蛇添足，编译器不认识，`找不到‘name^’ 这个变量`
greet1(name=name^) // 合法，greet1 不关心参数所有权，直接复制，但是你给我所有权，那也行
```

## 七、海象运算符 `:=`

在表达式中赋值并返回值：

```lz
if (n := compute()) > 0:
    print(n)
    print("positive")

// 等价于：
n = compute()
if n > 0:
    print(n)
    print("positive")

count = 0

def count_up() -> int =
    count += 1
    count

while (n := count_up()) < 10:
    print(n)

```

## 八、错误语法边界

```lz
// ❌ let 绑定不可重新赋值
let x = 1
x = 2                       // 错误

// ❌ const 运行时赋值
const X: int = rand()       // 错误：运行时表达式，需用 comptime 包裹

// ❌ let owned 语义矛盾（解析器忽略 owned）
let owned s: str = "hi"     //错误： owned 只能修饰 形参

// ❌ 变量名与关键字冲突
let if = 1                  // 错误：if 是关键字
let match = 2               // 错误：match 是关键字
let test = 3                // 错误：test 是关键字

// ❌ 禁止组合: let mut ref 冗长修饰
let mut ref x = 42          // 错误: let 与 ref 互斥, mut 为冗长修饰

// ⚠️ `_` 是丢弃占位符，不是普通变量名
let _ = some_func()         // 合法: 绑定到 _ 即丢弃返回值
_ = some_func()             // 等价的丢弃写法（见下）

// ✅ 正确的丢弃写法
_ = some_func()             // 仅求副作用, 丢弃返回值

// ⚠ 变量遮蔽 (shadowing)
let x = 1                   // 合法: 同作用域内可用 let 遮蔽之前的同名绑定
let x = "hello"             // 合法: x 类型变为 str, 旧绑定被遮蔽
// 遮蔽后旧绑定不可访问, 其资源按所有权规则释放
// 遮蔽只影响同名标识符, 不影响捕获该标识符的闭包（闭包捕获的是遮蔽前的绑定）
```
