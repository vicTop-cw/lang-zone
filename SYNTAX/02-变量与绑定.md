# LZ 变量与绑定

> 规范版本: 3.3 · 基于编译器源码 · 最后校订: 2026-09-14

本文档定义 Lang-Zone 的变量绑定语义：默认可变、`let` 不可变、`const` 常量、`ref` 引用，以及修饰符装饰器（`@mut` / `@immut` / `@ref` / `@owned` / `@const` / `@static` / `@shared` / `@cell` / `@lazy` / `@comptime` / `@source` 及融合型）。

---

## 一、核心语义

Lang-Zone 的变量绑定与 Rust 相反：

> **默认绑定可变更（mutable）**。只有显式使用 `let` 才是不可变绑定。

| 绑定形式 | 可变性 | 说明 |
|----------|:------:|------|
| `let x = 42` | 不可变绑定 | 不可重新赋值 |
| `x = 42` | 默认可变绑定 | 默认可重新赋值 |
| `let mut x = 42` | **显式可变绑定** | 与 `x = 42` 完全等价（语法糖，见 §2.3）；仅用于强调可变性 |
| `ref x = 42` | **可变引用** | 可重新赋值（`x = 100`），通过引用修改原值 |
| `let ref x = 42` | **不可变引用** | 不可重新赋值 |
| `owned x = 42` | **强制消费绑定** | 必须显式消费（`x^` / `return x` / 传 owned 形参），消费后毒化（见 §六） |
| `let owned x = 42` | **不可变 + 强制消费** | 不可重新赋值，且必须显式消费 |
| `mut owned x = 42` | **可变 + 强制消费** | 可重新赋值，且必须显式消费 |

> **ref 弱化**：`ref x = s` 与 `x = &s` 等价（取引用绑定）；`ref x = &s` 是对引用再取地址（二级引用），合法（见 [13-指针与引用.md](13-指针与引用.md) §2.1）。
> **禁止组合**: `let mut ref x = 42` 为非法绑定形式（`let` 已标示不可变, 与 `ref` 互斥, `mut` 为冗长修饰）。

## 二、默认可变绑定

### 2.1 基本语法

```lz
x = 42            // 默认可变
x = 100           // 重新赋值，合法
print(x)          // 100

y = "hello"
y = "world"       // 合法
```

### 2.2 带类型注解

```lz
x: int = 42       // 默认可变 + 类型注解
x = 100           // 合法
```

### 2.3 mut 修饰符（no-op / 显式可变）

```lz
mut x = 42        // 等价于 x = 42
mut y: int = 42   // 等价于 y: int = 42
let mut z = 42    // 等价于 z = 42（显式可变语法糖，与默认可变绑定完全等价）
```

`mut` 关键字仅作为装饰性标记存在，不改变语义；`let mut x = v` 中 `mut` 覆盖 `let` 的不可变语义，整体等价于默认可变绑定 `x = v`（`let` 仅对 `let x = v` 表示不可变）。

> `mut` 在变量绑定中是 no-op（默认已可变），但在 struct 方法参数中 `mut self` 表示 `&mut Self`（可变引用）。详见 [06a-struct.md](06a-struct.md)。

## 三、let 不可变绑定

### 3.1 基本语法

```lz
let x = 42        // 不可变
// x = 100        // ❌ 编译错误
```

### 3.2 带类型注解

```lz
let x: int = 42
let name: str = "world"
let pi: f64 = 3.14159
```

### 3.3 解构绑定

```lz
let (a, b) = (1, 2)     // 元组解构
let Some(v) = opt        // Option 解构（顶层 let 亦支持模式解构，见 00 §1.7）

// case struct 提取解构（对应 Scala unapply / unapplySeq）
let p = PointEx(1, 2)
let PointEx(x, y) = p    // 编译为 let (x, y) = p.__unapply__()

// `..` rest 模式：忽略其余元素
let (first, ..,) = (1, 2, 3, 4)    // first=1，其余忽略
let (head, .., tail) = xs          // 解构 head 和 tail，中间忽略
```

> **case struct 提取解构**：`let PointEx(x, y) = p` 要求 `PointEx` 是 **case struct**（编译器自动配 `__unapply__`，见 [06d-内置魔法trait和全局函数.md](06d-内置魔法trait和全局函数.md) §九点五）或显式实现 `def __unapply__(self)` 的普通 struct。解构在 IR 层糖化为 `let (x, y) = p.__unapply__()`，复用元组解构机制（提取出的各字段按位置绑定）。循环变量同样支持此语法，见 [05-控制流.md](05-控制流.md) §3.1 `for PointEx(x, y) in pts`。

## 四、const 编译期常量

### 4.1 语法

```lz
const MAX_SIZE: int = 1000
const PI: f64 = 3.14159
const GREETING: str = "hello"
```

- 必须在声明时初始化
- 值必须在编译期可确定
- 不支持运行时表达式

### 4.2 错误示例

```lz
// ❌ 常量值需编译期可求值——以下使用运行时调用，需用 comptime 包裹
const X: int = rand()       // 错误：运行时表达式
const NOW: str = get_time() // 错误：运行时表达式
```

### 4.3 使用 `comptime` 包裹运行时求值

```lz
comptime:
    const LEN: int = some_list.len()    // ✅ comptime 块内，编译期执行
    const NOW: str = get_time()         // ✅ comptime 块内
```

## 五、ref 引用绑定

> **为何有 `ref` 和 `&` 两套符号？** 声明引用用 `ref`（变量绑定语法），取引用用 `&`（表达式操作符）。这是因为 LZ 的变量绑定由关键字（`let`/`ref`/`mut ref`）控制语义，而表达式中 `&x` 产生引用值。生成 Rust 后两者统一为 `&`/`&mut`，但 LZ 语法层需要区分"声明一个新引用绑定"和"获取已有变量的引用值"。

### 5.1 可变引用

> 遵循 LZ "默认可变"原则：`ref r = x` 创建**可变引用**（等价于 Rust `&mut T`），可修改原值。

```lz
x = 42
ref r = x         // r 是 x 的可变引用（无 `let`，默认可变）
r = 100           // 通过引用修改 x
print(x)          // 100

// mut ref 等价于 ref（mut 为 no-op）
mut ref m = x     // 也是可变引用
```

### 5.2 不可变引用

```lz
x = 42
let ref r = x     // r 是 x 的不可变引用（`let` 强制不可变）
// r = 100        // ❌ 编译错误
```

### 5.3 引用绑定字面量

```lz
ref r = 42         // 创建临时变量存 42，r 指向它（可变引用）
let ref s = 42     // 不可变引用指向临时变量
```

直接对字面量/常量取引用时，编译器自动创建临时变量存储该值，引用指向该临时变量。

对应的 Rust 映射：

| LZ | Rust |
|----|------|
| `ref r = x` | `let r = &mut x;` |
| `let ref r = x` | `let r = &x;` |
| `ref r = 42` | `let mut tmp = 42; let r = &mut tmp;` |

## 六、owned 所有权转移

`owned` 既可修饰**形参**，也可修饰**变量绑定**——强制显式消费（线性语义），消费后原变量毒化。

### 6.1 owned 变量绑定

```lz
owned fd = open("file.txt")      // 强制消费：必须显式消费 fd
mut owned buf = alloc(1024)       // 可变 + 强制消费
let owned cfg = load_config()     // 不可变 + 强制消费

// ❌ 编译错误：owned 变量未消费
// print(fd)                     // 读取不是消费

fd^                               // ✅ 显式转移所有权（消费）
// print(fd)                     // ❌ fd 已毒化
```

**owned 变量强制消费的三种形式**（与 owned 形参一致，见 [03-函数基础.md](03-函数基础.md) §2.3）：

| 消费形式 | 示例 | 说明 |
|----------|------|------|
| 显式转移 | `x^` | 后缀 `^` 把所有权交给他人 |
| 返回 | `return x` | 作为返回值交出所有权 |
| 传 owned 形参 | `use_owned(x)` | 传给 `owned` 修饰形参的函数 |

> **毒化语义**：无论原变量在栈还是堆，`owned` 消费（`x^` / `return x` / 传 owned 形参）后原变量即失效——编译器按 `owned` 规则强制检查，再使用报编译错误。

### 6.2 owned 形参

```lz
def greet(owned name: str) = print(f"Hello, {name}!") // owned 修饰形参：必须拿到所有权
def greet1(name: str) = print(f"Hello, {name}!") // 无 owned：仿射，可丢弃

s: str = "Alice" // 这个就是自带 owned

//greet(s)                //ERROR, ❌ s 已被移动

greet1(t)                // 编译通过,自动转移所有权，等同于 greet1(t^)

// print(t)               // ❌ t 已被移动

def foo(..) = print("called foo!")

// 错误，args 属于内部注入 ，没有个形参
//foo(s=(42,"foo"))

name = "Alice"

greet(name~) // 合法，等价于 greet(name = name^) `name~` 是命名参数的简化糖写法
greet1(name~) // 合法，等价于 greet1(name = name) `name~` 是命名参数的简化糖写法
//greet(name^~) // 错误，画蛇添足，编译器不认识，`找不到‘name^’ 这个变量`
//greet1(name^~) // 错误，画蛇添足，编译器不认识，`找不到‘name^’ 这个变量`
greet1(name=name^) // 合法，greet1 不关心参数所有权，直接复制，但是你给我所有权，那也行
```

## 七、海象运算符 `:=`

在表达式中赋值并返回值：

```lz
if (n := compute()) > 0:
    print(n)
    print("positive")

// 等价于：
n = compute()
if n > 0:
    print(n)
    print("positive")

count = 0

def count_up() -> int =
    count += 1
    count

while (n := count_up()) < 10:
    print(n)

```

## 八、修饰符装饰器

修饰符装饰器表达**变量与形参**的属性、存储与求值形态。它与关键字修饰符（`let` / `mut` / `ref` / `owned` / `const`）表达同一语义，二者**二选一**。修饰符装饰器为**内置封闭集**，不可扩展。

### 8.1 两类装饰器

| 类别 | 书写位置 | 作用 |
|------|----------|------|
| **修饰符装饰器** | **与目标同行** | 表达目标的属性 / 存储 / 求值形态 |
| **普通装饰器** | **独占一行** | 为紧随其后的声明附加指示（见 [03e 复合综合](03e-复合综合.md) §二） |

```lz
@mut x = 42                  // 修饰符装饰器：显式可变（等价 mut x = 42）

@export(Rust)                // 普通装饰器：独占一行
def add(a: int, b: int) -> int = a + b
```

- 修饰符装饰器**与目标同行**；普通装饰器**独占一行**。位置不符 → 编译错误。

### 8.2 基础修饰符装饰器

修饰符装饰器**一律可修饰变量与形参**。

| 轴 | 装饰器 | 等价关键字 | 语义 |
|----|--------|-----------|------|
| 可变性 | `@mut` | `mut` | 显式可变 |
| 可变性 | `@immut` | `let` | 不可变 |
| 引用 | `@ref` | `ref` | 引用绑定 |
| 所有权 | `@owned` | `owned` | 强制消费（线性），消费后毒化 |
| 常量 | `@const` | `const` | 编译期常量 |
| 存储期 | `@static` | — | 静态存储（全局存在、可捕获） |
| 共享 | `@shared` | — | 共享 / 线程安全 |
| 内部可变 | `@cell` | — | 内部可变容器（外不可变、内可变） |
| 惰性 | `@lazy` | — | 绑定处不求值，存 thunk；首次访问求值并缓存一次 |
| 编译期 | `@comptime` | `comptime` | 值须编译期已知 |
| 实参形态 | `@source` | — | 实参以源码形式传入 |

```lz
@immut pi = 3.14159          // 不可变，等价 let pi = 3.14159
@const MAX: int = 1000       // 编译期常量，等价 const MAX: int = 1000
@lazy cfg = load_config()    // 首次访问才求值并缓存
@owned fd = open("f.txt")    // 强制消费

def f(@comptime n: int) -> int = n + 1   // 形参位：n 的实参须编译期已知
```

### 8.3 融合型修饰符装饰器

融合型是规范内置的组合形态，与其成分轴的并写等价。融合型分五族：

**① 引用族**

| 融合 | = | 语义 |
|------|---|------|
| `@borrow` | `@ref` + `@immut` | 不可变借用 |
| `@borrow_mut` | `@ref` + `@mut` | 可变借用 |
| `@rcell` | `@ref` + `@cell` | 共享的内部可变引用 |

**② 所有权族**

| 融合 | = | 语义 |
|------|---|------|
| `@take` | `@owned` + `@mut` | 可变消费 |
| `@take_ro` | `@owned` + `@immut` | 只读消费 |

**③ 共享 / 并发族**

| 融合 | = | 语义 |
|------|---|------|
| `@rc` | `@shared`（非原子） | 单线程共享 |
| `@arc` | `@shared`（原子） | 跨线程共享 |
| `@weak` | `@shared`（非持有） | 弱引用（不增计数） |
| `@mutex` | `@shared` + `@cell` | 互斥共享 |
| `@rwlock` | `@shared` + `@cell` | 读写锁共享 |
| `@atomic` | `@shared` + `@cell` | 原子标量共享 |

**④ 静态 / 惰性族**

| 融合 | = | 语义 |
|------|---|------|
| `@lazy_static` | `@static` + `@lazy` | 全局惰性初始化 |
| `@once` | `@lazy` + `@shared` | 只算一次并共享 |
| `@lazy_mut` | `@lazy` + `@mut` | 惰性 + 可变 |
| `@static_mut` | `@static` + `@mut` | 可变静态 |

**⑤ 编译期族**

| 融合 | = | 语义 |
|------|---|------|
| `@compile_time` | `@comptime` + `@const` | 编译期常量 |
| `@meta` | `@comptime` + `@source` | 元编程（源码 + 编译期） |

### 8.4 组合规则

- 每个目标**至多一个**修饰符装饰器；需要多个轴时用 §8.3 的融合型。
- 修饰符装饰器与其等价关键字在同一目标上**二选一**，不并写。
- 与 `let` 的组合：`@immut` 与 `let` 等价；`let` 可与正交轴的修饰符装饰器并存（如 `let @shared x = v`）；`@mut` / `@ref` 等改变可变性的装饰器与 `let` 的不可变语义冲突。

## 九、错误语法边界

```lz
// ❌ let 绑定不可重新赋值
let x = 1
x = 2                       // 错误

// ❌ const 运行时赋值
const X: int = rand()       // 错误：运行时表达式，需用 comptime 包裹

// ❌ owned 变量未消费
owned fd = open("f")     // 必须显式消费 fd，否则编译错误
// fd^                     // ✅ 消费（见 §六 6.1）

// ❌ owned 变量消费后再次使用（毒化）
owned buf = alloc(1)
buf^
// print(buf)              // 错误：buf 已毒化

// ❌ 变量名与关键字冲突
let if = 1                  // 错误：if 是关键字
let match = 2               // 错误：match 是关键字
let test = 3                // 错误：test 是关键字

// ❌ 禁止组合: let mut ref 冗长修饰
let mut ref x = 42          // 错误: let 与 ref 互斥, mut 为冗长修饰

// ⚠️ `_` 是丢弃占位符，不是普通变量名
let _ = some_func()         // 合法: 绑定到 _ 即丢弃返回值
_ = some_func()             // 等价的丢弃写法（见下）

// ✅ 正确的丢弃写法
_ = some_func()             // 仅求副作用, 丢弃返回值

// ❌ 修饰符装饰器须与目标同行
@mut
x = 42                      // 错误：修饰符装饰器与目标不同行

// ❌ 普通装饰器须独占一行
@export(Rust) def f() = 1   // 错误：普通装饰器与目标同行

// ❌ 每目标至多一个修饰符装饰器
@shared @mut y = 0          // 错误：须改用融合型 @atomic

// ❌ 与 let 的不可变语义冲突
let @mut z = 1              // 错误：@mut 与 let 不可并写

// ❌ 非内置修饰符装饰器（内置封闭集）
@magic_mod w = 1            // 错误：修饰符装饰器为内置封闭集，无 @magic_mod

// ⚠ 变量遮蔽 (shadowing)
let x = 1                   // 合法: 同作用域内可用 let 遮蔽之前的同名绑定
let x = "hello"             // 合法: x 类型变为 str, 旧绑定被遮蔽
// 遮蔽后旧绑定不可访问, 其资源按所有权规则释放
// 遮蔽只影响同名标识符, 不影响捕获该标识符的闭包（闭包捕获的是遮蔽前的绑定）
```
