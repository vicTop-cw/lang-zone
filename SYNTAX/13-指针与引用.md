# LZ 指针与引用

> 规范版本: 3.3 · 基于编译器源码 · 最后校订: 2026-08-05

本文档定义 Lang-Zone 的指针类型与引用系统。

---

## 一、指针类型

LZ 不要求显式写出 `dyn` 关键字。当你使用 `Box`、`Rc`、`Arc` 等指针包裹一个 trait 类型时，`dyn` **自动隐含**。

### 1.1 内置指针与内部可变性类型

| LZ 指针 | Rust 映射 | 说明 |
|---------|-----------|------|
| `Box<T>` | `Box<dyn T>` | 独占所有权堆分配 |
| `Rc<T>` | `Rc<dyn T>` | 引用计数（单线程） |
| `Arc<T>` | `Arc<dyn T>` | 原子引用计数（多线程） |
| `Cell<T>` | `Cell<T>` | 内部可变性（Copy 类型） |
| `RefCell<T>` | `RefCell<T>` | 内部可变性（运行时借用检查） |

> **注意**：`Cell<T>` / `RefCell<T>` 是**内部可变性容器**，用于在不要求 `&mut` 的情况下修改内部值；它们**不是** Box/Rc/Arc 那样的堆指针/智能指针，不拥有指针式间接。
>
> **裸指针**：写作 `*T`（如 `*i64`），仅在 `@unsafe` 作用域内可声明与解引用（见 §2.3）。

### 1.2 `dyn` 隐式规则

```lz
// LZ 写法：
let x: Box<Drawable> = Box.new(Circle(...))

// 生成的 Rust：
// let x: Box<dyn Drawable> = Box::new(Circle { ... });
```

规则：只要 trait 用于指针内部，`dyn` **自动隐含**，无需手动写 `dyn`。`dyn` 不作为 LZ 关键字存在。

### 1.3 指针 + 具体类型

指针包裹具体类型时不加 `dyn`：

```lz
let x: Box<int> = Box.new(42)            // Rust: Box<i64>
let y: Rc<List<int>> = Rc.new([1,2,3])  // Rust: Rc<Vec<i64>>
let z: Arc<Dict<str, int>> = Arc.new({}) // Rust: Arc<HashMap<String, i64>>
```

## 二、引用

### 2.1 引用绑定

| 语法 | 语义 | Rust 映射 |
|------|------|-----------|
| `ref r = x` | 可变引用 | `let r = &mut x` |
| `let ref r = x` | 不可变引用 | `let r = &x` |

```lz
x = 42
ref r = x           // r: &mut int，可通过 r 修改 x
r = 100             // x 也变成 100
```

### 2.2 参数引用修饰符

| 修饰符 | 语义 | Rust 映射 |
|--------|------|-----------|
| `ref x: T` | 不可变引用参数 | `x: &T` |
| `mut ref x: T` | 可变引用参数 | `x: &mut T` |

```lz
def read(ref data: List<int>) -> int =
    data.len()                           // &List<i64>

def modify(mut ref data: List<int>) =
    data.push(42)                        // &mut List<i64>
```

### 2.3 `@unsafe` 作用域边界

`@unsafe` 装饰器用于标记包含指针操作的作用域。其规则：

1. **可装饰**: `def` 函数、`impl` 块（对整个 impl 生效）、`struct` 内部的个别方法。
2. **不可装饰**: `trait`（trait 是抽象契约，不应有 unsafe 标记）、`@unsafe` 构建块之间（构建块已隐式 unsafe，见 §三）。
3. **嵌套规则**: `@unsafe` 函数内可再调用另一个 `@unsafe` 函数。编译器在跨越 `@unsafe` 边界时将 pointer 类型转换为 opaque handle，反之亦然。

```lz
@unsafe
def deref_ptr(ptr: *int) -> int =       // 仅 @unsafe 内可声明 *int
    return *ptr                         // 仅 @unsafe 内可解引用

// ❌ 错误: trait 不可标记 @unsafe
@unsafe
trait UnsafeTrait =                     // 编译期错误
    def raw_op(self) -> *int

// ✅ 正确: impl 块可标记 @unsafe
@unsafe
impl MyType =
    def raw_op(self) -> *int = ...      // 整个 impl 在 unsafe 上下文中
```

## 三、所有权 `^` 与 `owned`

```lz
let x = "hello"
let y = x^           // x 的所有权转移给 y
// print(x)          // ❌ x 已被移动
```

`^` 是后缀运算符，标记显式所有权转移。参数传递时自动 `owned`（等价于 `^`）。

**`owned` 修饰符**（形参/变量绑定均可，见 [02-变量与绑定.md](02-变量与绑定.md) §六、[03-函数基础.md](03-函数基础.md) §2.3）：

| 场景 | 语法 | 强制消费 | 消费后原变量 |
|------|------|:---:|------|
| 形参 | `def f(owned x: T)` | **是**（`x^` / `return x` / 传 owned 形参） | 毒化 |
| 变量绑定 | `owned x = expr` | **是**（同上） | 毒化 |
| 可变变量 | `mut owned x = expr` | **是** | 毒化 |
| 不可变变量 | `let owned x = expr` | **是** | 毒化 |

> **毒化**：无论原变量在栈还是堆，`owned` 消费后原变量即失效，再使用报编译错误。
> **非法组合**：`owned ref x: T`（引用无所有权可消费）；函数实参 `owned cb: fn(T)`（函数值不能 owned）。

## 四、取引用 `&` 与装箱 `Box.new`

### 4.1 取引用 `&`

`&` 前缀运算符获取一个实例的**引用**（与 C/Rust 一致），与 `ref` 绑定互逆：

```lz
let x = 42
let r = &x              // r: &int（不可变引用），等价于 let ref r = x

let y = 0
let m = &mut y          // m: &mut int，等价于 ref m = y
```

**语义**：`&` = 取引用（产生引用值，不移动、不装箱）；类型注解中的 `&T` 与之对应（`ref x: T` → `&T`）。

### 4.2 装箱取指针 `Box.new` / `Rc.new` / `Arc.new`

需要**堆指针**（`Box<T>` / `Rc<T>` / `Arc<T>`）时用对应构造器显式装箱，不使用一元运算符：

```lz
let x = 42
let p = Box.new(42)       // p: Box<int>（默认，推断上下文）
let p: Rc<int> = Rc.new(42)    // 显式 Rc 指针
let q: Arc<int> = Arc.new(42)  // 显式 Arc 指针

let s = "hello"
let ps = Box.new(s)       // ps: Box<str>
```

**语义**：装箱 = 将值移动到堆上并返回智能指针；`Box.new` 默认，`Rc.new`/`Arc.new` 按需选择。

```
x  ──&──→  r（引用 &T，不移动）
x  ──Box.new──→  p（指针 Box<T>，移动）
p  ──* / ptr[0]──→  x（解引用还原值）
```

## 五、解引用 `*` / `ptr[0]`

指针/引用可以通过一元 `*` 或索引 `ptr[0]` 解引用（与 C/Rust 一致）。

### 5.1 一元解引用 `*ptr`（首选）

```lz
let x = Box.new(42)
let val = *x            // 解引用，val = 42（映射 __deref__，见 12-操作符 §1.2）
```

### 5.2 索引解引用 `ptr[k]`

```lz
let x = Box.new(42)
let val = x[0]          // 等价 *x，解引用取索引 0，val = 42

let arr = Box.new([1, 2, 3])
let first = arr[0]      // 解引用后取索引 0，first = 1
let third = arr[2]      // third = 3
```

- `ptr[0]` — 解引用获取指针内部值（等价 `*ptr`）
- `ptr[k]`（k > 0）— 解引用后对集合类型取索引

## 六、设计审视：`*` vs `&` 约定

| 操作 | LZ | C/Rust | 评估 |
|------|:--:|:------:|------|
| 取引用 | `&x` | `&x` | ✅ 一致 |
| 装箱取指针 | `Box.new(x)` | `Box::new(x)` | ✅ 一致 |
| 解引用 | `*ptr` / `ptr[0]` | `*ptr` | ✅ 一致 |

**结论**：
1. `&x` = 取引用，`*ptr` = 解引用，`Box.new(x)` = 装箱——**与 C/Rust 完全一致**。
2. `ptr[0]` 作为 `*ptr` 的索引等价形式保留，便于集合类型解引用后直接取元素。
3. `&` 在类型注解中表示引用类型（`ref x: T` → `&T`），运行时取引用用 `&x`。

## 七、`dyn` 设计决策

**LZ 不需要 `dyn` 关键字**。原因：

1. 指针类型（`Box` / `Rc` / `Arc`）包裹 trait 时自动生成 `dyn`
2. 编译器在 codegen 阶段判断指针内部是否为 trait → 自动添加 `dyn`
3. 用户无需关心 Rust 的 `dyn` 概念

```
LZ:  Box<Drawable>      → Rust: Box<dyn Drawable>
LZ:  Rc<Clone>          → Rust: Rc<dyn Clone>
LZ:  Box<int>           → Rust: Box<i64>          (具体类型，无dyn)
```

## 八、语法边界

```lz
// ❌ dyn 不是 LZ 关键字
let x: Box<dyn Drawable> = ...     // 错误：dyn 不是有效标识符

// ✅ 正确
let x: Box<Drawable> = ...

// ❌ ref 不能用于裸值绑定后又转移
let ref r = x
let y = r^                         // 错误：引用不能转移所有权
```
