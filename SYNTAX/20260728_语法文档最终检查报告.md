## 一、P0 关键问题

### 1. `self` 语义在普通方法与魔法方法中不一致

**问题描述**：
- `06a-struct.md` §3.2：普通 struct 方法中 `self`（无 `mut`）= **不可变引用 `&Self`**
- `06g-魔法综合.md` §1：魔法方法中 `self`（无 `mut`，owned 模式）= **消费所有权 `self: Self`**
- 同一语法 `self` 在不同上下文中表示相反的所有权语义

```lz
// 普通方法：self = &Self（不可变借用）
struct Point =
    x: f64
    def get_x(self) -> f64 = self.x   // self 是 &Self

// 魔法方法：self = Self（消费所有权）
magic add<T> =
    def __add__(self, other: T) -> T  // self 是 Self（owned）
```

**影响程度**：P0 严重设计不一致。同一语法不同语义，用户极易混淆。

**建议**：在 `06a-struct.md` 中明确列出所有 self 模式（`self`/`mut self`/`owned self` 等），并添加与魔法方法 self 模式的对照表。

### 2. `await` 使用规则自相矛盾

**问题描述**：
- `10-并发与异步.md` §1.2 明确规则："`await` 只能在 `async` 函数中使用"
- `10-并发与异步.md` §1.3 示例却展示在同步 `def main()` 中直接使用 `await`：

```lz
def main() =                 // 同步函数！
    let f1 = spawn fetch_data(10)
    let f2 = spawn fetch_data(20)
    let r1 = await f1        // ← 在同步函数中使用 await？
    let r2 = await f2
```

**影响程度**：P0 文档矛盾。用户无法确定 `await` 的正确使用场景。

**建议**：明确规则——要么 `await` 只能在 `async` 函数中使用（此时 §1.3 示例需修正），要么允许在同步函数中对 `spawn` 返回的 `Future` 使用 `await`（此时 §1.2 规则需修正）。

### 15. [NEW] `raises` 函数返回类型语义混乱

**问题描述**：
- `09-错误处理.md` §5.2 示例中：
```lz
def read_config() -> Dict<str, str> raises str =
    let content = read_file("config.json")?
    let parsed = parse_json(content)?
    Ok(parsed)       // ← 返回 Ok(parsed)，但返回类型是 Dict<str, str>
```
- 函数体内使用 `Ok(parsed)` 包装返回值，但返回类型标注为裸类型 `Dict<str, str>`
- 用户无法理解 `raises` 函数到底返回 `T` 还是 `Result<T, E>`
- 这与 `?` 操作符（§4.3 说 `?` 仅对 `Result` 类型有效，对自定义 `raises` 异常使用 `try/catch`）自相矛盾

**影响程度**：P1 语义混乱。`raises` 函数的返回类型模型不清晰。

**建议**：明确 `raises` 函数的返回类型语义——是返回 `T`（异常通过隐式 `Result` 传播）还是返回 `Result<T, E>`。

### 19. [NEW] `00-词法基础.md` `owned` 语义描述方向错误

**问题描述**：

- 实际语义是所有权转移给**被调用者（函数）**，而非调用者
- `02-变量与绑定.md` §六 示例正确展示了所有权转移给函数

```lz
// 00-词法基础.md 错误描述："所有权将被转移给调用者"
// 实际行为（02-变量与绑定.md）：所有权转移给函数
def greet(owned name: str) = print(f"Hello, {name}!")  // name 所有权转移给 greet
```

**影响程度**：P2 描述错误。方向性错误可能导致用户误解所有权模型。

### 21. [NEW] `99-内置预导入库.md` 中 `sort`/`reverse` 与 `filter` 签名风格不一致

**问题描述**：
- `sort(xs): (List<T>) -> List<T>` — 只接受 List
- `reverse(xs): (List<T>) -> List<T>` — 只接受 List
- `filter(xs, f): (Iter<T>, fn(T)->bool) -> Iter<T>` — 接受惰性迭代器
- `map(xs, f): (Iter<T>, fn(T)->R) -> Iter<R>` — 接受惰性迭代器
- 用户不清楚为什么 `sort` 和 `reverse` 只支持 List 而 `filter`/`map` 支持迭代器

**影响程度**：P2 签名不一致。
