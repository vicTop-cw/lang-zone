# LZ 表达式

> 规范版本: 3.3 · 基于编译器源码 · 最后校订: 2026-08-04

本文档定义 Lang-Zone 的完整表达式语法：运算符优先级、字面量、调用、方法访问、管道、推导式等。

---

## 一、概述

表达式是产生值的语法单元。LZ 的表达式涵盖字面量、运算符、调用、管道、推导式等。

> 完整运算符优先级表详见 **[12-操作符.md](12-操作符.md)** §二。

|------|------|

### 4.3 is 编译期同一性 / 类型兼容检查

`is` 是**编译期关键字**，运行时**不可使用**（Rust 无 RTTI，LZ 同路线）。它有两种编译期用法：

**① duck 约束内 — 单例同一性判定**（原始用途）

```lz
// duck 约束内 — 编译期单例同一性判定
duck Optional<T> =
    def is_none(ref self) -> bool
    // 可在 duck 内使用 `is None` 判定变体
```

`is` 支持的单例值：`None`、`Unit`、`Nil`。

**② 普通表达式 — 编译期类型兼容检查**（实现扩展）

`x is T`（`T` 为类型名）在编译期检查 `x` 的静态类型与 `T` 是否兼容，内联为 `Bool` 字面量：

```lz
let x = 5
print(x is int)     // true（编译期判定，非运行时 RTTI）
print(x is str)     // false
```

> 说明：这是编译期静态检查，生成 `true`/`false` 字面量，不产生任何运行时类型查询（`TypeId`/`type_name`）；RHS 不是简单类型名时回退为 `false`。

> 详见 [01b-duck关系约束.md](01b-duck关系约束.md)。

## 五、逻辑运算

```lz
a and b             // 逻辑与（短路）
a or b              // 逻辑或（短路）
not a               // 逻辑非
!a                  // 逻辑非（与 not 等价）
```

符号形式（与关键字完全等价）：

```lz
a && b              // 逻辑与，等价 a and b
a || b              // 逻辑或，等价 a or b
!a                  // 逻辑非，等价 not a
```

> `and`/`or`/`not` 是关键字形式，`&&`/`||`/`!` 是符号形式，两者完全等价。

## 十、管道 `|>`

管道将前一个表达式的结果作为数据传给右侧的 callable，**默认将数据预填充为右侧 callable 的首个位置参数**。

左侧可以是任意值 T；右侧必须是接收 T 的**单参 callable**（函数 / 闭包 / 方法 / 构造调用 / 实现 `__call__` 的实例），与 Python 的 callable 语义一致。

### 10.1 基本管道

```lz
data |> f            // 等价于 f(data)
data |> f |> g       // 等价于 g(f(data))

5 |> double          // double(5) → 10
```

### 10.2 带额外参数的管道

```lz
// 左操作数被自动插入为函数的第一个参数
10 |> add(1, 2, 3)       // add(10, 1, 2, 3) → 16
10 |> add                // add(10)
```

任何至少有一个位置参数的函数都可以直接用于管道。

### 10.3 Lambda 管道

```lz
10 |> |x| x * x          // 100
```

### 10.4 构造调用预填充

右侧是构造调用时，左侧数据自动预留为该类型的**首个字段**：

```lz
struct Point =
    x: f64
    y: f64

let p = 1.0 |> Point(2.0)   // Point { x: 1.0, y: 2.0 } — x 取左侧数据，y 取显式实参
```

### 10.5 `__call__` 实例（可调用对象）

右侧是实现 `__call__` 实例方法的实例时，等价于调用其 `__call__`，数据预填充为 `__call__` 的首个位置参数：

```lz
struct Point =
    x: f64
    y: f64

    def __call__(mut self, other: Point) -> Point =
        Point(self.x + other.x, self.y + other.y)

let p = Point(1.0, 2.0)
let p1 = p |> p      // 等价于 p.__call__(p) — 预留首个位置参数给 other
let p2 = p |> p1     // 等价于 p1.__call__(p)
```

任何实现了 `__call__` 的实例都是 callable，可出现在管道右侧。

### 10.6 左侧 `__lpipe__`（数据变换）

左侧数据在进入管道前，若其类型实现了 `__lpipe__`，先调用 `recv.__lpipe__()` 产出数据；未实现则原样使用（等价于返回自身）：

```lz
struct Box =
    v: int

    def __lpipe__(self) -> Box =
        // 放大数据
        Box(self.v * 10)

let r = Box(5) |> double   // 数据先经 __lpipe__ 变为 Box(50)，再传给 double
```

- 签名：`def __lpipe__<R>(self) -> R = ...`
- 默认实现：`def __lpipe__<R>(self) -> R = self`（即未实现时返回自身）

### 10.7 右侧 `__rpipe__`（处理函数工厂，优先于 `__call__`）

右侧实例实现了 `__rpipe__` 时优先于 `__call__`：`__rpipe__` 接收左侧数据，返回一个**单参处理函数**，管道用该函数处理数据：

```lz
struct Adder =
    base: int

    def __rpipe__(self, other: Adder) -> fn(Adder) -> Adder =
        |x: Adder| Adder(x.v + other.base)   // 基于 other 生成处理函数

let r = Adder(5) |> Adder(3)   // 优先走 __rpipe__：(right.__rpipe__(left))(left)
```

- 签名：`def __rpipe__<T,R>(self, other: T) -> fn<T,R>(T) -> R = ...`
- **优先级**：`__rpipe__` > `__call__` > 函数/构造/闭包预填充
- 未实现 `__rpipe__` 时看 `__call__`：若 `__call__` 不是单参函数（非 self 参数 ≠ 1），报编译错误
- 既无 `__rpipe__` 也无 `__call__` 的实例出现在右侧 → 报编译错误「不可调用」

### 10.8 集合管道

```lz
[1, 2, 3, 4, 5]
    |> map(|x| x * 2)         // [2, 4, 6, 8, 10]
    |> filter(|x| x > 5)      // [6, 8, 10]
    |> collect()
```

### 10.9 分派优先级总览

`data |> right` 的展开规则（从高到低）：

1. 左侧先经 `__lpipe__`（有则调用，无则原样）
2. 右侧是**实例**（已知 struct 类型变量）：
   - 实现 `__rpipe__` → `(right.__rpipe__(data))(data)`
   - 否则实现 `__call__` → `right.__call__(data, ...args)`（`__call__` 须为单参，否则报错）
   - 否则 → 报错「不可调用」
3. 右侧是**函数/构造/未知标识符** → 首参预填充调用 `right(data, ...args)`；已知 struct 按字段顺序映射（§10.4）
4. 右侧是**闭包/方法/其他表达式** → 直接调用 `right(data, ...args)`

> 注：`__pipe__` 魔法方法已废弃（2026-08-08 起），管道语义由上述通用 callable 规则驱动；旧版 `a |> b` 依赖 `__pipe__` trait 的实现已移除。

## 十六、列表推导

```lz
[x * 2 for x in lst if x > 0]    // 带过滤
[x + y for x in xs for y in ys]  // 多迭代器
```

语法规则：
- 支持多个 `if` 过滤条件：`[x for x in xs if x > 0 if x < 100]`
- 支持多个 `for` 迭代器：`[x + y for x in xs for y in ys]`
- 推导式变量不泄漏到外部作用域
- 字典推导：`{k: v for (k, v) in pairs if v > 0}`
- 集合推导：`{x for x in xs}`

## 十七、if 表达式

`if` / `elif` / `else` 后的冒号**必须换行 + 缩进**（非注解冒号规则）：

```lz
let result = if x > 0:
        "positive"
    else:
        "negative"

let grade = if score >= 90:
        "A"
    elif score >= 80:
        "B"
    else:
        "C"
```

单行 `if` 表达式**不合法**（冒号必须换行缩进）。

---

## 十八、match 表达式

`case` 的**冒号形式**必须换行 + 缩进；**胖箭头** `=>` 支持内联：

```lz
// 冒号形式：换行缩进（非注解冒号规则）
let msg = match n:
    case 0:
        "zero"
    case 1:
        "one"
    case _:
        "other"

// => 内联形式（前后留白）
let msg = match n:
    case 0 => "zero"
    case 1 => "one"
    case _ => "other"
```

## 二十、错误语法边界

```lz
// ❌ 冒号内联 — 非注解冒号必须换行+缩进
if x > 0: "positive"        // 错误：if 冒号后必须换行缩进
case 0: "zero"              // 错误：case 冒号后必须换行缩进，内联用 =>

// ❌ 优先级歧义（需加括号）
a + b * c          // 正确：* 优先级高
(a + b) * c        // 显式分组

// ❌ 索引越界（运行时错误）
xs.[0]             // 错误：. 和 [] 不要连用，用 xs[0]

// ❌ 管道右值不是函数
data |> 42         // 错误：管道右值必须是可调用

// ❌ 安全导航用于非 Option 类型
let x: int = 42
x?.method()        // 错误：int 不是 Option

// ❌ f-string 中非法表达式
f"{if x: 1}"       // 错误：f-string 不支持控制流表达式
f"{|x| x + 1}"     // 错误：f-string 不支持闭包
```
