# LZ 函数 — 可变参数

> 规范版本: 3.3 · 基于编译器源码 · 最后校订: 2026-08-05

LZ 提供三条相互独立、职责清晰的参数机制：

| 机制 | 语法 | 作用 | 是否注入变量 | 安全？ |
|------|------|------|:---:|:---:|
| **安全收集** | `lst: List<T>` | 自动收集位置实参到具名 List | 否（直接用 `lst`） | ✅ 安全 |
| **安全分隔符** | `/` 与 `*` | 仅划分位置/关键字边界，**不注入、不收集** | 否 | ✅ 安全 |
| **`..` 变参注入** | `..` / `..: Tuple` / `..: Dict` | 动态收集多余实参到 `args`/`kwargs` | ✅ 注入 | ❌ 无注解/异质为 unsafe（带具体注解则类型安全） |

> 引入 Python 式 `/` `*` 分隔体系，正是为了解决“我只想分割、不想注入、还要保持安全”的需求——`..` 一旦写就强制注入 `Any`/`dyn` 并标 unsafe，无法满足该场景。

> ⚠️ **核心规则（三类互不重叠）**：
> - **`/` 与 `*`**：纯语法分隔符，**不注入任何变量、不收集实参、类型安全**。仅用于约束“哪些参数只能位置传 / 只能关键字传”。
> - **`..`**：**始终**触发变参收集注入——无论是否带类型注解。无注解的 `..` 不是“仅分隔符”：
>   - **单个无注解 `..` → 只注入 `args`**（位置变长参数，元素类型 `Any`，等价于 `..: Tuple<Any, ..>`）；**不会**注入 `kwargs`。
>   - 想要 `kwargs` 必须显式 `..: Dict<...>`，或用**第二个 `..`**（`.., ..` 双收集）。
>   - 带注解只是把收集限定到某一侧（`Tuple`=args / `Dict`=kwargs）。
> - **同一签名里 `/`、`*` 分隔符与 `..` 注入互斥**（见 §三）：要么纯分割（安全），要么纯注入（unsafe），不能混用——混用会产生“谁负责边界”的歧义。

---

## 一、安全收集：`lst: List<T>`（无 `..`）

**不需要 `..`**。直接将最后一个形参类型为 `List<T>` 作为参数，编译器自动将所有位置实参收集到该 List 中：

```lz
def sum_all(values: List<int>) -> int =
    total = 0
    for v in values:
        total += v
    total

sum_all(1, 2, 3, 4, 5)           // 15 — 自动收集为 List<int>
sum_all()                          // 0  — 空参，values = []
sum_all([1, 2, 3])                // 15 — 显式传 List 也可以


def sum_all2(a: int ,b: int = 0, values: List<int>) -> int =
    total = a + b
    for v in values:
        total += v
    total

sum_all2(1, 2, 3, 4, 5)           // 15 — 自动收集为 List<int>
//sum_all2()                         //错误，a 为必参 
sum_all2(3)                         // 3 — b 默认为 0
sum_all2(a=3,b=4, 1,2,3)           // 13 —  1,2,3 自动收集为 List<int>
sum_all2(3,1,2,3)           // 9 —  2,3 自动收集为 List<int>,b=1
sum_all2(3,b=5,1,2,3)           // 14 —  1,2,3 自动收集为 List<int>,b=5
sum_all2(3,1,2,3,b=7)           // 16 —  1,2,3 自动收集为 List<int>,b=7


def sum_all3(a: int , values: List<int>,b: int = 0) -> int =
    total = a + b
    for v in values:
        total += v
    total

sum_all3(1, 2, 3, 4, 5)           // 15 — 2,3,4,5 自动收集为 List<int>，a=1, b=0（values 非末尾形参仍可收集位置实参）
sum_all3(3, [1, 2, 3])           // 9 —  1,2,3 自动收集为 List<int>, b=0
sum_all3(3, [1, 2, 3], 5)           // 14 —  1,2,3   ,b=5
sum_all3(3, [1, 2, 3], 7)           // 16 —  1,2,3   ,b=7



def sum_all4(a: int , values: List<int> = [] ) -> int =  // 可以有默认值，只看形参位置是不是最后一个且是不是List<T>
    total = a + b
    for v in values:
        total += v
    total

sum_all4(1)
sum_all4(1, [2, 3, 4]) // 10 —  正常用法
sum_all4(1,2,3,4)            // 10 —  1,2,3,4 自动收集为 List<int>

//sum_all4(1,[2,3],4)            //错误，[2,3],4 不属于同一个类型 ，除非你让int和 List<int> 拥有同一个 trait 实现

```

## 二、`..` 变参注入模式

`..` 是参数列表中的**变参注入标记**（非边界分隔符），最多出现 **2 次**。

### 2.1 核心规则：`..` 只负责变参注入（位置/关键字边界由 `/` `*` 负责）

> `..` **不划分**位置/关键字边界——那是 §三 安全分隔符 `/` 与 `*` 的职责。`..` 的唯一职责是**注入 `args`/`kwargs`** 收集多余实参。

```
[普通参数: 位置或关键字均可]  ..  [注入 args]   (..: Dict 或 第二个 .. → 注入 kwargs)
```

- **`..` 之前/之后的具名参数**：仍同时支持位置和关键字传递（除非被 `/` `*` 约束，见 §三）。
- **`..` 的作用**：在形参列表里出现即触发注入；它不强制“之前仅位置、之后仅关键字”。
- **`args` / `kwargs` 收集**：**只要出现 `..` 即注入 `args`**（见 §2.3 / §2.6）。单个无注解 `..` **只注入 `args`**；`kwargs` 仅在存在 kwargs 侧 `..`（`..: Dict<...>` 或第二个 `..`）时才注入。注解决定收集哪一侧、元素类型。

### 2.2 List 参数的位置语义

| 签名 | `lst` 传递方式 | 说明 |
|------|:---:|------|
| `f(lst: List<T>)` | 位置或关键字 | 无 `..` 参与。自动收集所有位置实参，或接收一个显式 List |
| `f(lst: List<T>, ..)` | 位置或关键字 | `..` 在末尾，`lst` 收集位置实参；bare `..` 仅注入 `args`（本例位置侧已被 lst 收集，故为空），**不**注入 kwargs，命名实参将报错 |
| `f(.., lst: List<T>)` | **仅关键字** | `..` 在 `lst` 之前，位置实参已被 `..` 注入 `args`，`lst` 只能收命名实参 → 表现为仅关键字（这是注入副作用，非边界约束；纯边界请用 §三 的 `*`） |
| `f(a: int, lst: List<T>, ..)` | 位置或关键字 | `a` 必须位置。`lst` 在后面不受 `..` 约束 |
| `f(.., a: int, lst: List<T>)` | a、lst 均仅关键字 | `..` 在最前，位置实参全入 `args`，a/lst 只能收命名实参 → 表现为仅关键字（纯边界约束见 §三 `*`） |

### 2.3 单 `..` 类型注解（args-only / kwargs-only）

**任何 `..` 都激活变参收集**，与是否带注解无关；但**单 `..` 无注解时只注入 `args`**（位置变长，元素 `Any`），不会注入 `kwargs`：

| 签名 | 收集内容 | 说明 |
|------|:---:|------|
| `f(..)` | ✅ args-only | 单 `..` **无注解**：仅收集位置参数，元素 `Any`（≡ `..: Tuple<Any, ..>`） |
| `f(..: Tuple<T>)` | ✅ args-only | `..` 类型为 `Tuple` = 仅收集位置参数（类型约束为 `T`） |
| `f(..: Tuple<T1, T2, ..>)` | ✅ args-only | 约束位置参数各自类型 |
| `f(..: Dict<K,V>)` | ✅ kwargs-only | `..` 类型为 `Dict` = 仅收集命名参数（值类型约束为 `V`） |
| `f(.., ..)` | ✅ args + kwargs | 双 `..`，两侧均收集（元素 `Any`） |
| `f(..: Tuple<T>, ..: Dict<K,V>)` | ✅ args + kwargs | 双 `..` 各自类型约束 |

```lz
// 无注解的单 .. → 仅注入 args（元素 Any），不注入 kwargs
def catch_all(..) =
    for v in args:
        print(f"arg: {v}")            // v: Any
    // kwargs 未注入：单 .. 无注解只收位置参数

catch_all(1, 2, 3)                     // args=[1,2,3]
// catch_all(1, name="x")             // ❌ 单 .. 无注解不收集 kwargs；命名实参需 ..: Dict 或第二个 ..

// kwargs-only — 只需要命名参数
def config(..: Dict<str, int>) =
    for (k, v) in kwargs:
        print(f"{k}: {v}")
config(timeout=30, retries=3)          // ok
// config(1, 2, 3)                     // ❌ 无 args 收集（被 Dict 限定为 kwargs-only）

// args-only — 只需要位置参数
def sum_all(..: Tuple<int>) =
    total = 0
    for v in args:
        total += v
    total
sum_all(1, 2, 3, 4)                    // 10

// args-only + 约束第1个为 str, 其余不限
def log(..: Tuple<str, ..>) =
    print(args[0])                     // args[0]: str
```

### 2.4 完整模式穷尽表

下表中：**P**=仅位置 | **K**=仅关键字 | **P/K**=均可 | **✅**=`args`/`kwargs` 变量被注入 | **—**=该侧未启用（无 `..`，或被注解限定到另一侧）

| # | 签名 | a | lst | b | args | kwargs | 说明 |
|:--|------|:--:|:--:|:--:|:--:|:--:|------|
| A1 | `f(a: T)` | P/K | — | — | — | — | 普通函数，无 `..`，不注入 |
| A2 | `f(a: T = v)` | P/K | — | — | — | — | 带默认值 |
| A3 | `f(lst: List<T>)` | — | P/K | — | — | — | 安全收集，自动收集位置实参（无 `..`） |
| A4 | `f(a: T, lst: List<U>)` | P/K | P/K | — | — | — | 混合，lst 收集剩余位置实参 |
| B1 | `f(.., a: T)` | — | — | K | ✅ | — | 前置 `..` → 仅注入 `args`（Any）；`a` 仅关键字 |
| B2 | `f(a: T, ..)` | P | — | — | ✅ | — | 后置 `..` → 仅注入 `args`（Any）；`a` 仅位置 |
| B3 | `f(a: T, .., b: U)` | P | — | K | ✅ | — | 中间 `..` → 仅注入 `args`（Any） |
| B4 | `f(.., a: T, b: U)` | — | — | K | ✅ | — | 两参数均仅关键字；`..` 仅注入 `args`（Any） |
| B5 | `f(lst: List<T>, ..)` | — | P/K | — | ✅ | — | `lst` 收集位置实参，`..` 仅注入 `args`（本例位置侧已被 lst 收集，故为空） |
| B6 | `f(.., lst: List<T>)` | — | K | — | ✅ | — | `lst` 仅关键字；`..` 仅注入 `args`（Any） |
| C1 | `f(..: Tuple<T>)` | — | — | — | ✅ | — | **单 `..`+Tuple = args-only（类型 T）** |
| C2 | `f(..: Dict<K,V>)` | — | — | — | — | ✅ | **单 `..`+Dict = kwargs-only（值类型 V）** |
| C3 | `f(a: T, ..: Tuple<U>)` | P/K | — | — | ✅ | — | 普通参数 + args-only（类型 U） |
| C4 | `f(..: Dict<K,V>, a: T)` | — | — | K | — | ✅ | kwargs-only（值类型 V）+ 关键字参数 |
| D1 | `f(.., ..)` | — | — | — | ✅ | ✅ | 双 `..`，args + kwargs 双收集（均 `Any`） |
| D2 | `f(..: Tuple<T>, ..)` | — | — | — | ✅ | ✅ | args 约束类型 T，kwargs `Any` |
| D3 | `f(.., ..: Dict<K,V>)` | — | — | — | ✅ | ✅ | args `Any`，kwargs 约束类型 V |
| D4 | `f(..: Tuple<T>, ..: Dict<K,V>)` | — | — | — | ✅ | ✅ | 双 `..` 各自类型约束 |
| D5 | `f(a: T, .., b: U, ..)` | P | — | K | ✅ | ✅ | 普通参数 + 双收集（均 `Any`） |
| D6 | `f(a: T, ..: Tuple<U>, b: V, ..: Dict<K,W>)` | P | — | K | ✅ | ✅ | 全量：位置+关键字+类型化双收集 |

> **`..` 类型判定规则**：`..` **始终**触发变参收集注入，与是否带注解无关。
> - **单 `..` 无注解 → 只注入 `args`**，元素类型 `Any`（即 `Tuple<Any, ..>`，位置变长参数）；**不注入 `kwargs`**。
> - 带注解 `..: Tuple<...>` → 仅注入 `args`（位置参数，元素类型约束）。
> - 带注解 `..: Dict<...>` → 仅注入 `kwargs`（命名参数，值类型约束）。
> - 双 `..`（第一个对应 `args` 侧、第二个对应 `kwargs` 侧）：两侧均注入；任一侧可独立加注解或留空（留空即该侧为 `Any`）。`kwargs` 仅在存在 kwargs 侧 `..`（`..: Dict` 或第二个 `..`）时注入。
> - 当某侧已被显式 `List<T>` / 具名参数消费时，对应注入变量可能为空（例如 `f(lst: List<T>, ..)` 中位置实参已被 `lst` 收集，`args` 为空）。

### 2.5 类型标注

`..` 支持附带类型注解，约束 `args` / `kwargs` 的动态类型：

```lz
// ..: Tuple<T1, T2, ...> — 约束 args 的元素类型
def log(..: Tuple<str, int>, ..) =
    for v in args:
        print(v)              // v: str | int

// ..: Dict<K, V> — 约束 kwargs 的值类型
def config(.., ..: Dict<str, str | int>) =
    for (k, v) in kwargs:
        print(f"{k}: {v}")    // v: str | int

// 两端都标注
def handler(..: Tuple<str, ..>, ..: Dict<str, str>) =
    // args 元素类型: str（可变长元组）
    // kwargs 值类型: str
    ...
```

| 标注 | 含义 |
|------|------|
| `..: Tuple<T>` | args 中每个元素类型为 T |
| `..: Tuple<T1, T2, ...>` | args 按位置约束不同类型 |
| `..: Dict<K, V>` | kwargs 的值类型为 V |
| 无标注（单 `..`） | 仅注入 `args`，元素默认 `dyn Any` 擦除 |

### 2.6 内置变量

只要出现 `..`，编译器就按下面的规则注入 `args` 和/或 `kwargs`（并非总有两者）。**注入变量的元素类型取决于 `..` 的注解**：带具体注解 → 注入**具体类型**（编译期已知，内部免 `as`、免 `raises`）；无注解或异质兜底 → 注入 `dyn Any`（unsafe 边界，需 `as`/`match`）。

| 变量 | 类型 | 出现条件 |
|------|------|---------|
| `args` | `List<T>`（当 `..: Tuple<T>`） | `..` 注解为 `Tuple<T>`，元素类型 T 在编译期确定 |
| `args` | `Vec<Box<dyn Any>>`（擦除） | 出现 `..` 且无 `Tuple` 注解（裸 `..` 或 `.., ..` 的 args 侧） |
| `kwargs` | `Dict<K, V>`（当 `..: Dict<K,V>`） | `..` 注解为 `Dict<K,V>`，值类型 V 在编译期确定 |
| `kwargs` | `HashMap<String, Box<dyn Any>>`（擦除） | 存在 kwargs 侧 `..`：`.., ..` 的第二个 `..` 或裸 `..` 被允许收 kwargs 时 |

> 见 §2.8：如何在内部**免类型转换**直接拿到明确类型。

### 2.7 `@overload` 与可变参数共用

`@overload` 允许多个同名 `def` 按签名分派。**变长参数 `..` 与重载的分派原则是：静态分派只看“显式参数”，`..` 使该 overload 成为“变长兜底”候选。**

**规则：**
1. **每个 `@overload` 定义可各自带 `..`**，签名相互独立。
2. **分派顺序**：
   - 先用**不带 `..`** 的 overload，按其固定显式参数（位置数量、关键字名、注解类型）做静态匹配；
   - 若无固定 overload 命中，再按**声明顺序**对带 `..` 的 overload 做兜底匹配（同样先看显式参数是否吻合）。
3. **冲突禁止**：两个 overload 若**显式参数完全相同、仅在 `..` 注解上不同**（如 `..: Tuple<int>` vs `..: Tuple<str>`），编译期无法区分（因分派只看显式参数、`..` 注解不参与，擦除后二者签名相同），属**编译错误**。
4. 若需按 `..` 的**内容**（元素类型）分派，改用**单一变长 overload + 函数体内 `match`/`try` 分派**，不要拆成多个仅 `..` 不同的 overload。
5. 变长 overload 体内对 `args`/`kwargs`（`Any`/`dyn`）做 `as` 强转时，按 [09-错误处理](09-错误处理.md) 仍需标注 `raises`。

```lz
// 固定签名优先，变长 .. 兜底
@overload
def show(x: int) = print(f"int:{x}")

@overload
def show(x: str) = print(f"str:{x}")

@overload
def show(..) =            // 兜底：任意数量/类型的位置参数
    for v in args:
        print(v)

show(1)                   // → int:1   （命中 show(int)）
show("a")                 // → str:a   （命中 show(str)）
show(1, 2, 3)             // → 1 2 3   （兜底 show(..)）
```

```lz
// 显式参数不同 + 变长 ..：先比显式参数再兜底
@overload
def g(a: int, ..) = print("int 领头", args)

@overload
def g(a: str, b: str, ..) = print("两 str", args)

g(1, 2)                   // → int 领头 [1, 2]
g("x", "y", 1)            // → 两 str ["x","y",1]
```

```lz
// 需要按 args 元素类型分派 → 单一变长 overload + match
@overload
def f(..) =
    match args:
        case [int, ..] => print("整数系列")
        case [str, ..] => print("字符串系列")
        else => panic("不支持的参数组合")
```

> 注：`@overload` 的完整规范（声明顺序、分派算法、与 duck/trait 的交互）应另立专章；本节仅规定其与 `..` 可变参数的共用约束。

### 2.8 类型保真：如何在内部免转换拿到明确类型

**痛点**：裸 `..` 注入 `Vec<Box<dyn Any>>`，元素类型被擦除，函数体内必须 `as`/`downcast` 才能用，且按 [09-错误处理](09-错误处理.md) 需标 `raises`。下面是**三种拿到明确类型、避免手写转换**的机制，按推荐度排序。

#### 方案 A — 同质注解（编译期已知，零转换）★ 最常用

`..: Tuple<T>` / `..: Dict<K,V>` 直接把元素类型钉死，注入的就是具体类型容器，内部按 T/V 直接用，**无擦除、无 `as`、无需 `raises`**：

```lz
def sum_all(..: Tuple<int>) =        // args: List<int>
    total = 0
    for v in args:                   // v: int，编译期已知，无转换（for 冒号后换行缩进）
        total += v
    total

def cfg(..: Dict<str, int>) =         // kwargs: Dict<str, int>
    for (k, v) in kwargs:             // v: int
        print(k, v)
```
- 限制：所有收集到的元素必须是**同一类型 T**（同质）。类型不同的实参在该签名下编译报错。

#### 方案 B — 异构泛型变长捕获（type-pack variadic，零开销、最安全）

当实参类型**各不相同**又想在内部免转换，用泛型变长类型包 `Ts...` 把每个元素的真实类型保留下来：

```lz
def show<Ts...>(..: Tuple<Ts...>) =    // Ts... 由调用点推断
    // args 是异质元组 (Ts0, Ts1, Ts2, ...)，每个槽位类型精确
    print(args.0, args.1, args.2)      // args.0: Ts0, args.1: Ts1 —— 类型明确，免 as
show(1, "a", True)                     // 推断 Ts... = <int, str, bool>，无擦除

def head<Ts...>(..: Tuple<Ts...>) =
    match args:
        case (a,)      => a            // a: Ts0
        case (a, b)    => a            // 按元组长度分派，a/b 类型精确
        else           => panic("至少需要一个参数")
```
- `args` 的静态类型 = 调用点推导出的异质元组；每个位置类型明确，**运行时无类型擦除、无 `as`、无 `dyn`**。
- 需要编译器支持**变长泛型（type pack）+ 元组展开**（编译期能力，零运行时开销）。
- 适用：类型在调用点已知、希望静态安全且免转换的异构场景。

#### 方案 C — 动态反射（保留 `dyn Any`，但免手写 `as`）

仍注入 `Box<dyn Any>`，但提供两种免手写转换的访问方式：

1. **`match` 按类型分支**：编译器在分支内自动 `downcast` 并把值绑定为具体类型变量，你**不用写 `as`**：
```lz
def describe(..) =
    for v in args:                      // v: dyn Any
        match v:
            case int  => print(f"int {v}")    // v 自动 downcast 为 int
            case str  => print(f"str {v}")    // v 自动 downcast 为 str
            case bool => print(f"bool {v}")
            else      => panic("未知类型")
```
2. **运行时自省**：每个元素携带 `TypeId` / `type_name()`，可 `v.type_name()` 拿到明确类型名（用于日志/报错，不用于取值）：
```lz
def log_args(..) =
    for v in args:
        print(v.type_name(), v)         // 例如打印 "int" "str" …… 明确类型名
```

> **选择建议**：
> - 同质集合 → **方案 A**（最简单，零成本）。
> - 异构但每个位置类型在调用点确定、要静态安全 → **方案 B**（零开销、免 `as`，推荐）。
> - 类型完全动态 / 来自外部输入 → **方案 C**（`match` 免手写 `as`，但仍有运行时分支）。
> - B 与 C 不冲突：可 `..: Tuple<Ts...>` 捕获类型，再用 `match` 对具体类型分支处理。
>
> **验收用例**：`DEMO/variadic_type_fidelity.lz`（含 A/B/C 三组）。

## 三、安全分隔符：`/` 与 `*`（仅分割，不注入，类型安全）

当**不需要收集多余实参**、只想**约束哪些参数只能位置传 / 只能关键字传**，且不希望引入 `Any`/`dyn` 的 unsafe 边界时，使用 Python 式分隔符（PEP 570 `/`、PEP 3102 `*`）。它们**纯语法、不注入任何变量、不收集实参、完全类型安全**。

### 3.1 语法

```
def f(pos1, pos2, /, pos_or_kw, *, kw1, kw2):
       └─ 仅位置 ─┘     └─ 均可 ─┘    └─ 仅关键字 ─┘
```

- **`/`**：其左侧所有参数**只能位置传递**（positional-only）。`/` 本身不占参数位。
- **`*`**：其右侧所有参数**只能关键字传递**（keyword-only）。`*` 本身不占参数位。
- `/` 与 `*` 之间：位置或关键字均可。
- 可只写 `/`（无 `*`）、只写 `*`、或两者都写（`/ ... *`）。顺序必须 `/` 在 `*` 之前。

### 3.2 示例

```lz
// 仅位置：x、y 只能用位置传，z 可位置可关键字
def pow(x: int, y: int, /, z: int = 1) =
    x ** y + z
pow(2, 3)            // ✅ → 9
pow(2, 3, 4)         // ✅ z=4 → 12
// pow(x=2, y=3)     // ❌ x、y 是仅位置

// 仅关键字：a 可位置可关键字，b、c 必须关键字
def config(a: int, *, b: int, c: int) =
    a + b + c
config(1, b=2, c=3)  // ✅
// config(1, 2, 3)   // ❌ b、c 必须关键字

// 完整三段：仅位置 / 均可 / 仅关键字
def full(a, b, /, c, d=0, *, e, f) =
    (a, b, c, d, e, f)
full(1, 2, 3, e=5, f=6)        // ✅ a=1,b=2(位置) c=3(位置/关键字) e,f 关键字
// full(1, 2, c=3, 4, e=5, f=6) // ❌ / 与 * 之间的参数也不能在 * 后又混位置
```

### 3.3 与 `..` 注入的互斥规则（重要）

`/` `*` 是“纯分割、零注入”，`..` 是“纯注入、unsafe”。**同一签名不允许两者混用**，否则边界归属产生歧义：

| 非法示例 | 原因 |
|---------|------|
| `f(a, /, ..)` | `/` 已声明位置边界，`..` 又要注入位置 `args`，冲突 |
| `f(*, ..)` | `*` 已声明关键字边界，`..` 又要注入，冲突 |
| `f(.., a, /)` | `..` 注入与 `/` 边界冲突 |

**组合原则**：
- 要“安全分割”→ 用 `/` `*`，**不要**写 `..`。
- 要“动态收集多余实参”→ 用 `..`，**不要**写 `/` `*`。
- 若既想约束边界又想收集多余实参，拆成两层：外层函数用 `/` `*` 做安全边界，内部把实参显式转发给带 `..` 的函数（或反之）。

```lz
// 安全边界 + 显式转发到变参注入（两者不混在同一签名）
def safe_api(x: int, *, opts: Dict<str, int>) =
    inner(opts)          // 显式转发，不混用 / 与 ..

def inner(..: Dict<str, int>) =   // 内部才用 .. 注入
    for (k, v) in kwargs:
        print(k, v)
```

### 3.4 与 `@overload` 的关系

`/`、`*` 的边界约束参与 `@overload` 静态分派：仅位置（`/`）与仅关键字（`*`）签名视为**不同签名**，可分派；这与 §2.7 的“显式参数相同但 `..` 注解不同则冲突”不矛盾，因为 `/` `*` 不改参数类型、只改传递约束，编译器可静态区分。

## 四、示例

```lz
// === 安全收集 — 推荐 ===
def log(level: str, messages: List<str>) =
    for msg in messages:
        print(f"[{level}] {msg}")

log("INFO", "started", "ready")          // 自动收集
log("INFO", ["started", "ready"])        // 显式 List

// === .. 变参注入 ===

// lst: 位置或关键字 — 单个 .. 仅注入 args（bare → 元素 Any；本例位置实参已被 lst 收集，args 为空）；命名实参不被收集
def proc<T>(lst: List<T>, ..) =
    for x in lst:
        print(x)

proc([1, 2, 3])                          // lst 位置传入
proc(lst=[1, 2, 3])                      // lst 关键字传入

// lst: 仅关键字（.. 在 lst 之前）
def kw_proc<T>(.., lst: List<T>) =
    for x in lst:
        print(x)

kw_proc(lst=[1, 2, 3])                   // ✅ 必须关键字
// kw_proc([1, 2, 3])                    // ❌ 错误：lst 是仅关键字参数

// === 安全分隔符 / 与 *（仅分割，不注入，类型安全）===
def divide(a: int, b: int, /, round: bool = False) =
    let q = a / b
    round ? q.round() : q
divide(10, 3)            // ✅ a,b 仅位置
// divide(a=10, b=3)     // ❌ a,b 仅位置，不可关键字

def settings(*, theme: str, debug: bool = False) =
    print(theme, debug)
settings(theme="dark", debug=True)   // ✅ 全部必须关键字
```

## 五、语法边界

```lz
// ❌ `..` 最多出现 2 次
def f(.., .., ..) = ...

// ❌ 连续逗号
def f(..,,..) = ...

// ❌ List 参数在 .. 之后不能自动收集位置参数
def f(.., lst: List<int>) = ...
// f(1, 2, 3)  // 错误：lst 仅关键字，不接受位置参数
```

## 六、两种模式对比

| | 安全 `lst: List<T>` | `..` 变参注入 |
|------|:---:|:---:|
| 类型安全 | ✅ 编译期 | 默认 ❌（无注解/异质擦除）；带具体注解 ✅ |
| 空参调用 | ✅ `lst = []` | 视签名而定 |
| 关键字传递 | ✅ 支持 | 由 `/` `*` 控制（`..` 本身不划边界） |
| 内置变量 | 无 | `args` / `kwargs` |
| 推荐场景 | 同类型变长 | 异构参数、DSL |
