# LZ 魔法方法 — 综合

> 版本: 3.1 · 基于编译器源码 · 2026-07-27

本文档是 magic 魔法方法的高级综合参考，涵盖 self 模式、多分派、关联类型、Self 约束、默认实现、完整工作流及 Rust 映射。

---

## 一、self 模式详解

self 参数决定了魔法方法的调用方式和所有权语义，共四种模式。

| 模式 | 声明写法 | 语义 | 调用端 |
|------|----------|------|--------|
| `owned` | `def __xxx__(self, ...)` | 消费 self，转移所有权 | 调用后原值不可再使用 |
| `ref` | `def __xxx__(self, ...)` + `self = "ref"` | 不可变借用 `&self` | 调用后原值仍可用 |
| `refmut` | `def __xxx__(mut self, ...)` | 可变借用 `&mut self` | 独占可变引用 |
| `none` | `def __xxx__(...)` 无 self | 关联函数，无 receiver | 直接 `Type::xxx()` 调用 |

### owned — 消费型

```lz
magic add<T> =
    def __add__(self, other: T) -> T
        where Self <: Add<T>
        = ...

struct Point =
    x: int
    y: int
    def __add__(self, other: Point) -> Point =
        Point(x: self.x + other.x, y: self.y + other.y)

let p1 = Point(x: 1, y: 2)
let p2 = Point(x: 3, y: 4)
let p3 = add(p1, p2)   // p1 所有权被转移，此后不能再用 p1
```

**使用场景**：运算符重载（`+`、`-`、`*`）、迭代器消费（`into_iter`）、类型转换。

### ref — 只读借用

```lz
magic display<T> =
    def __str__(self) -> str
        = ...
      // 编译器自动推断 self = "ref"

struct User =
    name: str
    age: int
    def __str__(self) -> str =
        f"{self.name} ({self.age})"

let u = User(name: "Alice", age: 30)
print(str(u))         // 只读，u 仍然可用
print(str(u))         // 可多次调用
```

**使用场景**：比较操作（`==`、`<`）、格式化输出、只读查询。

### refmut — 可变借用

```lz
magic iter<T> =
    def __next__(mut self) -> Option<T>
        = ...
      // mut self → self = "refmut"

struct Counter =
    current: int
    max: int
    def __next__(mut self) -> Option<int> =
        if self.current < self.max:
            let val = self.current
            self.current += 1       // 修改内部状态
            Some(val)
        else:
            None

let c = Counter(current: 0, max: 3)
let a = next(c)   // Some(0)
let b = next(c)   // Some(1) — c 的状态被记住
```

**使用场景**：迭代器、流式处理、状态机、构建器模式。

### none — 无 self

```lz
magic default<T> =
    def __default__() -> T
        = ...
      // 无 self 参数 → self = "none"

struct Config =
    host: str
    port: int
    def __default__() -> Config =
        Config(host: "localhost", port: 8080)

let cfg = default()   // Config(host: "localhost", port: 8080)
```

**使用场景**：工厂方法、默认构造、类型级关联函数。

## 二、多分派（Multi-Dispatch）

当 `multi_dispatch = true` 时，编译器按参数类型为每个可能的实现生成独立的 trait impl。

### 工作机制

```lz
magic convert<From, To> =
    def __convert__(self) -> To
        = ...

// 标记为多分派：编译器根据返回类型 To 生成多个 impl
magic __convert__:
    dispatch = "by_ret"
```

**dispatch 策略**：

| 策略值 | 分派依据 | 示例 |
|--------|----------|------|
| `"none"` | 不分派，单 trait impl | 普通方法 |
| `"by_ret"` | 按返回值类型分派 | `convert::<To>` → 根据 `To` 选择 impl |
| `"by_params"` | 按所有参数类型联合分派 | 复杂多态场景 |
| `"by_arg(N)"` | 按第 N 个参数类型分派 | `by_arg(0)` = 按 self 类型分派 |

### 示例

```lz
magic convert<From, To> =
    def __convert__(self) -> To
        = ...
// 声明式辅助
magic __convert__:
    dispatch = "by_ret"

struct Int = value: int
    def __convert__(self) -> f64 = self.value as f64
    def __convert__(self) -> str = str(self.value)

let n = Int(value: 42)
let f: f64 = convert(n)   // 编译器选择 __convert__() -> f64
let s: str   = convert(n)   // 编译器选择 __convert__() -> str
```

## 三、关联类型 vs 泛型返回

`ret` 字段控制返回类型的抽象方式。

### ret = "assoc"（关联类型，默认）

```lz
magic map<T, R> =
    def __map__(self, f: fn(T) -> R) -> Iterable<R>   // ret = "assoc"
        where Self <: Iterable<T>
        = ...

// 编译器生成：
// trait Map<T> {
//     type Output;             // ← 关联类型
//     fn __map__(self, f: fn(T) -> Self::Output) -> Iterable<Self::Output>;
// }
```

**特点**：每个 `Self` 类型对于给定的 `T` 只能有一种 `Output` 类型。适用于返回类型由 Self 决定的场景。

### ret = "generic"（泛型返回）

```lz
magic __map__:
    ret = "generic"

// 编译器生成：
// trait Map<T, R> {           // ← R 为泛型参数
//     fn __map__(self, f: fn(T) -> R) -> Iterable<R>;
// }
```

**特点**：同一 `Self` 类型可以对多种 `R` 提供实现（配合多分派）。适用于返回类型可变的场景。

### 选择建议

| 场景 | 推荐 |
|------|------|
| 返回类型由 Self 唯一确定 | `assoc`（默认） |
| 相同 Self 需要支持多种返回类型 | `generic` + `dispatch = "by_ret"` |
| 实现多个转换目标 | `generic` + 多分派 |

## 四、Self 约束

`where Self <: Trait` 限制哪些类型可以实现此魔法。

### 语法

```lz
magic map<T, R> =
    def __map__(self, f: fn(T) -> R) -> Iterable<R>
        where Self <: Iterable<T>           // 单约束
        = ...

magic sort<T> =
    def __sort__(self) -> Iterable<T>
        where Self <: Iterable<T>           // 多重约束可逐行列出
        where T <: Comparable
        = ...
```

### 作用

```lz
// ❌ 编译错误：int 不是 Iterable
struct Int = value: int
    // int 不满足 where Self <: Iterable<T> 约束，无法 impl __map__

// ✓ 正确：MyList 是 Iterable
struct MyList<T> =
    items: List<T>
    // MyList 满足 Iterable<T>，可以 impl __map__
```

**常用约束组合**：

| 魔法 | 典型约束 |
|------|----------|
| `__map__` | `where Self <: Iterable<T>` |
| `__filter__` | `where Self <: Iterable<T>` |
| `__sort__` | `where Self <: Iterable<T>, where T <: Comparable` |
| `__add__` | `where Self <: Add<T>` |
| `__eq__` | 无约束（任何类型可比较相等） |

## 五、默认实现

magic 块可通过 `= expr` 提供默认实现，否则使用 `= ...` 标记为抽象。

### 抽象（= ...）

```lz
magic map<T, R> =
    def __map__(self, f: fn(T) -> R) -> Iterable<R>
        where Self <: Iterable<T>
        = ...                    // 抽象：struct 必须提供实现
```

任何声明实现此魔法的 struct **必须**自行提供 `__map__` 方法，否则编译错误。

### 默认实现（= expr）

```lz
magic collect =
    def __collect__<T, R>(
        self,
        f_map: fn(T) -> R,
        f_filter: fn(T) -> bool = |_| True
    ) -> Iterable<R>
        where Self <: Iterable<T>
        = map(filter(self, f_filter), f_map)   // 默认实现
```

**语义**：
- 若 struct 未显式定义 `__collect__`，自动使用默认实现
- 若 struct 提供了自己的 `__collect__`，覆盖默认行为

**适用场景**：为常见模式提供开箱即用的实现，同时允许特化。

## 六、完整工作流

```
┌─────────────────────────────────────────────────────┐
│  ① magic 块定义                                      │
│                                                     │
│  magic map<T, R> =                                  │
│      def __map__(self, f: fn(T) -> R) -> Iterable<R>│
│          where Self <: Iterable<T>                  │
│          = ...                                      │
│                                                     │
│  产物：Trait Map + 全局函数 map 声明                    │
└──────────────────────┬──────────────────────────────┘
                       │
                       ▼
┌─────────────────────────────────────────────────────┐
│  ② struct 实现魔法方法                                │
│                                                     │
│  struct MyList<T> =                                 │
│      items: List<T>                                 │
│      def __map__(self, f: fn(T) -> R) -> Iterable<R>│
│          = ...                                      │
│                                                     │
│  编译器匹配签名 → 自动生成 impl                        │
└──────────────────────┬──────────────────────────────┘
                       │
                       ▼
┌─────────────────────────────────────────────────────┐
│  ③ 自动生成 trait impl                               │
│                                                     │
│  impl Map<T, R> for MyList<T> {                     │
│      fn __map__(self, f) -> Iterable<R> { ... }     │
│  }                                                  │
└──────────────────────┬──────────────────────────────┘
                       │
                       ▼
┌─────────────────────────────────────────────────────┐
│  ④ 全局函数可用                                       │
│                                                     │
│  fn map<T, R, S>(self: S, f: fn(T) -> R)            │
│      -> Iterable<R>                                 │
│      where S: Map<T, R>                             │
│                                                     │
│  用户代码：let result = map(my_list, |x| x * 2)       │
└─────────────────────────────────────────────────────┘
```

**关键点**：
1. magic 块定义"魔法契约"——声明了 trait 接口 + 全局函数包装
2. struct 只需定义 `__方法名__` 方法，编译器自动匹配并生成 impl
3. 所有实现此魔法的类型统一使用全局函数调用
4. 全局函数签名由 magic 块中的方法签名推导

## 七、与 Rust trait 的映射总结

| LZ 概念 | Rust 等价 | 说明 |
|---------|-----------|------|
| `magic name<T>` | 标准库 trait + blanket impl | magic 同时生成 trait 和全局函数 |
| `def __xxx__(self, ...)` | `fn xxx(self, ...)` | 魔法方法签名 |
| `__add__` | `std::ops::Add` | 运算符重载 |
| `__eq__` | `std::cmp::PartialEq` | 相等比较 |
| `__lt__` | `std::cmp::PartialOrd` | 顺序比较 |
| `__iter__` | `std::iter::IntoIterator` | 转换为迭代器 |
| `__next__` | `std::iter::Iterator` | 迭代器 next |
| `__str__` | `std::fmt::Display` | 显示格式化 |
| `__drop__` | `std::ops::Drop` | 析构函数 |
| `__clone__` | `std::clone::Clone` | 克隆 |
| `__call__` | `std::ops::Fn` 族 | 可调用对象 |
| `__getitem__` | `std::ops::Index` | 索引访问 |
| `where Self <: T` | trait bound on Self | Self 约束 |
| `= ...` | 无默认实现 | 抽象方法 |
| `= expr` | 默认实现 | 默认方法体 |
| `ret = "assoc"` | associated type `type Output` | 关联类型输出 |
| `ret = "generic"` | generic type parameter `<R>` | 泛型输出 |
| `dispatch = "by_ret"` | 手动 impl 选择（LZ 特有） | 按返回类型分派 |

**设计差异**：
- Rust 的 trait 是显式声明 + 显式 impl 的；LZ 通过 magic 实现"声明即生成"，减少样板代码
- LZ 的 `dispatch` 多分派是 Rust 没有的一级语言特性
- LZ 将运算符重载统一为 `__xxx__` 魔法方法，映射到 Rust 对应 trait

## 八、隐式策略（Implicit Strategy）

隐式策略是一组特殊魔法方法，编译器在特定场景下**自动搜索并植入调用**，无需用户显式书写。

### 8.1 `__implicit_copy__` — Mojo 风格隐式复制

当变量被 `move`（所有权转移）后，编译器自动调用 `__implicit_copy__` 生成副本，使原变量继续可用：

```lz
// struct 实现隐式复制
struct Point =
    x: f64
    y: f64

    def __implicit_copy__(ref self) -> Self =
        Point(x: self.x, y: self.y)

// 使用：p1 被 move 后自动复制
let p1 = Point(x: 1.0, y: 2.0)
let p2 = p1^                    // move p1
print(p1.x)                     // ✅ 编译器自动插入 p1.__implicit_copy__()
```

- 触发条件：move（`^` 后缀）操作后，原变量被引用
- 签名：`def __implicit_copy__(ref self) -> Self`
- Trait：`ImplicitCopy`

### 8.2 `__implicit_to__` — Scala 风格隐式转换

当类型不匹配时，编译器自动搜索 `__implicit_to__` 进行隐式转换：

```lz
struct Int = value: int
    def __implicit_to__(self) -> f64 =
        self.value as f64
    def __implicit_to__(self) -> str =
        self.value as str

// 使用：编译器自动选择正确的返回类型
let n = Int(value: 42)
let f: f64 = n                  // 自动调用 __implicit_to__() -> f64
let s: str = n                  // 自动调用 __implicit_to__() -> str
```

- 触发条件：赋值/传参时类型不匹配，且存在可用的 `__implicit_to__`
- 签名：`def __implicit_to__[T](self) -> T`
- Trait：`ImplicitInto`
- 多分派：**是**（按返回类型 `T` 匹配）

### 8.3 `__implicit_default__` — 隐式默认值填充

当函数参数的默认值未显式提供时，编译器自动调用 `__implicit_default__` 构造默认值：

```lz
struct Config =
    host: str
    port: int

    def __implicit_default__() -> Self =
        Config(host: "localhost", port: 8080)

// 使用：编译器自动填入默认 Config
def server(cfg: Config = ...) =
    print(cfg.host)

server()                        // ✅ cfg 自动获得 __implicit_default__()
server(Config(host: "0.0.0.0", port: 3000))  // 显式传参跳过隐式
```

- 触发条件：函数调用时省略有 `= ...` 标记的参数
- 签名：`def __implicit_default__() -> Self`
- Trait：`ImplicitDefault`

### 8.4 隐式策略优先级

当多种隐式策略冲突时，编译器按以下顺序查找：

1. 显式类型注解（最高优先级）
2. `__implicit_to__` 隐式转换
3. `__implicit_default__` 默认值
4. `__implicit_copy__` move 后复制

### 8.5 设计动机

隐式策略借鉴了三类主流语言的隐式机制：

| 魔法方法 | 参考语言 | 原始机制 |
|----------|---------|---------|
| `__implicit_copy__` | Mojo | `__copyinit__` — move 后自动复制 |
| `__implicit_to__` | Scala 3 | `given Conversion[A, B]` — 类型不匹配时自动搜索 |
| `__implicit_default__` | Kotlin/Swift | 默认参数 + `by lazy` — 省略参数时自动构造 |

### 8.6 语法边界

```lz
// ❌ 隐式转换循环
struct A =
    def __implicit_to__(self) -> B = B(value: self.value)
struct B =
    def __implicit_to__(self) -> A = A(value: self.value)
// 错误：A ↔ B 双向隐式转换导致编译器无限搜索

// ❌ 隐式 copy 用于非 Copy 资源
struct File = handle: int
    def __implicit_copy__(ref self) -> Self =
        File(handle: dup(self.handle))
// 警告：隐式复制可能重复释放资源

// ✅ 合理使用
struct Vector2 =
    x: f64
    y: f64
    // 值类型适合隐式复制
    def __implicit_copy__(ref self) -> Self =
        Vector2(x: self.x, y: self.y)
```

## 九、常见错误与语法边界

```lz
// ❌ 魔法方法签名不匹配
magic map<T,R> =
    def __map__(self, f: fn(T) -> R) -> Iterable<R>
        where Self <: Iterable<T>
        = ...
// struct 实现 __map__ 时签名必须完全匹配

// ❌ Self 约束未满足
struct Point = x: int, y: int
    def __map__(self, f: fn(int) -> T) -> Iterable<T> = ...
// 错误：Point 未实现 Iterable<int>，不满足 where Self <: Iterable<T>

// ❌ dispatch 字段冲突
magic __convert__:
    dispatch = "by_ret"
// struct 的多个 __convert__ 方法返回类型必须互斥
```
