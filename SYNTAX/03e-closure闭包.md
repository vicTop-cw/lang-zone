# LZ 闭包（Closure）

> 规范版本: 3.3 · 基于编译器源码 · 最后校订: 2026-08-05

本文档定义 Lang-Zone 的匿名函数（闭包）语法：参数形式、胖箭头 `=>` 的换行规则、参数注解规则、作为参数传递、与逻辑或的区分，以及错误边界。函数嵌套定义与装饰器见 [03e-复合综合](03e-复合综合.md)。

---

## 一、基本形式

LZ 闭包使用 `|params| body` 语法。**无参闭包用 `| |`**（中间**必须空格**）与逻辑或 `||`（紧贴）区分。

```lz
|x| x + 1                    // 单参数（单行，省略 =>）
|x, y| x + y                 // 多参数
|a, b| a > b                 // 返回 bool
| | 42                       // 无参闭包（中间空格）
| | print("no args")         // 无参闭包
```

---

## 二、胖箭头 `=>` 与换行规则（核心）

`=>` **可选**，但有严格的换行约束：

- **单行**：`|params| body` 可省略 `=>`，直接跟表达式。
- **多行（换行缩进）块体**：**必须显式写 `=>`**，`=>` 之后换行缩进书写块体，与 `def` 函数一致。

```lz
// ✅ 单行（无 =>）
|x| x + 1
|x, y| x + y

// ✅ 单行（带 =>，等价）
|x| => x + 1
|x, y| => x + y
| | => 42                    // 无参闭包 + 胖箭头

// ✅ 多行块体（必须带 =>）
|a, b| =>
    c = a + b
    c * c

// ❌ 错误：换行多行体却省略 =>
|x|
    x + 1                    // 错误：多行体必须写 |x| =>
```

> **铁律**：`|params|` 之后若**换行再写体**（无论几行），都必须补 `=>`；否则解析失败。`=>` 前后须留白。

---

## 三、参数注解规则

闭包参数**是否必须注解**取决于使用场景：

| 场景 | 规则 |
|------|------|
| `let f = \|x\| body`（变量绑定） | **参数必须注解**，如 `\|x: int\|` |
| `func(\|x\| body)`（作为函数实参） | 注解可选（由上下文 `fn(...)` 类型推断） |
| `@overload def f(g: fn(...))` 传闭包实参 | **参数必须注解** |

```lz
// 变量绑定：参数必须注解
let double = |x: int| -> int = x * 2
let noop = | | -> int = 42         // 无参
print(double(5))             // 10
print(noop())                // 42

// 作为实参：注解可选（上下文推断）
def apply(f: fn(int) -> int, x: int) -> int =
    f(x)
apply(|x| x + 1, 5)          // 6
apply(|x| => x + 1, 5)       // 6（胖箭头等价写法）
```

> **返回类型注解**：闭包可带 `-> T`（如 `|x: int| -> int = ...`）；单行省略 `=>` 时写作 `|x: int| -> int = x * 2`（`=` 后为表达式体）。

---

## 四、无参闭包 vs 逻辑或

| 写法 | 含义 | 说明 |
|------|------|------|
| `\|\|`（紧贴） | 逻辑或 | `a \|\| b` — 短路或运算符 |
| `\| \|`（中间空格） | 无参闭包 | `\| \| => 42` — 零参数匿名函数 |

```lz
let or_result = True || False     // 逻辑或
let closure = | | => 42           // 无参闭包（空格！）
let closure2 = | | print("hi")    // 无参闭包（单行省略 =>）
```

## 五、闭包语义

- **闭包捕获**：闭包以词法闭包方式捕获外层变量（读/写均可），与 `def` 内嵌函数一致。
- **捕获模式 → Rust 映射**（编译器依据对捕获变量的使用自动选择，无需用户标注）：

  | 使用方式 | 生成 Rust | 说明 |
  |----------|-----------|------|
  | 只读捕获 | 闭包按引用捕获，映射 `Fn`（`&self`） | 多次调用互不干扰，不可修改捕获变量 |
  | 可写捕获（`mut` 外部变量被修改） | 映射 `FnMut`（`&mut self`） | 闭包可修改捕获变量，但不转移所有权 |
  | 捕获后转移所有权（`^` 显式移动、或 `dyn` 环境下） | 映射 `FnOnce` 或 `move` 闭包 | 捕获变量所有权移入闭包，原变量失效 |

  - 推断规则：只读 → `Fn`；写捕获 → `FnMut`；显式 `^` / 存入 `Box<dyn>` → `move` + `FnOnce`（或按目标 trait 收敛）。
  - 闭包作 `fn(...)` 参数时的 trait bound 由编译器按捕获分析自动匹配（若既有写又有转移需求，须用 `dyn` + 显式语义）。
- **非生成器作用域**：闭包**不是**生成器上下文，**不能**包含 `yield`/`yield from`。生成器只能用 `iterator` 关键字或生成器构建块 `func *:`（见 [14-生成器](14-生成器.md)）。
- **不能作为生成器声明**：`def` 内嵌闭包、`iterator` 内嵌闭包均不支持 `yield`。

```lz
// ❌ 错误：yield 在闭包内
def bad() =
    f = |x: int| =>
        yield x            // 错误！闭包不是生成器作用域
    f(1)

// ❌ 错误：闭包捕获运行时变量用于 comptime
comptime:
    let cap = outer_var          // 错误：outer_var 运行时不存在
```

---

## 六、错误语法边界汇总

| 写法 | 问题 |
|------|------|
| `|x|` 换行后直接写体（无 `=>`） | 多行体必须带 `=>` |
| `let f = \|x\| body`（参数无注解） | 变量绑定场景参数必须注解 |
| `\|\| 42` | 被解析为逻辑或，非无参闭包（缺空格） |
| 闭包内 `yield` | 闭包不是生成器作用域 |
