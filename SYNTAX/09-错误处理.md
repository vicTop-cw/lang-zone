# LZ 错误处理

> 规范版本: 3.2 · 基于编译器源码 · 最后校订: 2026-07-31

本文档定义 Lang-Zone 的错误处理语法：`panic`、`raise`/`raises`、`try`/`catch`/`finally`、`?` 传播。

---

## 一、panic 中止（内置函数）

`panic` 是**内置函数**，**不是关键字**。当前编译器在词法层为其保留专用 token（仅用于稳定解析 `panic(...)`），语义上它等价于 prelude 中的内建函数，不应被当作保留关键字。

### 1.1 语法

```lz
panic("message")             // 立即中止程序，打印消息
panic(expr)                  // expr 的类型为 str
```

### 1.2 示例

```lz
def divide(a: int, b: int) -> int =
    if b == 0:
        panic("division by zero")
    a / b
```

## 二、raise / raises 异常

### 2.1 raise 抛出异常

```lz
raise "error message"        // 抛出异常
raise ErrorType("details")   // 抛出带类型的异常
```

### 2.2 raises 声明

如果函数体中有 `raise`，必须在函数签名中声明 `raises` 类型：

```lz
def divide(a: int, b: int) -> int raises str =
    if b == 0:
        raise "division by zero"
    a / b
```

### 2.3 语义检查

```lz
// ❌ 编译错误：函数体有 raise 但未声明 raises
def bad() -> int =
    raise "oops"

// ✅ 正确
def good() -> int raises str =
    raise "oops"
```

## 三、try / catch / finally

### 3.1 基本语法

```lz
try:
    // 可能出错的代码
    risky_operation()
catch pattern:
    // 错误处理
    handle_error()
finally:
    // 始终执行（无论是否出错）
    cleanup()
```

### 3.2 作为表达式

```lz
let v = try:
    safe_divide(10, 2)
catch e:
    -1               // 出错时返回 -1

print(v)              // 5
```

- `try` 体的尾表达式作为 `Ok` 值
- `catch` 分支捕获 `Err`，尾表达式作为该分支的值

### 3.3 多 catch 分支

```lz
try:
    operation()
catch ValueError:
    handle_value()
catch TypeError:
    handle_type()
catch e:              // 通配 catch
    handle_any(e)
```

### 3.4 try/catch/else

`try` 块成功后执行 `else` 块，失败则跳过：

```lz
try:
    let data = read_file("input.txt")
catch IOError:
    print("file not found")
else:
    print(f"read {data.len()} bytes")
```

`else` 在 `try` 成功、`catch` 未触发时执行。`else` 必须出现在所有 `catch` 分支之后、`finally`（如有）之前。

### 3.5 finally 最终块

```lz
try:
    file = open("data.txt")
    process(file)
catch e:
    print(f"error: {e}")
finally:
    file.close()     // 始终关闭文件
```

## 四、异常类型

LZ 的异常类型通过 `enum` 定义。编译器不预设异常层次结构，用户可自由定义：

### 4.1 内置异常类型

| 异常类型 | 说明 | 对应 Rust |
|----------|------|-----------|
| `Exception` | 通用异常基类（用户自定义异常的父类） | — |
| `ValueError` | 值错误（如参数越界） | — |
| `TypeError` | 类型错误 | — |
| `ParseError` | 解析错误 | — |
| `IOError` | I/O 操作错误（预导入） | `std::io::Error` |
| `StopIteration` | 生成器终止信号（由编译器自动处理） | — |
| `str` | 字符串异常（`raise "msg"` 抛出） | — |

### 4.2 自定义异常

```lz
enum AppError:
    NotFound(str)
    InvalidInput(str)
    PermissionDenied(str)

def find_user(id: int) -> str raises AppError =
    guard id > 0
        else:
            raise AppError.InvalidInput("id must be positive")
    "user"

try:
    let u = find_user(-1)
catch AppError.InvalidInput(msg):
    print(f"invalid input: {msg}")
catch AppError.NotFound(msg):
    print(f"not found: {msg}")
```

### 4.3 错误传播 `?`

`?` 后缀操作符将 `Result<T,E>` 错误向上传播：

```lz
def parse_and_process(s: str) -> int raises ParseError =
    let val = parse_int(s)?
    val * 2
```

> `?` 仅对 `Result` 类型有效。对于自定义 `raises` 异常，使用 `try/catch`。

## 五、? 错误传播

### 5.1 语法

```lz
value = fallible()?         // 如果是 Err，向上传播；Ok 则解包
```

### 5.2 示例

```lz
def read_config() -> Result<Dict<str, str>, str> raises str =
    let content = read_file("config.json")?
    let parsed = parse_json(content)?
    Ok(parsed)
```

等价于：

```lz
def read_config() -> Result<Dict<str, str>, str> raises str =
    let content = match read_file("config.json"):
        case Ok(v):
            v
        case Err(e):
            raise e
    ...
```

## 六、错误语法边界

```lz
// ❌ raise 未声明 raises
def bad() -> int =
    raise "oops"             // 错误：缺少 raises 声明

// ❌ panic 缺少消息
panic()                      // 错误：panic 需要参数

// ❌ try 无 catch 或 finally
try:
    do_something()           // 错误：try 必须有 catch 或 finally

// ❌ ? 用于非 Result/Option 类型
let x: int = 42
let y = x?                   // 错误：int 不是 Result

// ❌ catch 分支缺少模式
try:
    action()
catch:                       // 错误：catch 需要模式
    handler()

// ❌ raise 类型与 raises 不匹配
def f() -> int raises str =
    raise 42                 // 错误：raises str 但 raise 了 int
```
