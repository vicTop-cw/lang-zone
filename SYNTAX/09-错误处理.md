# LZ 错误处理

> 规范版本: 3.3 · 基于编译器源码 · 最后校订: 2026-08-05

本文档定义 Lang-Zone 的错误处理语法：`panic`、`raise`/`raises`、`try`/`catch`/`finally`、`?` 传播。

---

## 一、panic 中止（内置函数）

`panic` 是**内置函数**，**不是关键字**。词法层为 `panic(...)` 保留专用 token（仅用于稳定解析），语义上它等价于 prelude 中的内建函数，不应被当作保留关键字。

### 1.1 语法

```lz
panic("message")             // 立即中止程序，打印消息
panic(expr)                  // expr 的类型为 str
```

### 1.2 示例

```lz
def divide(a: int, b: int) -> int =
    if b == 0:
        panic("division by zero")
    a / b
```

## 二、raise / raises 异常

### 2.1 raise 抛出异常

```lz
raise "error message"        // 抛出异常
raise ErrorType("details")   // 抛出带类型的异常
```

### 2.2 raises 声明

如果函数体中有 `raise` 或使用了 `as` 强转，必须在函数签名中声明 `raises`（未声明而抛错 → 编译错误，见 §2.5）。`raises` 的类型检查规则：**裸 `raises`（不写类型）不检查抛出的具体类型**；**声明了具体类型列表时，`raise` 的表达式类型必须与列表之一兼容**（不匹配 → 编译错误，见错误边界）。三种形式：

```lz
// 形式一: 裸 raises — 仅告知该函数可能引发错误, 不声明具体类型
def might_fail(x: int) -> int raises =
    if x < 0:
        raise "negative"
    x as f64 as int   // 数值转换 infallible，不产生 CastError（见 §2.4）；裸 raises 因上方 raise 而声明

// 形式二: 逗号分隔 — 声明 1~N 个可能的错误类型
def divide(a: int, b: int) -> int raises str, LzError =
    if b == 0:
        raise "division by zero"
    a / b

// 形式三: 列表 — 声明多个错误类型 (与逗号分隔等价, 语义更紧凑)
def parse(text: str) -> int raises [ParseError, ValueError, CastError] =
    if text == "":
        raise ParseError("empty input")
    text.len() as int
```

### 2.3 `raises` 与 `Never` 的交互

`Never` 是永不返回的底层类型。标记为 `-> Never raises E` 的函数表示：若执行到 `return` 则为逻辑错误（编译器告警），但 `raise E` 是函数的唯一正常出口。

```lz
def unreachable() -> Never raises str =
    raise "should never reach here"

def guard_non_null(x: Option<int>) -> int raises str =
    match x:
        case Some(v):
            return v
        case None:
            raise "null pointer"     // 编译器理解此函数要么 return int 要么 raise str
```

### 2.4 `as` 强转与 `try-catch` 的 `raises` 规则

`as` 强转分为两类，`raises` 要求不同：

| `as` 类型 | 是否可能失败 | 示例 | `raises` 要求 |
|-----------|:---:|------|------|
| **数值类型间转换**（infallible） | ❌ 永不失败 | `int`↔`f64`、`f64`→`int`、`i32`→`int` 等数值互转 | **不需要** `raises` |
| **解析式转换**（fallible） | ✅ 可能抛 `CastError` | `"42" as int`、`str`→数值、`dyn`→具体类型 downcast | 按下表 |

fallible `as` 是否需要声明 `raises`，取决于是否被 `try-catch` 完全处理：

| 场景 | `raises` | 说明 |
|------|:---:|------|
| 函数体有 fallible `as` 且未被 `catch` | **需要** | `CastError` 可能向调用方传播 |
| fallible `as` 被 `try-catch` 完全捕获（不 re-raise） | **不需要** | 异常已内部消化 |
| fallible `as` 被 `catch` 后 **re-raise** 为新异常 | **需要** | 新异常类型应向调用方声明 |

```lz
// ✅ 数值转换 infallible — 不需要 raises
def to_float(x: int) -> f64 = x as f64          // 永不失败

// ✅ 不需要 raises — fallible as 被内部处理
def safe_parse(x: str) -> int =
    try:
        let n = x as int
        return n
    catch CastError:
        return 0

// ❌ 需要 raises — fallible as 可能向外传播
def risky_parse(x: str) -> int raises CastError =
    x as int
```

> 注意：`03c-检查站` 中的 checker 函数是例外 — 即使 `as` 被捕获，仍建议声明 `raises`，因为 checker 是编译期注入的约束，静默吞异常会破坏调用方的数据完整性保证。

### 2.5 语义检查

```lz
// ❌ 编译错误：函数体有 raise 但未声明 raises
def bad() -> int =
    raise "oops"

// ✅ 正确
def good() -> int raises str =
    raise "oops"
```

## 三、try / catch / finally

### 3.1 基本语法

```lz
try:
    // 可能出错的代码
    risky_operation()
catch pattern:
    // 错误处理
    handle_error()
finally:
    // 始终执行（无论是否出错）
    cleanup()
```

### 3.2 作为表达式

```lz
let v = try:
    safe_divide(10, 2)
catch e:
    -1               // 出错时返回 -1

print(v)              // 5
```

- `try` 体的尾表达式作为 `Ok` 值
- `catch` 分支捕获 `Err`，尾表达式作为该分支的值

### 3.3 多 catch 分支

```lz
try:
    operation()
catch ValueError:
    handle_value()
catch TypeError:
    handle_type()
catch e:              // 通配 catch
    handle_any(e)
```

### 3.4 try/catch/else

`try` 块成功后执行 `else` 块，失败则跳过：

```lz
try:
    let data = read_file("input.txt")
catch IOError:
    print("file not found")
else:
    print(f"read {data.len()} bytes")
```

`else` 在 `try` 成功、`catch` 未触发时执行。`else` 必须出现在所有 `catch` 分支之后、`finally`（如有）之前。

### 3.5 finally 最终块

```lz
try:
    file = open("data.txt")
    process(file)
catch e:
    print(f"error: {e}")
finally:
    file.close()     // 始终关闭文件
```

## 四、异常类型

LZ 的异常类型通过 `enum` 定义。编译器不预设异常层次结构，用户可自由定义：

### 4.1 内置异常类型

| 异常类型 | 说明 | 对应 Rust |
|----------|------|-----------|
| `Exception` | 通用异常基类（用户自定义异常的父类） | — |
| `ValueError` | 值错误（如参数越界） | — |
| `TypeError` | 类型错误 | — |
| `ParseError` | 解析错误 | — |
| `CastError` | 类型转换失败（`as` 强转失败时由 `__cast__` 抛出） | — |
| `IOError` | I/O 操作错误（预导入） | `std::io::Error` |
| `StopIteration` | 生成器终止信号（由编译器自动处理） | — |
| `str` | 字符串异常（`raise "msg"` 抛出） | — |

### 4.2 自定义异常

```lz
enum AppError:
    NotFound(str)
    InvalidInput(str)
    PermissionDenied(str)

def find_user(id: int) -> str raises AppError =
    guard id > 0
        else:
            raise AppError.InvalidInput("id must be positive")
    "user"

try:
    let u = find_user(-1)
catch AppError.InvalidInput(msg):
    print(f"invalid input: {msg}")
catch AppError.NotFound(msg):
    print(f"not found: {msg}")
```

### 4.3 错误传播 `?`

`?` 后缀操作符将**可传播值**的错误向上传播。可传播协议（统一机制）：

**`expr?` 的求值规则**：

1. 求值 `expr` 得到值 `v`。
2. 检查 `v` 的类型是否**可传播**：实现 `__is_ok__(self) -> bool`（`True` = 成功值，`False` = 错误值），或内置类型 `Result`/`Option`（编译器内建判定：`Ok`/`Some` = 成功，`Err`/`None` = 错误）。
3. 成功值 → 表达式结果为**解包后的值**（`Ok(v)`→`v`，`Some(v)`→`v`；自定义类型经 `__unwrap__` 解包，见下）。
4. 错误值 → **向上传播**（自动执行退出动作）：
   - 所在函数 `raises` 声明且错误类型兼容 → 等价 `raise`（`raise` 该错误值），结束本次调用。
   - 所在函数返回 `Result`/`Option` → 等价 `return Err(...)` / `return None`（包装后返回）。
   - 无 `raises` 声明且非 Result 返回 → **编译错误**（无法传播，见语法边界）。

**可传播协议的三件套魔法方法**（实现即可参与 `?`，见 [06d-内置魔法trait和全局函数.md](06d-内置魔法trait和全局函数.md)）：

| 魔法方法 | 签名 | 作用 |
|----------|------|------|
| `__is_ok__` | `def __is_ok__(self) -> bool` | 判定成功/错误值（`?` 的分支依据） |
| `__unwrap__` | `def __unwrap__(self) -> T` | 成功值解包（成功分支的结果） |
| `__err__` | `def __err__(self) -> E` | 错误值提取（传播时 `raise`/`return Err` 的内容） |

**内置类型**：

- `Result<T, E>`：`Ok(v)?` → `v`；`Err(e)?` → `return Err(e)`（函数返回 Result 时）或 `raise e`（函数 `raises` 声明 E 时）。
- `Option<T>`：`Some(v)?` → `v`；`None?` → `return None`（返回 Option）或 `raise ValueError("None")`（`raises` 时）。

**在 `raises` 函数中传播异常**（用户裁决：`?` 对 Result 与 raises 异常皆可传播）：

```lz
def parse_int(s: str) -> int raises ParseError = ...   // 抛 ParseError 的返回 int

def parse_and_process(s: str) -> int raises ParseError =
    let val = parse_int(s)?    // ParseError 兼容已声明 raises → 自动 raise 向上传播
    val * 2

def read_config(path: str) -> Result<Config, ParseError> =
    let cfg = parse_config(path)?   // 返回 Result：Err 自动包装为 return Err
    cfg
```

> 传播目标判定：**优先 raises**（函数已声明且错误类型兼容 → `raise`）；**其次 Result 返回**（→ `return Err(...)`）；两者皆无 → 编译错误。`?` 不是 `try/catch` 的替代——`catch` 用于捕获后处理，`?` 用于直接上抛。

## 五、`?` 的展开（与 match 等价）

`expr?` 是可传播协议（§4.3）的语法糖，等价于显式 `match`：

### 5.1 语法

```lz
value = fallible()?         // 可传播值：错误向上传播，成功值解包
```

### 5.2 与 match 等价

```lz
def read_config() -> Result<Dict<str, str>, str> raises str =
    let content = read_file("config.json")?
    let parsed = parse_json(content)?
    Ok(parsed)
```

等价于：

```lz
def read_config() -> Result<Dict<str, str>, str> raises str =
    let content = match read_file("config.json"):
        case Ok(v):
            v
        case Err(e):
            raise e            // raises 声明兼容 → 上抛
    let parsed = match parse_json(content):
        case Ok(v):
            v
        case Err(e):
            raise e
    Ok(parsed)
```

> `?` 的传播目标按 §4.3 判定：优先 `raises`（兼容 → `raise`），其次 `Result`/`Option` 返回（→ `return Err`/`None`）。上述示例 `raises str` 兼容 `read_file` 的 `Err(str)`，故展开为 `raise e`。

## 六、错误语法边界

```lz
// ❌ raise 未声明 raises
def bad() -> int =
    raise "oops"             // 错误：缺少 raises 声明

// ❌ panic 缺少消息
panic()                      // 错误：panic 需要参数

// ❌ try 无 catch 或 finally
try:
    do_something()           // 错误：try 必须有 catch 或 finally

// ❌ ? 用于不可传播类型
let x: int = 42
let y = x?                   // 错误：int 未实现 __is_ok__，不是可传播类型（Result/Option/raises 类型除外）

// ❌ catch 分支缺少模式
try:
    action()
catch:                       // 错误：catch 需要模式
    handler()

// ❌ raise 类型与 raises 不匹配
def f() -> int raises str =
    raise 42                 // 错误：raises str 但 raise 了 int
```
