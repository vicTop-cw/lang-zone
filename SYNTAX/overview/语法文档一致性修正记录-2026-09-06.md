## 二、观察备注（未改动，需你裁决）

1. **版本号策略自相矛盾（架构/流程方向，已保留）**：《语法文档编写规范》§三.3 要求每次修改「版本号只递增（次版本 +0.1）」，而《语法冻结基线》将规范版本冻结为 3.3 且由 `check_doc_versions.py` 校验全部头部相等。二者在「是否随修改抬高版本号」上冲突。本轮**遵循冻结基线**（保持 `规范版本: 3.3`，仅将 `最后校订` 更新为当天日期 2026-09-06），未擅自改动任一文件的架构/流程方向内容。建议后续统一二者口径（例如明确冻结期内仅更新 `最后校订`，版本号待自举后整体抬升）。**（该矛盾已于本文 §四 通过增补 §三.5「冻结期版本例外」统一口径解决。）**

2. **`Iterable` / `IntoIterator` / `Iterator<T>` 三者语义不同，均属正确**：审计中确认 `Iterable` 是已定义的 duck 约束（`01-类型系统.md` 第 596 行 `duck Iterable =`，用于 `where T: Iterable`）、`IntoIterator` 是魔法 trait（`__iter__`/`__into_iter__` 映射）、`Iterator<T>` 是迭代器类型（`LZSTD/traits.lz` 第 7 行 `trait Iterator =`）。三者各自一致，本轮未做改动，仅统一了易混淆的 `Iter<T>` → `Iterator<T>`。

3. **非 SYNTAX 文档的同类残留（超出本轮范围）**：`DEMO/lz_std/plan.md`、`issue/*.md` 等仍出现 `Iter<T>`，属 DEMO / 问题跟踪文档，不在「语法文档」范围内，未改动；如需也可一并对齐。
