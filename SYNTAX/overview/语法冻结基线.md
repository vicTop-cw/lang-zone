## 〇、冻结宣言

自 2026-08-04 起，LZ 语言**语法层正式冻结**：

- **冻结对象**：`SYNTAX/` 全部规范文档（README、各专题文档、附录）。
- **冻结内容**：语法规则的增、删、改。现有规则以 3.3 版本为唯一权威基线。
- **冻结目的**：使转译器（LZ → Rust）拥有**不可漂移**的输入规范，从而可以全量编写并稳定可用。
- **解除冻结**：仅当转译器完全可用（自举条件达成，见 §四）后，才允许按流程评估新语法。

## 二、冻结期变更规则

冻结期间**允许**：

| 类别 | 说明 | 需要 |
|------|------|------|
| 笔误修正 | 错别字、格式、内部链接失效 | 无需审批 |
| 澄清性重述 | 不改变语义的措辞优化（不新增/删除规则） | 无需审批 |
| 与源码对齐 | 转译器实现中发现规范与产物不一致 → 以规范为准修正实现，或依规范明确产物 | 记录于冻结日志（§五） |
| 缺陷修复 | 上述细则审计（2026-08-04）发现的问题若转译器实现中再现 | 记录于冻结日志 |

冻结期间**禁止**：

| 类别 | 说明 |
|------|------|
| 新增语法 | 任何新关键字/运算符/语句/表达式形态 |
| 修改现有语义 | 任何规则的行为变化（如 `break` 语义、`!` 的绑定） |
| 新增软关键字 | duck 软关键字表（附录B §1.13）不再扩充 |
| 新增 magic / 内建函数签名 | 99 的 prelude 表、06d 的魔法表不再增行 |

> 一切「新想法」在冻结期内**不允许**触碰上述禁止项，统一走三通道（§三）。

## 三、冻结期「新想法」三通道

冻结期内的创造欲按下述通道分流（判定标准见 05b 讨论纪要 / 本表）：

### 通道 1：宏（排版冲动）
- **适用**：代码改写类——新操作符糖、DSL、模板代码生成、重复模式抽取。
- **方式**：用 `macro`/`template` 在**宏模块**内实现并验证；不修改语法层。
- **出口**：宏实验证明「值得进核心」的，记录于想法仓库（§六），自举后评估。

### 通道 2：库 / prelude（功能冲动）
- **适用**：操作集合——迭代器组合、新容器、错误处理模式。
- **方式**：加入 prelude / std（`99-内置预导入库.md` 之外的新模块函数）；**禁止**改动 99 已有行，新增走新库模块。
- **出口**：真实代码验证价值；不触碰语法层。

### 通道 3：想法仓库（语义冲动）
- **适用**：语义承诺类——控制流、类型系统、所有权、求值策略等需要编译器理解的新概念。
- **方式**：记录于 `overview/想法仓库.md`（§六），每条含：痛点、宏/库替代方案、语法影响面、是否服务自举。
- **冷静期**：30 天；到期仍强烈需要才进入评估，且仅在自举后。
- **红线**：语义承诺类**绝不**在冻结期进入语法层（历史教训：duck/block 的复杂度必须在编译器成熟后才可扩展）。

> 一句话：**宏治排版、库治功能、仓库治语义；三者都不进语法层。**

## 四、解锁条件（自举）

冻结解除的**唯一**条件（全部满足）：

1. **转译器完全可用**：LZ → Rust 全量转译，编译产物可运行、测试通过（与 [项目进度报告.md](项目进度报告.md) 的测试门槛对齐）。
2. **自举达成**：LZ 代码实现（或转译）自身的编译器/工具链核心，摆脱对规范变动的依赖。
3. **验收通过**：全部 DEMO 以冻结基线 3.3 编译运行，无「以规范为准修正」之外的偏差。

达成后，开启「自举后评估期」：

- 从 `overview/想法仓库.md` 按「服务自举 + 真实痛点 + 宏验证过」排序逐条评估。
- 每条新语法走完整流程：提案（痛点/替代/影响面/自举相关性）→ 冷静期 → 评审 → 修改规范（版本号 3.4+）→ 实现。
- 每条落定同步更新本文件（§五 冻结日志）。
