## 二、P0 — 核心且简单（建议优先实现）

### P0-1 字典推导 `{k: v for x in xs}`

- **规范出处**：`SYNTAX/04-表达式.md`
- **当前状态**：❌ 真实缺失。无 `DictComprehension` AST 节点（grep 零命中）。列表推导 `[x for x in 1..10]` 已可用，但字典/集合推导未接入。
- **缺失点**：解析器仅支持列表推导；字典推导的 `k: v` 双表达式未实现。
- **规范示例**：
  ```lz
  let squares = {x: x * x for x in 1..10}
  let by_id = {u.id: u for u in users if u.active}
  ```
- **工作量**：M（可复用列表推导框架）。

### P0-2 集合推导 `{x for x in xs}`

- **规范出处**：`SYNTAX/04-表达式.md`
- **当前状态**：❌ 真实缺失。无 `SetComprehension` 节点。
- **缺失点**：同 P0-1，集合推导分支未实现。
- **规范示例**：
  ```lz
  let uniq = {x for x in numbers}
  let vowels = {c for c in text if c in "aeiou"}
  ```
- **工作量**：M（与 P0-1 共用推导框架，可一并实现）。

### P0-3 管道操作符 `|>` 完整接入

- **规范出处**：`SYNTAX/04-表达式.md`（管道）
- **当前状态**：🟡 部分实现（WIP）。已有 `Expr::Pipe` AST 与 `codegen/expr.rs:1035` 代码生成，但解析器优先级/触发条件不稳定，现有 `05_expressions/pipe.lz` 用函数调用绕过。
- **缺失点**：需让 `a |> f |> g` 稳定解析并生成 `g(f(a))`。
- **规范示例**：
  ```lz
  let result = data |> filter(is_valid) |> map(to_record) |> collect()
  ```
- **工作量**：M（解析器优先级修复 + 端到端验证）。

## 三、P1 — 核心但中等

### P1-1 顶层构建块 `x =: body`（函数体外）

- **规范出处**：`SYNTAX/11-构建块.md`
- **当前状态**：❌ 真实缺失。函数体内的 `=:` 可用；但顶层（模块作用域）`x =: body` 被解析器拒绝。
- **缺失点**：放宽构建块作用域约束，使其可出现在模块顶层。
- **规范示例**：
  ```lz
  config =:
      host = "localhost"
      port = 8080
      (host, port)
  ```
- **工作量**：M（parser 作用域 + 模块级 codegen）。

### P1-2 生成器构建块 `*: ` 端到端跑通

- **规范出处**：`SYNTAX/11-构建块.md`、`SYNTAX/14-生成器.md`
- **当前状态**：🟡 部分实现。已有 `BuildGen` 词法符号、解析器处理与 `codegen/builders.rs` 代码生成，但端到端是否干净编译运行待验证。
- **缺失点**：补一个完整 E2E demo 并修复边界（多 `yield`、嵌套 `*:`）。
- **规范示例**：
  ```lz
  let make = *:
      yield 1
      yield 2
      yield 3
  ```
- **工作量**：M（E2E 验证 + 边界修复，非从零实现）。

### P1-3 装饰器真实代码生成：`@parallel` / `@simd` / `@tail_call`

- **规范出处**：`SYNTAX/03-函数.md`（复合综合）
- **当前状态**：✅ 已实现（2026-07-31）。
  - `@simd` → `#[inline(always)]`（已实现）
  - `@parallel` → `#[cfg(feature = "rayon")]` + `use rayon::prelude::*;` + 函数体内 `.iter()`→`.par_iter()` 替换
  - `@tail_call` → `#[inline(never)]`
- **规范示例**：
  ```lz
  @parallel
  def process(batch: List<int>) -> int = sum(batch)
  ```
- **工作量**：✅ 完成。

### P1-4 泛型约束求解 `T: Trait1 + Trait2`

- **规范出处**：`SYNTAX/01-类型系统.md` / `SYNTAX/03-函数.md`
- **当前状态**：🟡 部分实现。多约束语法可解析，但约束求解（`hints`/`typing`）对多 trait 边界满足性检查不完整。
- **规范示例**：
  ```lz
  def merge<T: Clone + Display>(a: T, b: T) -> str = a.to_string() + b.to_string()
  ```
- **工作量**：M（类型系统内部）。

## 四、P2 — 高级 / 基础设施

### P2-1 提取器模式 `__unapply__`

- **规范出处**：`SYNTAX/06a-struct.md` / `SYNTAX/05-控制流.md`（match 解构）
- **当前状态**：❌ 真实缺失。仅 `codegen/expr.rs:951-954` 有 TODO 桩。
- **缺失点**：`case Point(x, y):` 依赖 `__unapply__` 返回元组并绑定到子模式，未实现。
- **规范示例**：
  ```lz
  struct Point:
      x: int
      y: int
      magic __unapply__(self) -> (int, int) = (self.x, self.y)
  match p:
      case Point(px, py) => print(px, py)
  ```
- **工作量**：L（match 模式机扩展 + codegen 绑定）。

### 已知边界（已实现但有限制）

- **列表推导迭代器仅支持区间**：`[x * x for x in 1..10]` 可解析，但 `[x * 2 for x in some_list]`（迭代器为列表变量）当前解析失败（`Expected RBrack, got For`）。属 P0 级补全项，已记入 `DEMO/99_spec/comprehension_over_list.lz`。
- **多行构造调用**：struct/enum 构造调用需单行书写，缩进的多行参数当前不被解析。

## 附：构建修复注记

复核中发现库代码存在一处潜在编译错误：`src/parser/expr.rs` 中 `let left = self.parse_or()?` 在后续管道 `while` 循环中被重新赋值，应为 `let mut left`。此错误此前被陈旧 cargo 缓存掩盖（`cargo test --lib` 报 433 通过实为缓存命中）。已修复为 `let mut left`，现库可干净编译、433 测试全绿。建议在 CI 中增加 `cargo build` 作为硬性门槛，避免缓存掩盖编译错误。
