## 四、P2 — 高级 / 基础设施

### P2-1 提取器模式 `__unapply__`

- **规范出处**：`SYNTAX/06a-struct.md` / `SYNTAX/05-控制流.md`（match 解构）
- **当前状态**：✅ 已实现（2026-07-31）。`magic __unapply__(self) -> (...)` 语法解析通过，`DEMO/99_spec/extractor_unapply.lz` 测试覆盖。
- **规范示例**：
  ```lz
  struct Point =
      x: int
      y: int
      magic __unapply__(self) -> (int, int) = (self.x, self.y)
  match p:
      case Point(px, py) => print(px, py)
  ```
- **工作量**：✅ 完成。

### P2-2 `go` / `setup` / `teardown` 运行时语义

- **规范出处**：`SYNTAX/10-并发与异步.md`（go）、`SYNTAX/15-测试框架.md`（setup/teardown）
- **当前状态**：
  - `go`：✅ 已实现（2026-07-31）。词法 → 解析 → codegen 全链路打通。`go expr` → `std::thread::spawn(move || { expr })`。
  - `setup`/`teardown`：✅ 已实现（2026-07-31）。词法 → 解析 → codegen 全链路打通。setup 和 teardown 语句内联到每个 suite 测试函数中。
- **规范示例**：
  ```lz
  go process(item)
  suite tests:
      setup: db = connect()
      teardown: db.close()
  ```
- **工作量**：✅ 完成。

### P2-3 跨模块类型推断（lz-infer 集成）

- **规范出处**：`SYNTAX/07-模块与导入.md`
- **当前状态**：🟡 **可选增强，非主编译管线依赖**（2026-08-15 降级）。
  - v159 已接通：`--lzi <file>` 加载 lz-infer 生成的 `.lzi` 签名，IR builder 在本地函数查不到返回类型时回退查询外部模块签名（`build_ir_with_lzi`）。
  - **局限（实证）**：`.lzi` 只提供类型签名、不提供实现——生成的 `.rs` 引用外部函数时 rustc 仍报 E0425，无法独立达成「编译运行」闭环。
  - **同项目跨模块类型走 `--project` 源码合并路径**（ProjectCompiler 递归 import），无需外部 `.lzi`。
  - 由 `infer` 特性门控（默认开启）；关闭后编译体积更小、无 serde 依赖。
- **工作量**：✅ 已接通（可选增强）。
