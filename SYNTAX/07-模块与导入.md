# LZ 模块与导入

> 规范版本: 3.3 · 基于编译器源码 · 最后校订: 2026-08-04

本文档定义 Lang-Zone 的模块系统：`import`、`from`、`as`、路径语法、桥接系统。

---

## 一、路径语法

Lang-Zone 使用 `.` 作为路径分隔符：

```lz
std.io.print                     // 模块路径
std.collections.List             // 类型路径
my_module.my_function            // 函数路径
Option.Some                      // 枚举变体
```

> `::` 不是有效路径语法，路径分隔符是 `.`。

## 二、import 导入

### 2.1 导入模块

```lz
import std.io                    // 导入整个模块
import std.collections.HashMap   // 导入特定子模块
```

导入后可使用模块路径访问：

```lz
import std.io
std.io.print("hello")
```

### 2.2 导入别名

```lz
import std.collections.HashMap as Map

let m: Map<str, int> = Map.new()
```

### 2.3 from 导入

```lz
from std.io import print, read   // 导入特定项
from std.collections import List, Dict
```

导入后可直接使用名称：

```lz
from std.io import print
print("hello")                   // 无需 std.io. 前缀
```

### 2.4 导入所有公开项

```lz
from std.io import *             // 导入模块所有公开项
```

### 2.5 相对导入

`.` 和 `..` 前缀表示相对于当前模块的路径：

```lz
// 当前包内导入
from .utils import helper      // 导入同目录下的 utils 模块
from .types import Point       // 导入同目录下的 types 模块

// 父包导入
from ..common import config    // 导入上级目录的 common 模块
```

语法规则：
- `. ` 单点 = 当前包目录
- `.. ` 双点 = 上级包目录
- 相对导入只能在包内部使用（非顶层模块）

### 2.5.1 模块可见性（默认全部公开）

模块**没有私有关键字**：顶层定义的所有项（`def`/`struct`/`enum`/`trait`/`magic`/`const`/`type` 别名/checker 块/宏模块内宏）**默认全部公开**，均可被 `import`/`from ... import` 引入。约定（非强制）：以下划线 `_` 开头的标识符视为「模块内部约定」，外部不应引用，但编译器不报错。

- 嵌套在 `block` 体内的子项受词法作用域限制（仅父块可见，见 05b §5.5），不属于模块顶层公开项。
- 循环导入（a ↔ b）→ 编译错误（§错误边界）。

### 2.5.2 模块初始化顺序

模块顶层语句（`let`/`const` 初始化、`block NAME:` plain 块、顶层表达式）在**首次 import 时按书写顺序执行一次**，且只执行一次（模块缓存）：

- 依赖顺序：`import a` 先完整执行 a 的顶层，再回到当前模块继续。因此 a 的顶层可以依赖 b，但 a↔b 互相 import 顶层循环 → 编译错误（无法确定初始化顺序）。
- `import` 一个模块**不触发**该模块 checker 块的体（checker 块惰性，见 05b §2.4）；只执行顶层语句。

### 2.6 导入宏模块（import macro）

`macro`/`template` 只能定义在宏模块（`#!bin macro`，见 [08-宏与编译期.md](08-宏与编译期.md) §2.1），普通模块要用宏必须通过 `import macro` 显式导入（宏命名空间与普通项分离）：

```lz
import macro my_macros                    // 导入整个宏模块
import macro my_macros as mm              // 导入并别名
from macro my_macros import id, checked_add   // 导入特定宏/模板
from macro my_macros import *             // 导入宏模块所有宏
```

- `import macro` 只引入该模块的 `macro`/`template`；普通 `def`/`struct` 用普通 `import`/`from`（§2.1-2.4）。
- 导入后调用语法不变：`macro` 用 `@name!`、`template` 用 `name!`（08 §3.4/§4.2）。
- 宏**必须显式导入**：未 `import macro` 直接调用宏 → 编译错误。

## 三、模块文件结构

### 3.1 单文件模块

一个 `.lz` 文件即一个模块：

```lz
// math.lz
def add(a: int, b: int) -> int = a + b
def sub(a: int, b: int) -> int = a - b
```

### 3.2 目录模块

```
my_package/
    __init__.lz        // 模块入口
    utils.lz           // 子模块
    types.lz           // 子模块
```

`__init__.lz` 定义模块根级别的导出：

```lz
// __init__.lz
from .utils import helper
from .types import Point
```

## 四、桥接系统（Rust 互操作）

### 4.1 RustBridge

直接导入 Rust crate：

```lz
import std.bridge.rust.serde_json
```

生成 Rust `use serde_json;`，并在 Cargo.toml 追加依赖。

CLI 编译时需要指定：

```bash
lzc file.lz --std-dir std/ --rust-crate serde_json=1.0
```

### 4.2 桥接配置（TOML）

`std/` 目录下的 `.toml` 文件定义桥接映射：

```toml
# std/bridge/rust/serde_json.toml
rust_prefix = "serde_json"
version = "1.0"
```

### 4.3 @export 导出

```lz
@export(Rust)
def add(a: int, b: int) -> int = a + b

@export(Python)
def greet(name: str) -> str = f"Hello, {name}"
```

> **checker 块与导出**：模块顶层的 checker 块（`block NAME[ps: __Params]` / `block NAME[chk]`）与 `def` 一样**默认对 `import`/`from` 可见**（LZ 模块间调用无需 `@export`）；`@export(Rust)` / `@export(Python)` 仅用于将其暴露给**外部 Rust/Python** 直接调用（因 checker 块在 codegen 层与函数等价，见 [05b-block命名块.md](05b-block命名块.md) §7.8）。plain 块（定义即执行的命名作用域）不可跨模块导出。跨模块调用的四种触发途径（`^:` / `[(expr)]` / `[chk]` / `break with`）见 05b §7.7。

## 五、错误语法边界

```lz
// ❌ 使用 :: 路径
import std::io                  // 错误：应用 .
Option::Some(42)                // 错误：应用 Option.Some(42)

// ❌ 导入不存在的模块
import does.not.exist           // 编译错误

// ❌ 循环导入
// a.lz: import b
// b.lz: import a
// 错误：循环导入

// ❌ from 导入语法错误
from import print               // 错误：缺少模块路径
from std.io import              // 错误：缺少导入项

// ❌ 导入别名语法错误
import std.io as                // 错误：缺少别名
```
