# LZ 宏系统

> 规范版本: 3.3 · 基于编译器源码 · 最后校订: 2026-08-04

本文档定义 Lang-Zone 的宏系统：`macro`、`template`、属性宏 `#`。

> 编译期求值（comptime）已独立为专题文档，详见 **[08b-comptime编译期](08b-comptime编译期.md)**。

---

## 一、属性宏 `#`

### 1.1 语法

`#` 是 Rust 属性宏的标记，**不是注释**。所有 `#!` 开头的指令都翻译为对应的 Rust 属性。

```lz
#!export(Rust)               // → #[export(Rust)] — Rust 导出属性
#!bin macro                  // → 声明本文件为宏模块（必须是首行）
#![derive(Clone)]            // → Rust #[derive(Clone)]
```

### 1.2 与装饰器的关系

```lz
@export(Rust)                // 装饰器形式（等价于下面的属性宏）
def f() = ...

#!export(Rust)               // 属性宏形式
def f() = ...
```

## 二、#!bin macro（宏模块）

### 2.1 声明

```lz
#!bin macro                   // 必须是源文件第一行
```

声明当前 `.lz` 文件为宏模块。宏模块可以定义 `macro`、`template`。

**`macro` 和 `template` 只能定义在宏模块**：非宏模块（普通 `.lz` 文件）中写 `macro ...` / `template ...` → **编译错误**。普通模块要使用宏，须通过「导入宏模块」引入（见 §四.3）。宏模块中也可定义普通 `def`/`struct` 等（供宏体或调用方使用），但 `macro`/`template` 声明本身仅限宏模块。

## 三、macro 宏定义

宏是编译期 Token 级代码转换，定义在 `#!bin macro` 模块中。

### 3.1 基本语法

```lz
#!bin macro                       // 首行声明宏模块

macro name(param: Tokens) -> Tokens =
    // 宏体：任意返回 Tokens 的表达式
```

**宏签名永远固定为 `Tokens -> Tokens`**：`macro` 的**全部参数类型**和**返回类型**都必须是 `Tokens`，不能是 `int`/`str` 等具体类型——这是强制规则（`macro` 是纯 Token 级转换，无自由类型参数）。

```lz
// ✅ 直接返回参数 — 最简单的恒等宏
macro id(input: Tokens) -> Tokens = input

// ✅ 使用 quote() 函数拼接
macro greet(name: Tokens) -> Tokens =
    quote("fn hello() { println!(\"Hello, \" + " + name + " + \"!\"); }")

// ✅ 使用内置函数组合
macro merge(a: Tokens, b: Tokens) -> Tokens =
    merge_tokens(a, b)
```

输入/输出类型均为 `Tokens`。若需要 `int`/`str` 等**自由类型参数**（如编译期数值校验），应改用 `template`（见 §四——template 参数签名自由，但返回仍必须 `Tokens`）。

### 3.2 反引号块（`quote()` 的语法糖）

`f\`\`\`` 和 `r\`\`\`` 是 `quote(...)` 的语法糖 — **非必需**，仅在需要输出大段原样文本时更方便。

| 前缀 | 模式 | `$(x)` 行为 | 等价函数 |
|------|------|:---:|------|
| `f\`\`\`` | 插值 | `$(expr)` 求值并替换 | `quote(f"...{expr}...")` |
| `r\`\`\`` | 原始 | 所有字符保留原样 | `quote(r"...")` |

```lz
// f``` — 插值模式
macro debug_log(msg: Tokens) -> Tokens =
    f```
    if DEBUG:
        print($(msg))
    ```

// r``` — 原始模式
macro raw(input: Tokens) -> Tokens =
    r```
    // $(x) 不会插值，原样保留
    ```

// 等价写法（不用语法糖，纯 quote ）
macro debug_log2(msg: Tokens) -> Tokens =
    quote("if DEBUG:\n    print(" + msg + ")\n")
```

### 3.3 示例

```lz
#!bin macro

// 恒等宏
macro id(input: Tokens) -> Tokens = input

// 用 quote() 拼接
macro const_i64(name: Tokens, value: Tokens) -> Tokens =
    quote("const " + name + ": i64 = " + value + ";")

// f``` 语法糖
macro vec(items..: Tokens) -> Tokens =
    f```
    vec![$(items)]
    ```

// 多步处理：先用内置函数过滤，再拼接
macro exported_fns(input: Tokens) -> Tokens =
    let fns = filter_tokens(input, "FnDef")
    merge_tokens(quote("// public functions:\n"), fns)

// 编译期校验（需 int 参数 → 必须用 template，macro 固定 Tokens 参数，见 §3.1）
template checked_add!<T>(a: int, b: int) -> Tokens =
    guard a + b < 1000
        else:
            error("overflow")
    quote("let result: i64 = " + a + "+" + b + ";")
```

### 3.4 宏调用

`macro` 定义的宏使用 `@name!` 形式调用（带 `@` 前缀 + `!` 后缀）：

```lz
@id!
def f() = 42                      // 展开：def f() = 42

@greet!("world")                  // 展开指定参数
@vec!(1, 2, 3)                    // 向量构建宏
```

> `macro` 定义的用 `@name!`；`template` 定义的用 `name!`（无 `@`）。`#` 开头的是 Rust 属性宏。

### 3.5 宏调用规则

**规则 1：`@name!` 必须独占一行**

`macro` 定义的宏调用必须是**独立的语句行**，不能嵌入在表达式中间：

```lz
// ✅ — 独立行
@id!
def f() = 42

// ✅ — 独立行带参数
@debug_log!("running...")

// ❌ — 不能内联在表达式中
// let x = @twice!(y) + 1    // 错误
// def f() = @id! def g()    // 错误
```

`template` 定义的宏模板（`name!`）则不受此限制，可以内联在表达式中。

**规则 2：反引号块内容不进行 LZ 语法检查**

`f\`\`\`` / `r\`\`\`` 包裹的内容只做**词法扫描**（括号匹配、缩进、关键字识别），不做完整的语法解析和类型检查。这意味着反引号块内可以写入**非 LZ 代码**（Rust、Python 等），只要词法层面正确即可。

```lz
// ✅ f``` 内嵌入 Rust 代码 — LZ 不检查其语法
macro rust_impl(input: Tokens) -> Tokens =
    f```
    impl MyType {
        fn process(&self) { ... }    // ← 不校验是否为合法 LZ
    }
    ```
```

**规则 3：仅对展开后的最终结果进行语法校验**

宏展开发生在 Lexer → Parser 之间。展开后的 Token 流才进入完整的 `Parser → AST → TypeCheck → CodeGen` 流程：

```
源文件 → Lexer → MacroExpander(展开 @name!) → Parser → CodeGen
                     ↑ 仅有词法扫描           ↑ 完整 LZ 语法分析
```

三层检测模型：

| 层级 | 作用域 | 检测内容 |
|:---:|------|------|
| Layer 1 | 所有代码（含反引号块） | 词法正确性（括号匹配、缩进、关键字） |
| Layer 2 | 宏输入参数 | Token 分组分类（Expr / Decl / Stmt / Pattern / Type） |
| Layer 3 | 展开后的代码 | 完整 LZ 语法与语义（类型检查、所有权、借用） |

**规则 4：宏可嵌套，每层嵌套多一次硬检查**

宏可以嵌套调用（宏展开结果中包含另一个宏调用）。嵌套 N 层意味着展开后需要通过 **N 次 Layer 3 硬检查**，而不是仅通过最外层的一次硬检。每一层展开后都必须各自生成合法的 LZ 代码。

```lz
// 外层宏
@outer!
@inner!                         // 内层宏 — 先展开 inner，再展开 outer
def f() = 42
```

**规则 5：宏可套用在任意 LZ 缩进块上**

`@name!` 可以作用于**任何一个完整的 LZ 缩进块语句**（`def`、`struct`、`if`/`elif`/`else`、`for`/`while`/`loop`、`match`/`case`、`try`/`catch`/`finally` 等）。这意味着理论上可以在 LZ 中嵌入 Python、Nim、Scala 3 等缩进类语言的代码块——只要你的宏能将其展开为合法的 LZ 即可。

**规则 6：非缩进块语句需用反引号块**

若宏需要操作的对象不是缩进块（如表达式、内联语句），须使用 `` f` `` / `` r` `` 反引号块包裹，且宏调用必须独占一行：

```lz
// ✅ 合法用法 1 — 套在缩进块上
@macro_name!
def func(x: int) -> int =
    // 任何一个完整的缩进块
    x + 1

// ✅ 合法用法 2 — 反引号块
@macro_name!
f```
$(some_tokens_var)
any content here
```

```lz
// ❌ 非法 — 不能内联在表达式中
let x = @twice!(y) + 1          // 错误
def f() = @id! def g()          // 错误
```

### 3.6 宏展开流程总结

```
源文件 → Lexer → 软检查(Layer 1+2) → MacroExpander(展开 @name!) 
       → 硬检查(Layer 3) → 若有嵌套宏 → 再次硬检查... → Parser → CodeGen
```

- **软检查** = 展开前的词法 + Token 分类校验
- **硬检查** = 展开后的完整 LZ 语法语义校验
- **多层嵌套** = 每层展开后各自独立硬检，任意一层不通过即编译失败

### 3.7 宏卫生性（hygiene）

**规则 7：宏展开的标识符与调用方命名空间隔离（卫生性）**：

- 宏内 `quote`/`f``` 产物中**新绑定的标识符**（`let x`、形参、`def f` 等左侧）会重命名加唯一后缀（如 `x__m1`），避免与调用方同名变量冲突。
- 宏展开中**引用的外层变量/函数名**（读引用，非新绑定）保持原样（call-site hygiene：由调用方上下文解析），因此宏可以引用调用方的变量。
- 调用方传入的 `Tokens`（如 `name` 参数）是**调用方卫生**：它们原样展开为调用方命名空间的标识符，宏不能改变其绑定。
- 反引号块（`r``` / `f```）内的**裸 Rust 代码**不做 hygiene 处理（原样输出），由 Rust 侧自行管理作用域。

> 结论：宏默认**双方卫生**——「宏内新绑定」与「调用方标识符」互不污染；「引用」按调用方解析。这样宏可以安全地生成局部变量而不会遮蔽调用方。

### 3.8 内置函数

宏体内可使用以下编译期内置函数操作 `Tokens`：

| 函数 | 签名 | 说明 |
|------|------|------|
| `quote` | `quote(s) -> Tokens` | 将字符串转为 Tokens |
| `merge_tokens` | `merge_tokens(a, b, ...) -> Tokens` | 拼接多个 Tokens |
| `token_count` | `token_count(stream) -> int` | 返回顶层 token 数量 |
| `is_empty_tokens` | `is_empty_tokens(stream) -> bool` | 检查是否为空 |
| `filter_tokens` | `filter_tokens(src, kind) -> Tokens` | 按类型过滤 token |
| `remove_tokens` | `remove_tokens(src, pattern) -> Tokens` | 移除匹配的 token |
| `replace_tokens` | `replace_tokens(src, rules) -> Tokens` | 查找替换 token |
| `token_stream` | `token_stream(src) -> Tokens` | 解析为树形结构 |
| `take` | `take(tokens, n) -> Tokens` | 取前 n 个 token |
| `drop_tokens` | `drop_tokens(tokens, n) -> Tokens` | 去掉前 n 个 token |
| `split_at` | `split_at(tokens, sep) -> Tokens` | 按分隔符拆分 |
| `join` | `join(tokens, sep) -> Tokens` | 用分隔符连接 |
| `error` | `error(msg) -> !` | 编译期报错 |
| `assert_eq` | `assert_eq(a, b)` | 断言两个 token 流相等（宏编译期断言，不同于测试框架的 `assert` 关键字） |

## 四、template 模板

模板是带泛型参数的编译期函数，返回 `Tokens`。调用时必须用 `!` 后缀标记。

**template 与 macro 的签名差异**：
- **`macro`**：签名**固定** `Tokens -> Tokens`（全参数 + 返回都是 `Tokens`，§3.1）。
- **`template`**：参数签名**自由**（可以是 `Tokens`，也可以是 `int`/`str` 等具体类型，或泛型 `<T>`），但**返回类型必须固定为 `Tokens`**——这是强制规则（template 的产物一定是 Token 流，供展开为 LZ 代码）。

### 4.1 语法

```lz
template name!<T>(params...) -> Tokens =   // 参数自由；返回必须 Tokens
    // 宏体：任意返回 Tokens 的表达式（与 macro 相同）
```

模板名以 `!` 结尾。宏体规则与 macro 完全相同 — 可以是任意表达式或 `f\`\`\`` / `r\`\`\`` 语法糖。

```lz
// 参数为 Tokens（与 macro 相似）
template make!<T>(name: Tokens, fields..: Tokens) -> Tokens =
    quote("struct " + name + " {\n" + fields + "\n}")

// 参数含具体类型（自由签名）— 编译期数值校验、拼接字符串
template build!<T>(count: int, prefix: str) -> Tokens =
    quote("const N: i64 = " + count + "; // " + prefix)

// 用 f``` 语法糖（等价的更方便写法）
template make_sugar!<T>(name: Tokens, fields..: Tokens) -> Tokens =
    f```
    struct $(name) =
        $(fields)
    ```
```

### 4.2 模板调用

`template` 定义的模板使用 `name!` 调用（无 `@` 前缀，仅 `!` 后缀）：

```lz
make!(MyStruct,
    x: int
    y: int
)

// 展开为：
// struct MyStruct =
//     x: int
//     y: int
```

### 4.3 跨模块使用宏：import macro

`macro`/`template` **只能在宏模块（`#!bin macro`）中定义**（§2.1），其他（普通）模块要通过「导入宏」使用。导入语法沿用 [07-模块与导入.md](07-模块与导入.md) 的 `import`/`from` 家族，但**专门用 `macro` 关键字标记**，使普通代码与宏的命名空间分开：

```lz
// ① 导入整个宏模块（宏名以路径前缀访问或直接可用，见下）
import macro my_macros

// ② 导入宏模块中的特定宏/模板
from macro my_macros import id, checked_add

// ③ 导入并起别名
import macro my_macros as mm
```

```lz
// macros.lz —— 宏模块（首行 #!bin macro）
#!bin macro

macro id(input: Tokens) -> Tokens = input
template checked_add!<T>(a: int, b: int) -> Tokens =
    guard a + b < 1000
        else:
            error("overflow")
    quote("let result: i64 = " + a + "+" + b + ";")
```

```lz
// app.lz —— 普通模块，导入宏模块后使用
import macro my_macros            // 或 from macro my_macros import id, checked_add

@id!                              // 宏调用（@name! 形式）
def f() = 42

checked_add!(3, 4)                // 模板调用（name! 形式），展开编译期校验
```

跨模块要点：

- **宏必须显式导入**：宏模块的宏/模板**不会**自动对普通模块可见；不 `import macro` 直接 `@name!` → 编译错误（与普通模块项默认可见不同，宏是编译期实体，须显式引入）。
- **调用语法不变**：导入后 `macro` 仍用 `@name!` 调用、`template` 仍用 `name!` 调用（§3.4/§4.2）。
- **宏模块间也可互相导入**：一个宏模块可 `import macro` 另一个宏模块的宏（嵌套/复用宏）。
- **只导宏，不导普通项**：`import macro` 只引入该模块的 `macro`/`template`；普通 `def`/`struct` 用普通 `import`/`from`（07 §二）。

## 五、属性宏完整列表

| 属性宏 | 用途 |
|--------|------|
| `#!bin macro` | 声明宏模块（宏模块才能定义 macro/template，§2.1） |
| `#!export(Rust)` | 导出为 Rust 动态库 |
| `#!export(Python)` | 导出为 PyO3 模块 |
| `#!no_std` | 禁用标准库 |

> **导入宏模块**：普通模块用 `import macro` / `from macro import` 引入宏模块中的 `macro`/`template` 后使用（见 §4.3）。

## 六、错误语法边界

```lz
// ❌ # 用作注释
# 这是注释吗？               // 错误：# 是属性宏标记

// ❌ #!bin macro 不在首行
import std.io
#!bin macro                  // 错误：必须是文件第一行

// ❌ 反引号块缺少 f/r 前缀
macro bad(input: Tokens) -> Tokens =
    ```
    input                    // 错误：需要 f``` 或 r``` 前缀
    ```

// ❌ 宏体返回非 Tokens 类型
macro bad(input: Tokens) -> int = 42
    // 错误：macro 返回必须固定为 Tokens

// ❌ 在非宏模块中定义 macro/template
import std.io
macro bad2(input: Tokens) -> Tokens = input
    // 错误：macro/template 只能定义在 #!bin macro 宏模块（§2.1）

// ❌ 未 import macro 就调用宏
@id!
def f() = 42
    // 错误：id 未从任何宏模块导入（需 import macro / from macro ... import，§4.3）

// ❌ macro 签名含非 Tokens 参数
macro bad3(a: int) -> Tokens = quote(a)
    // 错误：macro 签名固定 Tokens -> Tokens；需用 template 实现自由参数（§4）
```
